# Глава 4. Система типов

Qualisp — statically typed Lisp. Типы проверяются **до** исполнения, на этапе
`read → macroexpand → typecheck → emit → run`; `:any` в языке нет. Тип — это
компиляторные метаданные (`src/types.zig`), а не рантайм-значение: `type-of`
возвращает имя типа, но заменить им аннотацию нельзя.

## 4.1 Статическая типизация

Базовые типы:

| Тип | Что описывает | Пример значения |
|---|---|---|
| `:fixnum` | целое int64, арифметика с wrap | `42`, `-7` |
| `:flonum` | вещественное f64; доминирует в смешанной арифметике | `3.14`, `1e3` |
| `:bool` | `t` и `nil` | `t` |
| `:string` | неизменяемая rope из Unicode-скаляров | `"hi"` |
| `:symbol` | интернированный регистронезависимый символ | `'abc`, `:keyword` |
| `:nil` | только `nil` — false, «None» и пустой список | `nil` |
| `:char` | Unicode-скаляр u21 | `#\a`, `#\space` |
| `:never` | тип `throw`, подтип любого типа | — |
| `:syntax` | S-выражение как данные (§4.7) | `'(+ 1 2)` |
| `:tensor` | dtype + конкретная форма (§4.4) | `(tensor ((1.0 2.0)))` |
| `:func` | функция: код + окружение | `id` |
| `:struct` | номинальный тип структуры (§4.5, гл. 13) | `(pt 1 2)` |

Аннотации обязательны на верхнем уровне — и для `defvar`, и для параметров и
возврата `defun`:

```lisp
(defvar x :fixnum 1)
x               ; → 1
(setq x 2)      ; тип зафиксирован: можно только :fixnum
x               ; → 2

(defun sq (x :fixnum) :fixnum (* x x))
(sq 7)          ; → 49

(defun add (a :fixnum b :fixnum) :fixnum (+ a b))
(add 2 3)       ; → 5
```

`&optional` внутри тела имеет тип `(:option T)`, `&rest` — `(:list T)`:

```lisp
(defun g (x :fixnum &optional y :fixnum) :fixnum (if (null y) x x))
(defun rst (a :fixnum &rest xs :fixnum) :fixnum a)
```

Значения по умолчанию для `&optional` не задаются, форма `(p :type default)` не
поддерживается. Пустой список — это `nil`, поэтому `(:list T)` непуст, а проверять
список надо через `(null x)`, не через `(if x …)`.

Сахар `\` и `lambda` тоже аннотируются:

```lisp
(funcall (lambda (x :fixnum) :fixnum (+ x 1)) 9)   ; → 10
```

> 🐍 **Python-аналогия.** Это type hints, только обязательные на границе модуля:
> ```python
> x: int = 1
> def sq(x: int) -> int: return x * x
> def add(a: int, b: int) -> int: return a + b
> ```
> В отличие от Python, аннотация не «подсказка для линтера»: объявление с другим
> типом не скомпилируется.

## 4.2 Форма `the`

`(the T expr)` — проверяемый каст: «это выражение имеет тип T». Для
функции-значения тип записывается как `(:func (PARAMS...) R)`:

```lisp
(the :fixnum 42)                              ; → 42
(the (:func (:fixnum) :fixnum) id)            ; → #<function>
(funcall (the (:func (:fixnum) :fixnum) id) 5) ; → 5
```

> 🐍 **Python-аналогия.** `typing.cast(T, expr)` — но без «доверься мне»:
> несовпадение — ошибка, а не тихая замена. Примитив вроде `+` не является
> значением и в касте не участвует; каст работает с именованной функцией.

## 4.3 Что дают аннотации

1. **Ранние ошибки.** Несовпадение типов ловится до исполнения, вместе со спаном
   (`file:line:col`). Пример: `(defun f (x :fixnum &optional y :fixnum) :fixnum y)`
   отвергается — тело возвращает `(:option :fixnum)`, а не `:fixnum`.
2. **Оптимизации.** JIT генерирует код под доказанный тип: инлайн
   fixnum-арифметики со guard'ом тега и bail-блоком, быстрый путь для `f32`/`f64`,
   прямое чтение глобала по `SymbolId`.
3. **Документация.** Сигнатура — часть текста программы; в модулях она задаёт
   экспортируемый контракт.

**Перегрузок пользователя нет.** Одно имя — одно определение. Повторный `defun` с
тем же именем — ошибка компиляции:

```text
error at 1:1: function SQ is already defined (overloading is not supported)
```

Примитивы (`+`, `car`, `cons`, `print`, …) имеют встроенные сигнатуры — это не
механизм перегрузки для пользователя. Вызов разрешается статически; методы
структур диспетчируются по типу первого аргумента. Перегрузка по возвращаемому
типу запрещена.

## 4.4 Типы тензоров

Тип тензора — `(:tensor DTYPE (DIMS...))`, где
`DTYPE ∈ {:f16, :f32, :f64, :u8}`, а измерение — натуральное число или `_`
(неизвестное). Литерал выводит форму, dtype по умолчанию `:f32`:

```lisp
(defvar w (:tensor :f32 (2 2)) (param (tensor ((1.0 2.0) (3.0 4.0)))))
(type-of w)   ; → TENSOR
```

Линейных типов и «расходования» тензора нет: `owner` (`scratch`, `world`,
`pool`) — свойство реализации (гл. 5), а не статический тип. Операции читают
входы и возвращают новый тензор; `reshape`/`transpose`/`t-rows`/`t-column`/
`t-select-rows` копируют. Writable views в языке нет (гл. 6).

> 🐍 **Python-аналогия.** Ближе всего `numpy.ndarray` с известной формой: тип
> включает dtype и размерность, но не «кто владеет буфером».

## 4.5 Типы структур и трейтов (кратко)

Структура — номинальный тип `(:struct Name)`; конструктор — функция, доступ к
слотам статический. Trait — набор сигнатур, `impl` их реализует; диспетч
статический по первому аргументу, без vtable. Подробности — гл. 13.

```lisp
(defstruct pt ((x :fixnum) (y :fixnum)))
(defvar p (:struct pt) (pt 1 2))
(slot-value p 'x)        ; → 1
(set-slot p 'x 10)
(type-of p)              ; → STRUCT

(deftrait showable (show (self :self) :string))
(defstruct box ((v :fixnum)) (showable))
(impl box (defun show (self) :string "box"))
(show (box 3))           ; → "box"
```

`defvar` для структуры требует аннотации: `(defvar p (:struct pt) (pt 1 2))`.

## 4.6 Интроспекция типов

Примитив `type-of` возвращает имя типа **в верхнем регистре** — по конвенции
интернированных символов:

```lisp
(type-of 3)                  ; → INT
(type-of 3.5)                ; → FLOAT
(type-of "s")                ; → STRING
(type-of '(1 2))             ; → LIST
(type-of (tensor ((1.0))))   ; → TENSOR
(type-of (pt 1 2))           ; → STRUCT
```

> 🐍 `type-of` ≈ `type(x).__name__`, только с uppercase-именами.

## 4.7 Вывод типов и `:syntax`

Верхний уровень — только аннотации. Внутри функции — двунаправленная проверка:
литералы, арифметика, `let`, `lambda`, `if`, вызовы известных функций.
Полиморфизм — явный через переменные типов `:a`, `:b` (например,
`(defun identity (x :a) :a x)` в `core`); HM-вывод сигнатур без аннотаций не
выполняется. Невыводимый локальный тип — отказ компиляции, не `:any`.

`:syntax` — это конкретное дерево S-выражения, а не «любое значение»:

- `quote` даёт `:syntax`, `read-from-string : :string → :syntax`;
- `write-to-string : :a → :string`;
- `cons`/`car`/`cdr` перегружены для `:syntax` и `(:list T)`;
- `cdr` от `:syntax` снова `:syntax` (`nil` — корректный datum), поэтому
  обходчики пишут `(walk (cdr t))` без приведения;
- `defmacro` — функция `:syntax → :syntax`, раскрытие идёт до typecheck;
- `eval : :syntax → :a` выводит `:a` из контекста и заново прогоняет
  `expand → typecheck → emit`; несовпадение — runtime-ошибка. Это единственная
  граница статики.

`(eval (read-from-string "(+ 1 2)"))` без ожидаемого типа не скомпилируется —
тип вывода должен быть задан контекстом.

## 4.8 `type-of` возвращает uppercase-имена

`type-of` нормализует имена через интернирование символов:

| Значение | `type-of` | `type(x).__name__` (Python) |
|---|---|---|
| `42` | `INT` | `int` |
| `3.14` | `FLOAT` | `float` |
| `"hi"` | `STRING` | `str` |
| `'sym` | `SYMBOL` | (нет аналога) |
| `#\a` | `CHAR` | (нет аналога) |
| `(1 2 3)` | `LIST` | `list` |
| `(tensor ((1.0)))` | `TENSOR` | `numpy.ndarray` / `torch.Tensor` |
| функция (`defun`, `lambda`, метод) | `FUNCTION` | `function` |
| `(pt 1 2)` — структура (гл. 13) | `STRUCT` | имя класса (`Point`) |
| результат `catch-error` | `RESULT` | (нет аналога) |
| `nil` | `NIL` | `NoneType` |
| `t` | `BOOL` | `bool` |

Cons-ячейки сообщаются как `LIST`; единый callable-atom отдаёт `FUNCTION` и для
замыкания, и для примитива, и для JIT-обёртки.

## 4.9 Известные ограничения

- HM-вывод отсутствует: без аннотации на верхнем уровне форма не пройдёт
  проверку; «вывода по наблюдениям JIT» нет.
- Пользовательских перегрузок нет; `abs`/`min`/`max` как перегрузки не
  существуют.
- `&optional` без значений по умолчанию; `(p :type default)` не поддержан.
- `lambda`-литерал не вызывается напрямую — используйте `funcall`.
- `let*` отсутствует: `let` делает параллельные биндинги.
- Векторных и прочих `#`-литералов (`#(...)`, `#'`, `#| |#`) нет; `#\` задаёт
  только Char (`#\a`, `#\space`, `#\newline`, `#\tab`).
- `:any` нет; `eval` — единственная точка, где статический тип проверяется в
  рантайме.
