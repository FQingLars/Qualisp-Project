# Глава 3. Основы языка

## 3.1 S-выражения: главный синтаксис

В Qualisp одна форма записи для всего — S-выражения (символьные выражения):

```lisp
(+ 1 2)            ; вызов: оператор первый, 1 + 2
(* (+ 1 2) 3)      ; вложенность вместо приоритетов: (1+2)*3
(print "hi")       ; вызов функции
```

> 🐍 **Python-аналогия.** `(+ 1 2)` — это `1 + 2`, а `(* (+ 1 2) 3)` — `(1 + 2) * 3`. Скобки заменяют и приоритеты операторов, и круглые скобки вызовов: `f(x, y)` → `(f x y)`.

Комментарии: `;` до конца строки.

## 3.2 Типы данных

Внутреннее представление — тегированный union `SExpr`, теги: `NIL, CONS, SYMBOL, FIXNUM, FLONUM, STRING, FUNC, STRUCT, TENSOR, HLOPROG, PTR`. Ячейка — 32 байта. Вектор (`#(...)`) — литеральная форма ридера, `TYPE-OF` → `VECTOR`; запись `#\A` читается как `(CHAR "A")` — список-данные, а не отдельный char-тип, и `CHAR-CODE` принимает строку.

| Тип | Пример | Python-аналог |
|---|---|---|
| Целое (fixnum, int64) | `42`, `-7` | `int` |
| Вещественное (flonum, double) | `3.14`, `1e-3` | `float` |
| Строка | `"hello"` | `str` |
| Символ | `x`, `MY-SYM` | — (ближе всего `enum`/интернированные имена) |
| Keyword-символ | `:linux`, `:avx2` | литерал, как `enum`-константа (самовычисляем) |
| Список (cons-ячейки) | `(1 2 3)`, `(1 . 2)` | `list` (односвязный) |
| nil | `nil` | `None` / `[]` |
| Истина | `t` | `True` |
| Тензор | `(tensor ((1.0) (2.0)))` | `np.ndarray` |
| Функция (callable) | `(lambda (x) (* x x))`, `+`, скомпилированная JIT-обёртка | функция |
| Структура | `(defstruct pt (x y))`, затем `(pt 1 2)` | объект `@dataclass` |
| HLO-программа | результат `(HLO-COMPILE ...)` | скомпилированная функция |
| Указатель (`ptr`) | результат `(FFI-ADDR st 'field)` | `ctypes.c_void_p` |
| Вектор | `#(1 2 3)` | (нет аналога) — литеральный вектор, `TYPE-OF` → `VECTOR` |
| Char-литерал | `#\A` → `(CHAR "A")` | (нет аналога) — список-данные, `CHAR-CODE` берёт строку |

Функция — **один callable-атом** (тег `FUNC`): лисп-замыкание, примитив на C и его нативная компиляция — одно значение, один путь вызова. Мастер-запись атома — S-выражение (cons `(params body . env)` для лисп-функции, символ имени для C-примитива), а нативный код — выбрасываемый кэш поверх неё. `type-of` возвращает `FUNCTION` для всех трёх вкусов, печать — `#<function>` (у примитива — с именем: `#<function +>`). Подробно — гл. 19 и 20.

**Символы регистронезависимы**: ридер интернирует их через `SymbolTable::intern` (см. `src/core/symbol.cpp`); `Print`, `print`, `PRINT` — один и тот же символ (один и тот же `Symbol*`, O(1) сравнение по указателю). Поэтому все имена примитивов в коде записаны в верхнем регистре (`T+`, `MATMUL!`, `MSE!` и т.п.), но `(matmul! x w)` в пользовательском коде тоже работает. `INTERN` приводит имя к правилу читателя: `(intern "print")` — тот же символ, что `PRINT`.

Литеральные данные — через квотирование:

```lisp
'(1 2 3)          ; список-данные, не вызов
'foo              ; символ foo
`(a ,b ,@c)       ; квази-цитирование (шаблоны, гл. 12)
#'car             ; функция как значение
#(1 2 3)          ; вектор
#\A               ; символ-литера
```

> 🐍 В Python `'(1 2 3)` эквивалентен `[1, 2, 3]`, а `(1 . 2)` — паре `(1, 2)`.

**Keyword-символы самовычисляемы** (как в Common Lisp): `:linux` — литерал, значение которого он сам, кавычка не нужна, `(equal :linux :linux)` → `t`. Ключевые символы работают как константы-ключи и имена фич: `:avx2` в `target-feature` (§3.16), `:int` в `argparser` (гл. 15.17).

## 3.3 Переменные: defvar, setq, let

```lisp
(defvar answer 42)        ; глобальная переменная
(setq answer 43)          ; изменить существующую

(let ((x 1) (y 2))        ; локальные биндинги (параллельные)
  (+ x y))                ; → 3

(let* ((x 1) (y (+ x 1))) ; последовательные биндинги
  y)                      ; → 2
```

В реализации (`src/eval/interpreter.cpp::do_setq`, `do_defvar`, `do_let`, `do_let_star`) `defvar` записывает значение в `global_env_.bindings` и при необходимости клонирует в stable-память (`root_arena_`). `setq` ищет существующий символ в текущем фрейме и обновляет in-place, либо добавляет в глобальное окружение.

> 🐍 **Python-аналогия.** `defvar` ≈ присваивание на верхнем уровне модуля; `setq` ≈ повторное присваивание; `let` ≈ локальные переменные функции — только с явной областью видимости в скобках:
> ```python
> x, y = 1, 2        # let  (параллельно)
> x = 1; y = x + 1   # let* (последовательно)
> ```

Разница `let`/`let*` — как в Python-распаковке `a, b = f(), g()` (обе вычисляются до присваивания) против трёх отдельных строк.

> ⚠️ **`setq` с несколькими парами — семантика Common Lisp.** `(setq a 1 b 2)` присваивает **все** пары слева направо, и каждая следующая пара видит биндинг предыдущей: `(setq row (cons cur row) cur nil i (+ i 1))`. Нечётное число аргументов — ошибка.

## 3.4 Функции: defun, lambda, \

```lisp
(defun add (a b) (+ a b))
(add 2 3)                        ; → 5

(defun greet (name &optional greeting)
  (strcat (if greeting greeting "Hello, ") name))
(greet "Lars")                   ; → "Hello, Lars"
(greet "Lars" "Привет, ")        ; → "Привет, Lars"
```

`&optional` — необязательные параметры со значениями по умолчанию: `(defun f (a &optional (b 10)) ...)`. Если параметр опущен — используется default:

```lisp
(funcall (lambda (a &optional (b 5)) (list a b)) 1)   ;; → (1 5)
```

`&rest` собирает **весь** хвост аргументов в список:

```lisp
(funcall (lambda (a &rest r) (list a r)) 1 2 3)       ;; → (1 (2 3))
```

Оба маркера относятся к списку параметров: `(f 1 2 3)` на `(lambda (a &rest r))` привязывает `a=1`, а `r=(2 3)` — ни один аргумент не теряется. Функции с `&rest`, `&optional` или точечным хвостом параметров компилируются JIT'ом наравне с обычными (семантика паритетна интерпретатору — гл. 20) — поведение идентично по построению.

Анонимные функции:

```lisp
(lambda (x) (* x x))     ; полное имя
(\ (x) (* x x))          ; синоним lambda — читается «лямбда»
(map (\ (x) (* x x)) '(1 2 3))   ; → (1 4 9)
```

> 🐍 `(\ (x) (* x x))` — это `lambda x: x * x`.

**`\` — синоним `lambda`, а не отдельная форма.** Он работает везде, где ожидается лямбда: как значение аргумента (`map`, `apply`, `funcall`), в `let`-биндинге, в теле `defun` и в JIT-компилируемом коде — компилятор видит за ним ту же лямбду и специализирует её так же. Различий в семантике, арности или возвращаемом значении нет:

```lisp
(funcall (\ (x) (* x x)) 5)                  ; → 25
(let ((f (\ (x) (* 2 x)))) (funcall f 21))   ; → 42
(map (\ (x) (* x x)) (range 5))              ; → (0 1 4 9 16)
```

Вызов функции-значения: `(funcall f 5)` ≈ `f(5)`. Есть также `(apply f args-list)`.

Конструктор структуры (гл. 13) — тоже обычная функция: `(defstruct pt (x y))` даёт функцию `pt`, и `(pt 1 2)` создаёт структуру. Поле читается `(slot-value p 'x)`, записывается `(set-slot p 'x 10)`.

> ⚠️ **Лишние аргументы — ошибка.** Хвост аргументов вызова без `&rest` — ошибка («too many arguments»), как и для других неверных вызовов (проектная конвенция — громкий отказ).

Рекурсия — естественный способ писать циклы, но стек не бесконечен: интерпретатор считает eval-кадры и на лимите (по умолчанию 10 000) бросает **ловимую** ошибку. Списочные примитивы stdlib (`length`, `reverse`, `member`, `last`, `butlast`, `nth`, `map`, `filter`, `range`, `take`, `zip-with`) итеративные — длинный список им не страшен. Для ML-горячих циклов используйте `while` с per-iteration scope (см. гл. 5).

```lisp
(EVAL-MAX-DEPTH)        ;; → 10000  (читает лимит)
(EVAL-MAX-DEPTH 12000)  ;; → 10000  (поднимает лимит, возвращает старый)
(try (down 200000) (e (list 'caught)))
;; → (CAUGHT) — «eval: stack guard - thread stack exhausted
;;    (lower EVAL-MAX-DEPTH or reduce recursion)»; после catch eval полностью жив
```

> ⚠️ **Сторож стека, а не только счётчик кадров.** Лимит считает eval-формы, а не вызовы, поэтому глубокая не-хвостовая рекурсия упирается в реальный стек. На пути вызова `apply` проверяет пол стека, `StackExhausted` отделён от семантической ошибки, и `call_value` поднимает флаг — первая же `apply`, увидевшая bail, бросает наверх. Ловимый отпор приходит и из интерпретатора, и из JIT-кода (контракт — `tests/stack_guard.qlsp`). Потолок ручного лимита при стеке 8 МБ — ~11 000 eval-кадров; выше guard просто не успевает сработать до SIGSEGV. Windows-бинарник резервирует 8 МБ стека сборкой (`-Wl,--stack=0x800000`).

**Хвостовая рекурсия без предела.** Self-хвостовой вызов не кладёт новый кадр, а пере-биндит текущий: параметры копируются в куче-соп, итерация освобождается при возврате. Поэтому глубина рекурсии не растёт вообще, и guard выше не нужен:

```lisp
(defun tc-sum (n acc) (if (= n 0) acc (tc-sum (- n 1) (+ acc n))))
(print (tc-sum 200000 0))   ;; → 20000100000 — 200 000 хвостовых вызовов
```

Условия: вызов должен быть в хвостовой позиции; при живых узлах ленты автограда TCO для итерации выключается (корректность важнее скорости); `let`/`let*` разворачиваются в хвосте до 8 уровней вложенности. Взаимные хвостовые вызовы, нативная рекурсия JIT и хвосты за `cond`/`when` — обычная рекурсия.

## 3.5 Списки

Список — односвязный список cons-ячеек, cons-ячейки берутся из `ConsCellPool` (O(1) alloc/free). Базовые операции (имена в верхнем регистре после `intern`):

```lisp
(cons 1 '(2 3))     ; → (1 2 3)      — добавить в начало
(car '(1 2 3))      ; → 1            — голова
(cdr '(1 2 3))      ; → (2 3)        — хвост
(list 1 2 3)        ; → (1 2 3)      — создать из элементов
(append '(1 2) '(3))  ; → (1 2 3)    — конкатенация
(length '(1 2 3))   ; → 3
(reverse '(1 2 3))  ; → (3 2 1)
(nth 1 '(a b c))    ; → b            — элемент по индексу
(member 2 '(1 2 3)) ; → (2 3)        — поиск (возвращает хвост с позиции)
(null '())          ; → t
(atom 5)            ; → t            — атом?
```

Комбинации `cadr`, `caddr`, `cddr` и т.д. — сокращения `(car (cdr x))`, как `x[1]`, `x[2]`, `x[2:]` в Python. Все 16 комбинаций до 4 уровней определены в `stdlib/core.qlsp`: `caar`, `cadr`, `cdar`, `cddr`, `caaar`, `caadr`, `cadar`, `caddr`, `cdaar`, `cdadr`, `cddar`, `cdddr`, `second`, `third`, `fourth`, `first`, `rest`.

Функции высшего порядка (`map`/`filter`/`reduce` — модуль `collections`, гл. 15.16):

```lisp
(map (\ (x) (* 2 x)) '(1 2 3))          ; → (2 4 6)
(filter (\ (x) (> x 1)) '(1 2 3))       ; → (2 3)
(reduce + '(1 2 3 4))                   ; → 10
(zip-with + '(1 2) '(10 20))            ; → (11 22)
```

> ⚠️ **Порядок аргументов `reduce`.** Вызывается `(fn элемент аккумулятор)` — элемент первым (не как в Common Lisp); без инициализатора первый элемент становится аккумулятором без вызова `fn`. `map` многолистовый: `(map f xs ys)` останавливается на корочайшем списке.

`map`, `filter`, `reduce`, `range`, `take`, `zip-with` сделаны итеративно (`while` + локальный аккумулятор + `reverse`): список в миллион элементов им не страшен, и нативная страница JIT не упирается в потолок рекурсии. Результат — обычный список в scratch-памяти.

> 🐍 **Python-аналогия.**
> ```python
> [2*x for x in xs]        # map
> [x for x in xs if x > 1] # filter
> functools.reduce(op.add, xs)  # reduce
> [a + b for a, b in zip(xs, ys)]  # zip-with
> ```

Важно: списки в Qualisp иммутабельны по смыслу использования — операции создают новые списки в scratch-памяти (гл. 5), нет `lst.append()`.

## 3.6 Управление потоком

```lisp
(if (> x 0) "pos" "neg")         ; if: (if условие then else)

(cond                            ; cond = цепочка elif
    ((< x 0) "neg")
    ((= x 0) "zero")
    (t "pos"))

(progn                           ; последовательность, значение последней
    (print "шаг 1")
    (print "шаг 2")
    (* 2 2))

(while (< i 10)                  ; цикл while (с per-iteration scope, гл. 5)
    (setq i (+ i 1)))

(and a b c)                      ; короткое замыкание
(or a b c)
(xor a b c)                      ; нечётное число истинных аргументов
```

> 🐍 `(if c a b)` — тернарник `a if c else b`. `(cond ...)` — `if/elif/else`. `(progn ...)` — тело функции. `and`/`or` — одноимённые операторы Python; `xor` — `functools.reduce(operator.xor, map(bool, xs))` (в Python нет встроенного).

> ⚠️ **Строгий `if`.** Форма принимает ровно 2–3 аргумента: `(if test then [else])`. Четвёртая форма — ошибка программы: «if: too many forms (use cond or progn for branches)». JIT-компилятор зеркалит проверку: такое тело уходит в интерпретатор, где ошибка и бросается. Поэтому `(if t 1 2 3)` вне `try` — ошибка, а не `1`; для ветвления с несколькими формами используйте `cond`/`progn`.

Любое значение кроме `nil` истинно. `nil` — одновременно «пустой список» и «ложь». `(null x)` — предикат для пустого. Ноль — **истина**: `(if 0 'yes 'no)` → `yes`, и то же в предикатах и логических операторах. Ложь — только `nil`.

### `and` / `or` / `xor` — гибрид

`and` и `or` живут в двух видах, и это не два разных имени, а одна пара примитивов:

- **в позиции головы формы** — ленивые спецформы с коротким замыканием. `(and a b c)` вычисляет аргументы слева направо и останавливается на первом `nil` (для `and`) или первом истинном (для `or`); хвост не вычисляется. Значение — само это значение, а не `t`/`nil`;
- **как значение** — обычные n-арные встроенные функции `AND`/`OR`. Передать их можно куда угодно: в `apply`, `map`, `funcall`, в переменную.

```lisp
(apply and '(a b))                  ; то же, что (and a b) — но функцией
(apply or '(a b))                   ; то же, что (or a b)
(map or '(nil 3) '(nil 4))          ; → (3 4) — поэлементно
(map and '(1 2) '(3 4))             ; → (3 4)
```

Семантика «как значение» — n-арная, без лени: `(and)` → `T`, `(or)` → `nil`, `(and a b ...)` → последнее истинное значение (или `nil`, если какое-то ложно), `(or a b ...)` → первое истинное.

```lisp
(and)                               ; → T
(or)                                ; → nil
(and 1 2 3)                         ; → 3
(or nil nil 7)                      ; → 7
(and 1 nil 3)                       ; → nil
```

`XOR` — отдельная n-арная функция (не гибрид, спецформы у неё нет): истина, если истинных аргументов **нечётное** число. `(xor)` → `nil`, `(xor t)` → `T`, `(xor t t)` → `nil`, `(xor t nil t)` → `T`.

```lisp
(map xor '(t t t nil) '(t nil nil nil))   ; → (nil T T nil)
```

`and` без аргументов — `T` (конъюнкция пустого набора истинна), `or` и `xor` без аргументов — `nil`. Это определённые значения, а не «пустой вызов».

> ⚠️ **Значение — последнее вычисленное, а не булев флаг.** `(and 1 2)` → `2`, `(or nil 7)` → `7`: иначе `(defvar x (or (dict-get d 'k) 0))` терял бы само значение. Python ведёт себя так же: `1 and 2` → `2`.

### `and` / `or` в компилируемом коде

Под JIT логика понижается в `let` + `if`: `(or a b)` → `(let ((g a)) (if g g b))` — первый аргумент вычисляется ровно один раз, второй — только при нужде. `(and ...)` — зеркально, `(cond ...)` разворачивается в цепочку `if`, а `(and)`/`(or)` — в константы `T`/`nil`. Поэтому ленивость спецформы и значение n-арной функции не расходятся между интерпретатором и нативной страницей (гл. 20).

## 3.7 Сравнения и равенство

```lisp
(= 1 1)      (= 1.0 1.0)   ; числовое равенство (примитив =)
(string= "a" "a")          ; строки (примитив STRING=)
(equal x y)                ; структурное равенство (cons, строки, символы)
(eq x y)                   ; идентичность символа (Symbol* один и тот же)
(EQ x y)                   ; идентичность объекта (тот же объект)
(< <= > >=)                ; числа
```

Разница трёх предикатов — в уровне сравнения. `equal` — структурно для cons, строк и символов и по адресу для объектов с идентичностью; `eq` — **идентичность символа**: один и тот же интернированный `Symbol*`, сравнение O(1) по указателю; `EQ` — **идентичность объекта** (наблюдатель контракта цитат): отдельный примитив для вопроса «это тот же объект?» — замыкание, структура, тензор, любое значение с идентичностью. `(eq 'a 'a)` истинно, потому что символ один; два разных объекта с одинаковыми полями `EQ` не склеивает.

Контракт `EQUAL`: для cons-списков, строк и символов сравнение **структурное** (рекурсивно по car/cdr); для значений с идентичностью — замыканий, HLO/JIT-программ, **структур и тензоров** — по адресу. Ключевое свойство — рефлексивность: `(equal x x)` истинно для **любого** живого значения. Сравнение тензоров по значению — дело тензорных примитивов, не `equal`:

```lisp
(defvar a (tensor ((1.0 2.0))))
(equal a a)                ;; → t   — один и тот же буфер (идентичность)
(equal a (tensor ((1.0 2.0))))  ;; → nil — другой буфер
```

Структуры (гл. 13) сравниваются так же — **по идентичности**: `(equal p p)` → `t`, а две одинаковые по полям структуры дают `nil`. Это честно для мутабельного объекта: поля пишутся через `set-slot`, и равенство живёт по адресу, как `a is b` в Python.

> 🐍 `(equal a b)` — это `a == b` для списков, строк и символов и `a is b` для мутабельных объектов (структуры, тензоры): объекты с буферами сравниваются по идентичности, как Python-объекты без `__eq__`.

**Числа сравниваются по значению, а не по представлению.** `(= 0 0.0)` → `t`: fixnum и flonum сравниваются численно, как в Python. Это важно для production-обучения: целочисленный argmax-пред должен совпадать с float-метками из CSV-тензоров. Все прочие расхождения тегов по-прежнему дают `nil`: `(= 42 "42")` → `nil`.

## 3.8 Арифметика и математика

Примитивы (`src/eval/interpreter.cpp::register_primitives`):

```lisp
(+ 1 2 3)   (- 10 3)   (* 2 3 4)   (/ 7 2)
(mod 7 2)   (pow 2 10)  (sqrt 16.0) (abs -3)
(exp 1.0)   (log 2.718281)  (sin 0.0)  (cos 0.0)  (atan 1.0)
(random)                   ; → float [0,1)
(randint 1 6)              ; целое из [lo, hi)
(min2 1 2)  (max2 1 2)     ; примитивы для двух аргументов
```

`(/ 7 2)` → `3.5`: арифметика Qualisp ведёт себя как Python 3 — деление целых даёт float, а не усечённое целое. Для целочисленного деления используйте `mod` или работайте во float, как принято в ML-коде.

### `+ - * /` диспетчеризуются по типу операндов

Одна и та же форма работает и с числами, и с тензорами — по типу аргументов:

| Тип аргументов | `(+ a b)` | `(- a b)` | `(* a b)` | `(/ a b)` |
|---|---|---|---|---|
| числа | арифметика | арифметика | арифметика | арифметика |
| тензоры / HLO-прокси | поэлементно, теми же ядрами, что `T+!` | `T-!` | **поэлементно (Hadamard)**, ядро `T*!` | поэлементно, ядро `T/!` |

Тензорные операторы пишут узел ленты сами, по состоянию входа (см. ниже), и поддерживают broadcast: скаляр и правое выравнивание осей — как в NumPy.

```lisp
(let ((a (tensor ((1.0 2.0) (3.0 4.0)))))
  (print (+ a 1.0))       ;; → tensor([2, 3, 4, 5], shape=[2, 2]) — скаляр применён поэлементно
  (print (- a))           ;; → tensor([-1, -2, -3, -4], shape=[2, 2]) — отрицание
  (print (/ a)))          ;; → tensor([1, 0.5, 0.333333, 0.25], shape=[2, 2]) — обратное
```

> ⚠️ **`*` на тензорах — не матричное произведение.** `(* a b)` — поэлементное (Hadamard), форма результата — форма операндов после broadcast. Матричное — отдельная форма `MATMUL` / `MATMUL!` (и оператор `MATMUL` в HLO-графе). `(matmul a a)` на `[[1,2],[3,4]]` → `[[7,10],[15,22]]`, `(* a a)` → `[[1,4],[9,16]]`.

Унарные формы: `(- x)` — отрицание, `(/ x)` — обратное; на тензоре это поэлементные операции над всем тензором. У тензорных `T-!`/`T/!` унарной формы нет: `(- x)`/`(/ x)` дают нужный результат через перегрузку оператора (`T-!`/`T/!` требуют два операнда).

### Автоград включается сам

Оператор пишет узел ленты только если у входа `requires_grad`: `(+ param 1)` обучается, `(+ обычный-тензор 1)` — нет. Отдельного «включить автоград» вызова нет — состояние приходит с тензором (`PARAM`). Суффикс `!` остаётся явной tape-операцией: `T+!` пишет ленту всегда, `T+` — по состоянию входа; на тензоре оператор и его `!`-версия дают одно значение и один градиент.

```lisp
(defvar p (param (tensor ((2.0)))))
(defvar l (+ (* p p) 1.0))      ;; лента: T*!, затем T+! — новые записи первыми
(tape-form)
;; (((T+! tensor([5], shape=[1, 1], dtype=f32)
;;     (tensor([4], shape=[1, 1], dtype=f32) tensor([1], shape=[1], dtype=f32)) nil)
;;   (T*! tensor([4], shape=[1, 1], dtype=f32)
;;     (tensor([2], shape=[1, 1], dtype=f32) tensor([2], shape=[1, 1], dtype=f32)) nil))
```

> 🐍 Ближайший аналог — перегрузка операторов в PyTorch: `a * b` пишет `MulBackward` в граф, если `requires_grad`. Разница в том, что в Qualisp граф — это форма `TAPE-FORM` (гл. 7), а не невидимая структура.

### Под HLO-трассой

Под трассой (`HLO-START`/`START-TRACE`, гл. 10) `+ - *` строят узлы графа: у `+` и `*` есть свои узлы `ADD`/`MUL`, у `-` отдельного узла нет — он раскладывается в `MUL(-1) + ADD` (FUSION-дерево `(ADD P0 (MUL P1 -1))`).

Деление — исключение. `T/!` под трассой отвечает внятной ошибкой — «T/! under tracing: division has no graph node (use explicit ops)». Оператор `(/ ...)` разворачивается в то же ядро, поэтому в трассируемом коде деления нет; вне трассы и `T/!`, и `(/ ...)` — обычные tape-операции (пишут узел в ленту по состоянию входа).

`!`-операция под трассой ведёт себя по наличию двойника: у `T+!`, `T*!`, `MATMUL!` он есть, и форма становится обычным узлом графа (одна forward-математика, лента не пишется); у операции без двойника (`LOG!` и т.п.) — внятная ошибка с именем операции. Это позволяет писать один и тот же код для обучения и для трассировки.

> 🐍 В PyTorch `a / b` под `torch.compile` работает (в графе есть div-узел). В Qualisp деление — единственная из четырёх операций без графового узла: в трассируемом коде деления нет, поэтому его выносят за трассу или заменяют умножением на обратную величину.

## 3.9 Строки

```lisp
(strcat "Hello, " "World")        ; → "Hello, World"  (f"{a}{b}")
(strcat "n=" 5)                   ; → "n=5"           — не-строка печатается как WRITE-TO-STRING
(substr "hello" 1 3)              ; → "ell"           (s[1:4])
(number-to-string 42)             ; → "42"            (str(42))
(string= "a" "a")                 ; → t
(string-length s)                 ; len(s)
(string-ref s i)                  ; байт 0..255 по индексу (ord(s[i]))
(string-view s from len)          ; окно-строка: s[from:from+len] без копирования
(string-split sep s)              ; s.split(sep) — разделитель первым
```

> ⚠️ **`strcat` превращает каждый аргумент в текст.** Не-строка печатается тем же принтером, что `WRITE-TO-STRING`: `(strcat "n=" 5)` → `"n=5"`, `(strcat nil)` → `"nil"`. На этом же стоит сводка `run-tests` (`(strcat (type-of *test-passed*) "/" ... " passed")`) — счётчик печатается, а не исчезает.

Порядок аргументов у строковых операций — «что делаем, потом с чем»: `(STRING-SPLIT разделитель строка)`, `(STRING-JOIN разделитель список)`, `(STRING-REPLACE строка что на-что)`.

### Строковые окна

`STRING-VIEW` и `STRING-REF` не копируют строку — они дают **окно** (без аллокации):

```lisp
(let ((s "hello"))
  (print (string-view s 0 5))       ;; → "hello" — окно в stable-строку, копии нет
  (print (string-ref s 0))          ;; → 104 — байт 'h'
  (print (string-ref s 1))          ;; → 101 — байт 'e'
  (print (type-of (string-view s 0 5)))   ;; → STRING
  (print (equal (string-view s 0 5) "hello")))  ;; → T
```

- `(STRING-REF s i)` — байт `0..255` по индексу, без аллокации;
- `(STRING-VIEW s from len)` — окно в stable-строку, без копирования.

**Окно прозрачно:** это обычная строка. `TYPE-OF` → `STRING`, `equal` сравнивает по содержимому, и все строковые операции — `STRING-LENGTH`, `STRCAT`, `SUBSTR`, `STRING-SPLIT`, `STRING-CONTAINS`, `STRING-INDEX` — работают над ним одинаково.

```lisp
(let ((v (string-view "hello world" 6 5)))
  (print v)                        ;; → world
  (print (string-length v))        ;; → 5
  (print (strcat v "!"))           ;; → "world!"
  (print (string-split "o" v)))    ;; → ("w" "rld")
```

Границы — ошибка с именем операции: `(STRING-VIEW "abc" 1 5)` → `string-view: range [1,6) out of [0,3)`; `(STRING-REF "abc" 9)` → `string-ref: index 9 out of range (3)`.

**Копия — только на выходе из окна.** Над скретч-строкой (литерал, результат `SUBSTR` или другого окна) и над окном (`view-of-view`) операция даёт копию: такое окно не удержать алиасом. Escape в stable — `(defvar v (string-view ...))`, `setq` глобала — материализует строку в копию, и она живёт дальше сама.

**`STRING-SPLIT` — куски-окна, и разделитель первым.** Над stable-строкой `STRING-SPLIT` отдаёт куски-окна (копий нет); `string-slice`, `string-starts-with`, `string-ends-with` тоже работают через окна. Значения и семантика прежние — дешевле стало устройство.

```lisp
(STRING-SPLIT " " "a b c")         ; → ("a" "b" "c")  — правильно
(STRING-SPLIT "," "a,b,c")         ; → ("a" "b" "c")
(STRING-SPLIT "a,b,c" ",")         ; → (",")          — неверный порядок: разделитель ищется в "a,b,c"
```

> 🐍 В Python `s.split(sep)` — метод строки, порядок аргументов задан приёмником. В Qualisp приёмника нет, поэтому разделитель — **первый** аргумент: `(STRING-SPLIT sep s)`.

## 3.10 Печать

```lisp
(print "loss: 5")                     ; один строковый аргумент
(print (strcat "epoch " (to-string 5) ", loss " (to-string 0.25)))
;; → epoch 5, loss 0.25 — составные сообщения собираются через strcat
(display x)                    ; без кавычек/префиксов (raw)
```

`print` и `display` — это разные примитивы (`prim_print` и `prim_display`); print добавляет оформление (префиксы, кавычки для строк), display — голый вывод.

> ⚠️ **Ровно один аргумент.** `print` и `display` принимают **строго один аргумент** — лишний это ошибка арности («print: takes exactly one argument»). Чтобы напечатать несколько значений, соберите их сами: `(print (list "epoch" 5))` или склейте через `strcat`.

## 3.11 Собираем вместе: FizzBuzz

```lisp
(defun fizzbuzz (n)
  (cond
    ((= (mod n 15) 0) "FizzBuzz")
    ((= (mod n 3) 0)  "Fizz")
    ((= (mod n 5) 0)  "Buzz")
    (t (number-to-string n))))

(map fizzbuzz (range 16))
;; → ("FizzBuzz" "1" "2" "Fizz" "4" "Buzz" "Fizz" "7" "8" "Fizz" "Buzz" "11" "Fizz" "13" "14" "FizzBuzz")
;;    (range 16) начинается с 0: 0 кратно 15, поэтому первый элемент — "FizzBuzz")
```

> 🐍 Тот же код на Python:
> ```python
> def fizzbuzz(n):
>     if n % 15 == 0: return "FizzBuzz"
>     elif n % 3 == 0: return "Fizz"
>     elif n % 5 == 0: return "Buzz"
>     else: return str(n)
>
> [fizzbuzz(i) for i in range(1, 16)]
> ```

## 3.12 Тесты прямо в языке

В `stdlib/core.qlsp` встроен мини-фреймворк тестов:

```lisp
(deftest "fizzbuzz-15"
  (assert-eq (fizzbuzz 15) "FizzBuzz" "15 должно быть FizzBuzz"))

(deftest "длина-списка"
  (assert-eq (length '(1 2 3)) 3 "длина"))

(run-tests)
```

`deftest` ≈ `def test_...()` в pytest, `run-tests` ≈ `pytest`. Также в `core` есть `assert-zero` для проверки тензоров (что сумма квадратов градиента ≈ 0) — стандартный приём в тестах градиентов. Имена тестов склеиваются через `strcat` с префиксом `"test::"`, чтобы не было коллизий с пользовательскими символами.

Провал assert'а проваливает весь тест: сводка печатает `1/2 passed` и `SOME TESTS FAILED` (вывод `FAIL:` с сообщением), процесс завершается с кодом 1 — это и есть сигнал CI. Сводка печатает **счётчики**, а не имена типов, и освобождает реестр в конце: повторный `run-tests` в том же скрипте даёт `0/0 passed` и «all tests passed».

> ⚠️ **Сравнение float в release ненадёжно.** Release собирается с `-ffast-math`, поэтому `a == b` для NaN истинно, и `assert-eq` по списку `TENSOR->LIST` физически не способен заметить NaN. Порог числовой метрики обязан быть выше baseline вырожденного решения, а конечность проверяется `(FINITE? t)` (гл. 3.15), а не сравнением.

## 3.13 Гомоиконность: код как данные

Qualisp — гомоиконный язык: программа и данные имеют одинаковую структуру (S-выражения). В рантайме доступны примитивы для прямой работы с этой эквивалентностью: можно парсить строки в код, сериализовать код обратно, исполнять построенные программы, инспектировать замыкания.

Эта эквивалентность закреплена как **инвариант одной формы**: S-выражение — единственная авторитетная форма программы. Всё, что нативно (JIT-страницы замыканий, HLO-кёрнелы), — выбрасываемый кэш, выведенный из S-выражений и пересобираемый на лету; ничего не хранится «поверх» S-выражений, и вся гомоиконная механика ниже работает поверх скомпилированного кода без ограничений. Подробности — гл. 20 (JIT) и гл. 21 (образы).

### READ-FROM-STRING / WRITE-TO-STRING

```lisp
(read-from-string "(+ 1 2)")     ; → (+ 1 2)   (S-выражение)
(write-to-string '(+ 1 2))       ; → "(+ 1 2)" (строка)
```

> 🐍 Аналог `ast.literal_eval("(1 + 2)")` и `ast.unparse(...)` в Python — но здесь выражения нативные для языка, а не отдельное AST-дерево.

### EVAL — вычисление в рантайме

```lisp
(eval '(+ 1 2))                              ; → 3
(eval (read-from-string "(* 6 7)"))          ; → 42
(setq expr '(lambda (x) (* x x)))
(funcall (eval expr) 5)                      ; → 25 — eval даёт замыкание, вызов — funcall
```

> 🐍 Аналог `eval("1 + 2")` в Python. В Qualisp `eval` работает с самим S-выражением, без строкового прохода. `(eval expr)` вычисляет форму и возвращает **значение**; если это лямбда — получите замыкание, которое вызывается через `funcall`, как объект функции после `eval("lambda x: x*x")` в Python.

### FUNCTIONP / FUNCTION-PARAMS / FUNCTION-BODY / FUNCTION-ENV

```lisp
(defun square (x) (* x x))

(functionp square)           ; → T  (значение в позиции аргумента — замыкание)
(functionp 'square)          ; → nil (квотированный символ — не значение)
(function-params square)     ; → (X)        (список параметров)
(function-body square)       ; → ((* X X))  (тело как S-выражение)
(function-env square)        ; → nil для defun (глобальный env)
```

`FUNCTIONP` — предикат значения, а не имени: символ под кавычкой — данные, а не функция. `FUNCTION-PARAMS`/`FUNCTION-BODY` принимают значение функции; у C-примитива тела нет — они отвечают ошибкой «expected a function; primitives carry no body». `FUNCTION-BODY` возвращает код лямбды как данные — основы для метапрограммирования (генерация кода, lint, автодокументация). В Python аналог — `inspect.getsource`, но здесь возвращается **структурное** представление, а не исходный текст.

### SYMBOL-NAME

```lisp
(symbol-name 'hello)         ; → "HELLO"  (после intern — uppercase)
(symbol-name '|+ 1 2|)       ; → "+"  (внутри bars — verbatim)
```

> 🐍 Аналог `str(identifier)` для имён, не для значений. В Python такого нет — имена и значения разнесены.

### BOUNDP

```lisp
(boundp 'undefined-var)      ; → nil  (не определена)
(defvar x 42)
(boundp 'x)                  ; → T
```

Полезно в макросах и meta-circular interpreter'ах: «определена ли переменная?» без чтения значения.

### SET-READER-MACRO

```lisp
(set-reader-macro 'p (lambda (stream) '(print "hi")))
'p  ; в REPL автоматически напечатает "hi"
```

Подробнее — в гл. 12.

### RANDINT

```lisp
(randint 1 6)                ; → целое из [1, 6): 1..5
(randint 1 10)               ; → 1..9
```

> 🐍 Аналог `random.randrange(a, b)` — верхняя граница исключается. Аргумент один: он попадает в `hi`, и результат выходит за разумные пределы, поэтому вызывайте `randint` с двумя аргументами. `(random)` — float `[0,1)`, `(randn (list n))` — гауссов тензор.

### IMPORT-FROM

Частичный импорт вместо `import`:

```lisp
(import-from dl (linear train-step train-epochs))
;; поднимает только LINEAR, TRAIN-STEP, TRAIN-EPOCHS
;; остальное содержимое dl (net-forward, layer-w, ...) остаётся недоступным
```

> 🐍 Аналог `from sklearn.ensemble import RandomForestClassifier` в Python — но без скрытого `import sklearn` (модуль целиком не загружается как имя в глобальный env). Синтаксис — `(import-from модуль (имена...))`: имя модуля — символ или строка (`dl`, `"dl"`), список имён — второй аргумент.

## 3.14 Что увидел интерпретатор

Когда вы набираете `(+ 1 2)` в REPL:

1. **`Reader`** (`src/reader/readtable.cpp`) разбивает вход на токены, строит cons-дерево в scratch-scope.
2. **`Interpreter::eval`** (`src/eval/interpreter.cpp:235`) проверяет тип выражения:
   - атом (`nil`, число, строка, символ, тензор, замыкание, примитив, структура, HLOPROG) → возврат самого значения;
   - cons → специальная форма или вызов функции.
3. **`eval_cons`** (`eval_cons`) различает special forms (`if`, `let`, `defun`, `defmacro`, `match`, `defrule`, …) и обычные вызовы.
4. Для обычного вызова аргументы вычисляются через `eval_list` в том же scratch-scope; затем `apply` ищет примитив/замыкание.
5. Примитив (`src/eval/interpreter.cpp::register_primitives`) исполняется на C++; замыкание — создаётся новый `EnvFrame` и выполняется тело (`Interpreter::apply`).

В hot path вызовы тензорных операций `T+`, `T*`, `MATMUL` идут через AVX2/FMA OpenBLAS — без аллокаций cons-ячеек (тензор живёт в TensorBufferPool, гл. 5).

## 3.15 Тензорные примитивы: арность и доступ к элементам

Здесь — только контракты вызова; устройство тензоров разобрано в гл. 6.

Тензорные операции — обычные примитивы, и к ним предъявляется тот же контракт, что к любой функции: арность и типы аргументов проверяются, а не роняют процесс. `T+`, `T-`, `T*`, `MATMUL`, `CONV2D`, `MAXPOOL2D` (и их autograd-варианты), `BATCHNORM!`, `LAYERNORM!` при неверном вызове дают внятную ошибку — с указанием, что именно не так: не хватает аргумента, аргумент не целый, индекс отрицательный, ожидался тензор, а пришло число. Ошибка — структура (гл. 15), её текст читается `error-message`; `catch-error` дополнительно печатает цепочку ошибки. Например:

```lisp
(error-message (catch-error (lambda () (tref (randn (list 4)) 4))))
;; → "tref: index 4 out of range for dimension 0 of size 4"
(error-message (catch-error (lambda () (conv2d (tensor ((1.0 2.0) (3.0 4.0))) 1 1 1))))
;; → "expected tensor" — ядро свёртки должно быть тензором
```

### Доступ к элементу: `tref` и `tensor-item`

```lisp
(tref (tensor ((1.0 2.0))) 0)              ;; → 1.0  — один индекс: плоский номер элемента
(tref (tensor ((1.0 2.0)) (3.0 4.0)) 1 1)   ;; → 4.0  — N индексов: координаты ровно по рангу
(tensor-item (tensor ((1.0 2.0))) 1)        ;; → 2.0  — элемент по индексу
```

Контракт `tref`:

- **один индекс** — плоский номер элемента (как `NTH`, и как весь код проекта читает `(tref m 0)` на матрице);
- **N индексов** — координаты ровно по рангу тензора: два индекса на матрице, три на тензоре ранга 3; число индексов, отличное от ранга (кроме одного), — ошибка;
- **границы проверяются**: индекс вне диапазона — ошибка, а не значение из чужой памяти.

```lisp
(try (tref (randn (list 4)) 4) (e t))   ;; ловушка: e — структура ошибки, t вместо значения
(error-message (try (tref (randn (list 4)) 4) (e e)))
;; → "tref: index 4 out of range for dimension 0 of size 4"
```

`TENSOR-ITEM` принимает индекс вторым аргументом и читает **элемент по этому индексу**: выход за границу и отрицательный индекс — ошибка. Плоский список всего тензора даёт `TENSOR->LIST`.

### Окна по строкам и по плоскому индексу

Для строк и плоских срезов тензора есть отдельный вид доступа — **окно**: не копия, а алиас только для чтения (контракт владения — гл. 5, операции — гл. 6).

```lisp
(t-rows t from len)     ;; окно по строкам: [V] → [len], [V,d] → [len,d]
(t-slice t from len)    ;; непрерывное окно из len элементов с плоского индекса from, форма [len]
```

```lisp
(let ((m (tensor ((1.0 2.0) (3.0 4.0)))))
  (print (t-rows m 1 1))            ;; → tensor([3, 4], shape=[1, 2]) — одна строка
  (print (t-slice m 1 2)))          ;; → tensor([2, 3], shape=[2]) — плоский индекс 1, длина 2
```

- окно **read-only**: `TSET!`/`T+=`/`T-RELU` в него отказывают («destination is a read-only view»), чтобы оптимизатор не мог молча переписать веса через алиас;
- окно живёт после выхода владельца из scope и после переписи имени — владелец держится счётчиком;
- `TSET!` в источник виден через окно, обратное — нет;
- окно от окна материализуется в копию;
- `defvar`/`setq` глобала окна (escape в stable) даёт **копию**, и она writable;
- окно над trainable-параметром тоже read-only: чтобы обучать строки таблицы, используют `EMB-LOOKUP`/`T-GATHER!` плюс `ADAM-SPARSE-STEP`, а не окно (гл. 6, 8).

Тензор, полученный из окна, остаётся тензором: `TYPE-OF` → `TENSOR`, форма — форма окна. В NumPy срез `a[i:j]` — записываемое представление; в Qualisp окно только для чтения, и это осознанное ограничение модели памяти (гл. 5, 6). Формулировка «срезов нет» поэтому неточна: срезы есть, но в виде read-only окон, а запись идёт в источник через `TSET!`.

> 🐍 `(t-rows t i n)` — это `t[i:i+n]` (по строкам), `(t-slice t i n)` — `t.reshape(-1)[i:i+n]`. Оба результата в NumPy можно писать, в Qualisp — нет; для записи используйте `TSET!` в источник.

### Конечность значений

Release-сборка использует `-ffast-math`, поэтому сравнение плавающих в release ненадёжно (для NaN оно истинно). Конечность проверяется отдельным битовым примитивом:

```lisp
(FINITE? t)   ;; → t, если в тензоре нет NaN/Inf
```

Это единственный надёжный способ проверить NaN/Inf — и в тестах, и в обучающих циклах (подробно — гл. 6 и 7).

## 3.16 Вариационная компиляция: `target`, `target-feature`, `cfg`

Один компилятор параметризуется **дескриптором цели** — набором фич платформы (`:linux`, `:windows`, `:x86-64`, `:avx2`, …). Семантика одна для всех платформ: различия не форкаются, а выбираются по дескриптору — один эталон, один путь кода.

```lisp
(target)                 ;; → дескриптор платформы
(target-feature :avx2)   ;; → t или nil — запрос фичи (детерминирован)
```

- `(target)` возвращает алиас дескриптора платформы: алист `("os" . :LINUX)`, `("arch" . :X86-64)` и `("features" …)` — список фич (`:SSE2`, `:AVX2`, `:X86-64`, `:LINUX`, `:CPU`, `:DEV`).
- `(target-feature f)` — булев запрос фичи `f` (ключевой символ: `:linux`, `:x86-64`, `:avx2`, …). Детерминирован: повторный запрос отвечает тем же.
- `cfg` и `target-feature` согласованы по построению — один источник истины.

Условная форма `cfg`:

```lisp
(cfg :linux (init-for-linux))                  ;; простое условие — фича цели
(cfg (:and :x86-64 (:isa :avx2)) (fast-path))  ;; композиции :and / :or / :not
(cfg (:not :windows) (posix-only))
```

- Условие — фича или логическая композиция `(:and …)`, `(:or …)`, `(:not …)` (ISA-фичи — через `(:isa :avx2)`).
- **Несовпавшая ветка не выполняется.** Код отсекается на **раскрытии** — это фаза компиляции: ветка не компилируется и не исполняется, в рантайме накладных ноль. Это не `if`: условие проверяется один раз при раскрытии формы, а не при каждом проходе.
- Неизвестная фича в условии — внятная ошибка на раскрытии (опечатка в имени фичи не должна быть молчаливым `false`).
- Вложенные `cfg` считаются по тому же дескриптору цели.

> 🐍 **Python-аналогия.** `(target)` ≈ `sys.platform` / `platform.machine()` (дескриптор платформы), `(target-feature :avx2)` ≈ сверка с `platform.machine()`, а `cfg` — условная компиляция в духе C-препроцессора: ветка исключается из кода, а не проверяется в рантайме (`sys.platform`-ветвление проверяет условие при каждом исполнении).

### Командная строка: `command-line`

`(command-line)` — примитив, отдающий список аргументов командной строки; разбор обычно идёт по `(cdr (command-line))` — без первого элемента. Разбором аргументов занимается модуль `argparser` (гл. 15.17): позиционные и опциональные аргументы, типы `:str`/`:int`/`:float`/`:bool`, значения по умолчанию, обязательность, автогенерация `--help`.

```lisp
(let ((p (argparser :description "обучение модели")))
  (add-argument p "dataset")                          ;; позиционный
  (add-argument p "--epochs" :type :int :default 10)  ;; опция
  (let ((parsed (parse-args p (cdr (command-line)))))
    (arg-get parsed "epochs")))                       ;; значение опции
```

Результат `parse-args` — алис значений; имена хранятся без ведущих дефисов (`--epochs` → `"epochs"`), `arg-get` принимает запасное значение для отсутствующего: `(arg-get parsed "missing" 'fallback)`.
