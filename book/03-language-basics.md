# Глава 3. Основы языка

## 3.1 S-выражения: главный синтаксис

В Qualisp одна форма записи для всего — S-выражения (символьные выражения):

```lisp
(+ 1 2)            ; вызов: оператор первый, 1 + 2
(* (+ 1 2) 3)      ; вложенность вместо приоритетов: (1+2)*3
(print "hi")       ; вызов функции
```

> 🐍 **Python-аналогия.** `(+ 1 2)` — это `1 + 2`, а `(* (+ 1 2) 3)` — `(1 + 2) * 3`. Скобки заменяют и приоритеты операторов, и круглые скобки вызовов: `f(x, y)` → `(f x y)`.

Комментарии: `;` до конца строки.

## 3.2 Типы данных

Внутреннее представление — тегированный union `SExpr` (`src/core/sexpr.hpp`), теги: `NIL, CONS, SYMBOL, FIXNUM, FLONUM, STRING, FUNC, STRUCT, TENSOR, HLOPROG, PTR`. Ячейка — 32 байта.

| Тип | Пример | Python-аналог |
|---|---|---|
| Целое (fixnum, int64) | `42`, `-7` | `int` |
| Вещественное (flonum, double) | `3.14`, `1e-3` | `float` |
| Строка | `"hello"` | `str` |
| Символ | `x`, `MY-SYM` | — (ближе всего `enum`/интернированные имена) |
| Список (cons-ячейки) | `(1 2 3)`, `(1 . 2)` | `list` (односвязный) |
| nil | `nil` | `None` / `[]` |
| Истина | `t` | `True` |
| Тензор | `(tensor ((1.0) (2.0)))` | `np.ndarray` |
| Функция (callable) | `(lambda (x) (* x x))`, `+`, скомпилированная JIT-обёртка | функция |
| Структура | `(defstruct pt (x y))`, затем `(pt 1 2)` | объект `@dataclass` |
| HLO-программа | результат `(HLO-COMPILE ...)` | скомпилированная функция |
| Указатель (`ptr`) | результат `(FFI-ADDR st 'field)` | `ctypes.c_void_p` |

Функция — **один callable-атом** (тег `FUNC`): лисп-замыкание, примитив на C и его нативная компиляция — одно значение, один путь вызова. Мастер-запись атома — S-выражение (cons `(params body . env)` для лисп-функции, символ имени для C-примитива), а нативный код — выбрасываемый кэш поверх неё. `type-of` возвращает `FUNCTION` для всех трёх вкусов, печать — `#<function>` (у примитива — с именем: `#<function +>`). Подробно — гл. 19 и 20.

**Символы регистронезависимы**: ридер интернирует их через `SymbolTable::intern` (см. `src/core/symbol.cpp`); `Print`, `print`, `PRINT` — один и тот же символ (один и тот же `Symbol*`, O(1) сравнение по указателю). Поэтому все имена примитивов в коде записаны в верхнем регистре (`T+`, `MATMUL!`, `MSE!` и т.п.), но `(matmul! x w)` в пользовательском коде тоже работает. `INTERN` приводит имя к правилу читателя: `(intern "print")` — тот же символ, что `PRINT`.

Литеральные данные — через квотирование:

```lisp
'(1 2 3)          ; список-данные, не вызов
'foo              ; символ foo
`(a ,b ,@c)       ; квази-цитирование (шаблоны, гл. 12)
#'car             ; функция как значение
#(1 2 3)          ; вектор
#\A               ; символ-литера
```

> 🐍 В Python `'(1 2 3)` эквивалентен `[1, 2, 3]`, а `(1 . 2)` — паре `(1, 2)`.

## 3.3 Переменные: defvar, setq, let

```lisp
(defvar answer 42)        ; глобальная переменная
(setq answer 43)          ; изменить существующую

(let ((x 1) (y 2))        ; локальные биндинги (параллельные)
  (+ x y))                ; → 3

(let* ((x 1) (y (+ x 1))) ; последовательные биндинги
  y)                      ; → 2
```

В реализации (`src/eval/interpreter.cpp::do_setq`, `do_defvar`, `do_let`, `do_let_star`) `defvar` записывает значение в `global_env_.bindings` и при необходимости клонирует в stable-память (`root_arena_`). `setq` ищет существующий символ в текущем фрейме и обновляет in-place, либо добавляет в глобальное окружение.

> 🐍 **Python-аналогия.** `defvar` ≈ присваивание на верхнем уровне модуля; `setq` ≈ повторное присваивание; `let` ≈ локальные переменные функции — только с явной областью видимости в скобках:
> ```python
> x, y = 1, 2        # let  (параллельно)
> x = 1; y = x + 1   # let* (последовательно)
> ```

Разница `let`/`let*` — как в Python-распаковке `a, b = f(), g()` (обе вычисляются до присваивания) против трёх отдельных строк.

> ⚠️ **`setq` с несколькими парами — семантика Common Lisp.** `(setq a 1 b 2)` присваивает **все** пары слева направо, и каждая следующая пара видит биндинг предыдущей: `(setq row (cons cur row) cur nil i (+ i 1))`. Нечётное число аргументов — ошибка.

## 3.4 Функции: defun, lambda, \

```lisp
(defun add (a b) (+ a b))
(add 2 3)                        ; → 5

(defun greet (name &optional greeting)
  (strcat (if greeting greeting "Hello, ") name))
(greet "Lars")                   ; → "Hello, Lars"
(greet "Lars" "Привет, ")        ; → "Привет, Lars"
```

`&optional` — необязательные параметры со значениями по умолчанию: `(defun f (a &optional (b 10)) ...)`. Если параметр опущен — используется default:

```lisp
(funcall (lambda (a &optional (b 5)) (list a b)) 1)   ;; → (1 5)
```

`&rest` собирает **весь** хвост аргументов в список:

```lisp
(funcall (lambda (a &rest r) (list a r)) 1 2 3)       ;; → (1 (2 3))
```

Оба маркера относятся к списку параметров: `(f 1 2 3)` на `(lambda (a &rest r))` привязывает `a=1`, а `r=(2 3)` — ни один аргумент не теряется. Функции с `&rest`, `&optional` или точечным хвостом параметров компилируются JIT'ом наравне с обычными (семантика паритетна интерпретатору — гл. 20) — поведение идентично по построению.

Анонимные функции:

```lisp
(lambda (x) (* x x))     ; полное имя
(\ (x) (* x x))          ; короткая форма — читается «лямбда»
(map (\ (x) (* x x)) '(1 2 3))   ; → (1 4 9)
```

> 🐍 `(\ (x) (* x x))` — это `lambda x: x * x`.

Вызов функции-значения: `(funcall f 5)` ≈ `f(5)`. Есть также `(apply f args-list)`.

Конструктор структуры (гл. 13) — тоже обычная функция: `(defstruct pt (x y))` даёт функцию `pt`, и `(pt 1 2)` создаёт структуру. Поле читается `(slot-value p 'x)`, записывается `(set-slot p 'x 10)`.

> ⚠️ **Лишние аргументы — ошибка.** Хвост аргументов вызова без `&rest` — ошибка («too many arguments»), как и для других неверных вызовов (проектная конвенция — громкий отказ).

Рекурсия — естественный способ писать циклы, но стек не бесконечен: интерпретатор считает eval-кадры и на лимите (по умолчанию 10 000, ~3 400 Qualisp-кадров) бросает **ловимую** ошибку. Списочные примитивы stdlib (`length`, `reverse`, `member`, `last`, `butlast`, `nth`) итеративные — длинный список им не страшен. Для ML-горячих циклов используйте `while` с per-iteration scope (см. гл. 5).

```lisp
(EVAL-MAX-DEPTH)        ;; → 10000  (читает лимит)
(EVAL-MAX-DEPTH 12000)  ;; → 10000  (поднимает лимит, возвращает старый)
(try (down 200000) (e (list 'caught)))
;; → (caught) — «eval: recursion depth exceeded 10000
;;    (raise the limit with EVAL-MAX-DEPTH)»; после catch eval полностью жив
```

> ⚠️ Потолок ручного лимита при стеке 8 МБ — ~11 000 eval-кадров; выше guard просто не успевает сработать до SIGSEGV. Windows-бинарник резервирует 8 МБ стека сборкой (`-Wl,--stack=0x800000`).

**Хвостовая рекурсия без предела.** Self-хвостовой вызов не кладёт новый кадр, а пере-биндит текущий: параметры копируются в куче-соп, итерация освобождается при возврате. Поэтому глубина рекурсии не растёт вообще, и guard выше не нужен:

```lisp
(defun tc-sum (n acc) (if (= n 0) acc (tc-sum (- n 1) (+ acc n))))
(print (tc-sum 200000 0))   ;; → 20000100000 — 200 000 хвостовых вызовов
```

Условия: вызов должен быть в хвостовой позиции; при живых узлах ленты автограда TCO для итерации выключается (корректность важнее скорости); `let`/`let*` разворачиваются в хвосте до 8 уровней вложенности. Взаимные хвостовые вызовы, нативная рекурсия JIT и хвосты за `cond`/`when` — обычная рекурсия.

## 3.5 Списки

Список — односвязный список cons-ячеек, cons-ячейки берутся из `ConsCellPool` (O(1) alloc/free). Базовые операции (имена в верхнем регистре после `intern`):

```lisp
(cons 1 '(2 3))     ; → (1 2 3)      — добавить в начало
(car '(1 2 3))      ; → 1            — голова
(cdr '(1 2 3))      ; → (2 3)        — хвост
(list 1 2 3)        ; → (1 2 3)      — создать из элементов
(append '(1 2) '(3))  ; → (1 2 3)    — конкатенация
(length '(1 2 3))   ; → 3
(reverse '(1 2 3))  ; → (3 2 1)
(nth 1 '(a b c))    ; → b            — элемент по индексу
(member 2 '(1 2 3)) ; → (2 3)        — поиск (возвращает хвост с позиции)
(null '())          ; → t
(atom 5)            ; → t            — атом?
```

Комбинации `cadr`, `caddr`, `cddr` и т.д. — сокращения `(car (cdr x))`, как `x[1]`, `x[2]`, `x[2:]` в Python. Все 16 комбинаций до 4 уровней определены в `stdlib/core.qlsp`: `caar`, `cadr`, `cdar`, `cddr`, `caaar`, `caadr`, `cadar`, `caddr`, `cdaar`, `cdadr`, `cddar`, `cdddr`, `second`, `third`, `fourth`, `first`, `rest`.

Функции высшего порядка (примитивы C++):

```lisp
(map (\ (x) (* 2 x)) '(1 2 3))          ; → (2 4 6)
(filter (\ (x) (> x 1)) '(1 2 3))       ; → (2 3)
(reduce + '(1 2 3 4))                   ; → 10
(zip-with + '(1 2) '(10 20))            ; → (11 22)
```

> 🐍 **Python-аналогия.**
> ```python
> [2*x for x in xs]        # map
> [x for x in xs if x > 1] # filter
> functools.reduce(op.add, xs)  # reduce
> [a + b for a, b in zip(xs, ys)]  # zip-with
> ```

Важно: списки в Qualisp иммутабельны по смыслу использования — операции создают новые списки в scratch-памяти (гл. 5), нет `lst.append()`.

## 3.6 Управление потоком

```lisp
(if (> x 0) "pos" "neg")         ; if: (if условие then else)

(cond                            ; cond = цепочка elif
    ((< x 0) "neg")
    ((= x 0) "zero")
    (t "pos"))

(progn                           ; последовательность, значение последней
    (print "шаг 1")
    (print "шаг 2")
    (* 2 2))

(while (< i 10)                  ; цикл while (с per-iteration scope, гл. 5)
    (setq i (+ i 1)))

(and a b c)                      ; короткое замыкание
(or a b c)
```

> 🐍 `(if c a b)` — тернарник `a if c else b`. `(cond ...)` — `if/elif/else`. `(progn ...)` — тело функции. `and`/`or` — одноимённые операторы Python.

> ⚠️ **Строгий `if`.** Форма принимает ровно 2–3 аргумента: `(if test then [else])`. Четвёртая форма — ошибка программы: «if: too many forms (use cond or progn for branches)». JIT-компилятор зеркалит проверку: такое тело уходит в интерпретатор, где ошибка и бросается.

Любое значение кроме `nil` истинно. `nil` — одновременно «пустой список» и «ложь». `(null x)` — предикат для пустого.

## 3.7 Сравнения и равенство

```lisp
(= 1 1)      (= 1.0 1.0)   ; числовое равенство (примитив =)
(string= "a" "a")          ; строки (примитив STRING=)
(equal x y)                ; структурное равенство (cons, строки, символы)
(eq x y)                   ; идентичность (Symbol* один и тот же)
(< <= > >=)                ; числа
```

Контракт `EQUAL`: для cons-списков, строк и символов сравнение **структурное** (рекурсивно по car/cdr); для значений с идентичностью — замыканий, HLO/JIT-программ, **структур и тензоров** — по адресу. Ключевое свойство — рефлексивность: `(equal x x)` истинно для **любого** живого значения. Сравнение тензоров по значению — дело тензорных примитивов, не `equal`:

```lisp
(defvar a (tensor ((1.0 2.0))))
(equal a a)                ;; → t   — один и тот же буфер (идентичность)
(equal a (tensor ((1.0 2.0))))  ;; → nil — другой буфер
```

Структуры (гл. 13) сравниваются так же — **по идентичности**: `(equal p p)` → `t`, а две одинаковые по полям структуры дают `nil`. Это честно для мутабельного объекта: поля пишутся через `set-slot`, и равенство живёт по адресу, как `a is b` в Python.

> 🐍 `(equal a b)` — это `a == b` для списков, строк и символов и `a is b` для мутабельных объектов (структуры, тензоры): объекты с буферами сравниваются по идентичности, как Python-объекты без `__eq__`.

**Числа сравниваются по значению, а не по представлению.** `(= 0 0.0)` → `t`: fixnum и flonum сравниваются численно, как в Python. Это важно для production-обучения: целочисленный argmax-пред должен совпадать с float-метками из CSV-тензоров. Все прочие расхождения тегов по-прежнему дают `nil`: `(= 42 "42")` → `nil`.

## 3.9 Строки

```lisp
(strcat "Hello, " "World")        ; → "Hello, World"  (f"{a}{b}")
(strcat "n=" 5)                   ; → "n=5"           — не-строка печатается как WRITE-TO-STRING
(substr "hello" 1 3)              ; → "ell"           (s[1:4])
(number-to-string 42)             ; → "42"            (str(42))
(string= "a" "a")                 ; → t
```

> ⚠️ **`strcat` превращает каждый аргумент в текст.** Не-строка печатается тем же принтером, что `WRITE-TO-STRING`: `(strcat "n=" 5)` → `"n=5"`, `(strcat nil)` → `"nil"`. На этом же стоит сводка `run-tests` (`(strcat (type-of *test-passed*) "/" ... " passed")`) — счётчик печатается, а не исчезает.

## 3.10 Печать

```lisp
(print "loss: 5")                     ; один строковый аргумент
(print (strcat "epoch " (to-string 5) ", loss " (to-string 0.25)))
;; → epoch 5, loss 0.25 — составные сообщения собираются через strcat
(display x)                    ; без кавычек/префиксов (raw)
```

`print` и `display` — это разные примитивы (`prim_print` и `prim_display`); print добавляет оформление (префиксы, кавычки для строк), display — голый вывод.

> ⚠️ **Ровно один аргумент.** `print` и `display` принимают **строго один аргумент** — лишний это ошибка арности («print: takes exactly one argument»). Чтобы напечатать несколько значений, соберите их сами: `(print (list "epoch" 5))` или склейте через `strcat`.

## 3.11 Собираем вместе: FizzBuzz

```lisp
(defun fizzbuzz (n)
  (cond
    ((= (mod n 15) 0) "FizzBuzz")
    ((= (mod n 3) 0)  "Fizz")
    ((= (mod n 5) 0)  "Buzz")
    (t (number-to-string n))))

(map fizzbuzz (range 16))
;; → (1 2 Fizz 4 Buzz Fizz 7 8 Fizz Buzz 11 Fizz 13 14 FizzBuzz)
```

> 🐍 Тот же код на Python:
> ```python
> def fizzbuzz(n):
>     if n % 15 == 0: return "FizzBuzz"
>     elif n % 3 == 0: return "Fizz"
>     elif n % 5 == 0: return "Buzz"
>     else: return str(n)
>
> [fizzbuzz(i) for i in range(1, 16)]
> ```

## 3.12 Тесты прямо в языке

В `stdlib/core.qlsp` встроен мини-фреймворк тестов:

```lisp
(deftest "fizzbuzz-15"
  (assert-eq (fizzbuzz 15) "FizzBuzz" "15 должно быть FizzBuzz"))

(deftest "длина-списка"
  (assert-eq (length '(1 2 3)) 3 "длина"))

(run-tests)
```

`deftest` ≈ `def test_...()` в pytest, `run-tests` ≈ `pytest`. Также в `core` есть `assert-zero` для проверки тензоров (что сумма квадратов градиента ≈ 0) — стандартный приём в тестах градиентов. Имена тестов склеиваются через `strcat` с префиксом `"test::"`, чтобы не было коллизий с пользовательскими символами.

## 3.13 Гомоиконность: код как данные

Qualisp — гомоиконный язык: программа и данные имеют одинаковую структуру (S-выражения). В рантайме доступны примитивы для прямой работы с этой эквивалентностью: можно парсить строки в код, сериализовать код обратно, исполнять построенные программы, инспектировать замыкания.

Эта эквивалентность закреплена как **инвариант одной формы**: S-выражение — единственная авторитетная форма программы. Всё, что нативно (JIT-страницы замыканий, HLO-кёрнелы), — выбрасываемый кэш, выведенный из S-выражений и пересобираемый на лету; ничего не хранится «поверх» S-выражений, и вся гомоиконная механика ниже работает поверх скомпилированного кода без ограничений. Подробности — гл. 20 (JIT) и гл. 21 (образы).

### READ-FROM-STRING / WRITE-TO-STRING

```lisp
(read-from-string "(+ 1 2)")     ; → (+ 1 2)   (S-выражение)
(write-to-string '(+ 1 2))       ; → "(+ 1 2)" (строка)
```

> 🐍 Аналог `ast.literal_eval("(1 + 2)")` и `ast.unparse(...)` в Python — но здесь выражения нативные для языка, а не отдельное AST-дерево.

### EVAL — вычисление в рантайме

```lisp
(eval '(+ 1 2))                              ; → 3
(eval (read-from-string "(* 6 7)"))          ; → 42
(setq expr '(lambda (x) (* x x)))
(eval expr 5)                                ; → 25
```

> 🐍 Аналог `eval("1 + 2")` в Python. В Qualisp `eval` работает с самими S-выражениями, без строкового прохода.

### FUNCTIONP / FUNCTION-PARAMS / FUNCTION-BODY / FUNCTION-ENV

```lisp
(defun square (x) (* x x))

(functionp 'square)          ; → T  (это замыкание)
(function-params 'square)    ; → (X)        (список параметров)
(function-body 'square)      ; → ((* X X))  (тело как S-выражение)
(function-env 'square)       ; → nil для defun (глобальный env)
```

`FUNCTION-BODY` возвращает код лямбды как данные — основы для метапрограммирования (генерация кода, lint, автодокументация). В Python аналог — `inspect.getsource`, но здесь возвращается **структурное** представление, а не исходный текст.

### SYMBOL-NAME

```lisp
(symbol-name 'hello)         ; → "HELLO"  (после intern — uppercase)
(symbol-name '|+ 1 2|)       ; → "+"  (внутри bars — verbatim)
```

> 🐍 Аналог `str(identifier)` для имён, не для значений. В Python такого нет — имена и значения разнесены.

### BOUNDP

```lisp
(boundp 'undefined-var)      ; → nil  (не определена)
(defvar x 42)
(boundp 'x)                  ; → T
```

Полезно в макросах и meta-circular interpreter'ах: «определена ли переменная?» без чтения значения.

### SET-READER-MACRO

```lisp
(set-reader-macro 'p (lambda (stream) '(print "hi")))
'p  ; в REPL автоматически напечатает "hi"
```

Подробнее — в гл. 12.

### RANDINT

```lisp
(randint 10)                 ; → 0..9
(randint 5 10)               ; → 5..9
```

> 🐍 Аналог `random.randint(a, b)`. Существующий `(rand)` в stdlib — для [0,1] float, `(randn)` — гауссово.

### IMPORT-FROM

Частичный импорт вместо `import`:

```lisp
(import-from (dl linear train-step train-epochs))
;; поднимает только LINEAR, TRAIN-STEP, TRAIN-EPOCHS
;; остальное содержимое dl (net-forward, layer-w, ...) остаётся недоступным
```

> 🐍 Аналог `from sklearn.ensemble import RandomForestClassifier` в Python — но без скрытого `import sklearn` (модуль целиком не загружается как имя в глобальный env).

## 3.14 Что увидел интерпретатор

Когда вы набираете `(+ 1 2)` в REPL:

1. **`Reader`** (`src/reader/readtable.cpp`) разбивает вход на токены, строит cons-дерево в scratch-scope.
2. **`Interpreter::eval`** (`src/eval/interpreter.cpp:235`) проверяет тип выражения:
   - атом (`nil`, число, строка, символ, тензор, замыкание, примитив, структура, HLOPROG) → возврат самого значения;
   - cons → специальная форма или вызов функции.
3. **`eval_cons`** (`eval_cons`) различает special forms (`if`, `let`, `defun`, `defmacro`, `match`, `defrule`, …) и обычные вызовы.
4. Для обычного вызова аргументы вычисляются через `eval_list` в том же scratch-scope; затем `apply` ищет примитив/замыкание.
5. Примитив (`src/eval/interpreter.cpp::register_primitives`) исполняется на C++; замыкание — создаётся новый `EnvFrame` и выполняется тело (`Interpreter::apply`).

В hot path вызовы тензорных операций `T+`, `T*`, `MATMUL` идут через AVX2/FMA OpenBLAS — без аллокаций cons-ячеек (тензор живёт в TensorBufferPool, гл. 5).

## 3.15 Тензорные примитивы: арность и доступ к элементам

Здесь — только контракты вызова; устройство тензоров разобрано в гл. 6.

Тензорные операции — обычные примитивы, и к ним предъявляется тот же контракт, что к любой функции: арность и типы аргументов проверяются, а не роняют процесс. `T+`, `T-`, `T*`, `MATMUL`, `CONV2D`, `MAXPOOL2D` (и их autograd-варианты), `BATCHNORM!`, `LAYERNORM!` при неверном вызове дают внятную ошибку — с указанием, что именно не так: не хватает аргумента, аргумент не целый, индекс отрицательный, ожидался тензор, а пришло число. Ошибка — структура (гл. 15), её текст читается `error-message`; `catch-error` дополнительно печатает цепочку ошибки. Например:

```lisp
(error-message (catch-error (lambda () (tref (randn (list 4)) 4))))
;; → "tref: index 4 out of range for 4 elements"
(error-message (catch-error (lambda () (conv2d (tensor ((1.0 2.0) (3.0 4.0))) 1 1 1))))
;; → "expected tensor" — ядро свёртки должно быть тензором
```

### Доступ к элементу: `tref` и `tensor-item`

```lisp
(tref (tensor ((1.0 2.0))) 0)              ;; → 1.0  — один индекс: плоский номер элемента
(tref (tensor ((1.0 2.0)) (3.0 4.0)) 1 1)   ;; → 4.0  — N индексов: координаты ровно по рангу
(tensor-item (tensor ((1.0 2.0))) 1)        ;; → 2.0  — элемент по индексу
```

Контракт `tref`:

- **один индекс** — плоский номер элемента (как `NTH`, и как весь код проекта читает `(tref m 0)` на матрице);
- **N индексов** — координаты ровно по рангу тензора: два индекса на матрице, три на тензоре ранга 3; число индексов, отличное от ранга (кроме одного), — ошибка;
- **границы проверяются**: индекс вне диапазона — ошибка, а не значение из чужой памяти.

```lisp
(try (tref (randn (list 4)) 4) (e t))   ;; ошибка: e — структура, t вместо значения
(error-message (try (tref (randn (list 4)) 4) (e e)))  ;; → "tref: index 4 out of range for 4 elements"
```

`TENSOR-ITEM` принимает индекс вторым аргументом и читает **элемент по этому индексу**: выход за границу и отрицательный индекс — ошибка. Плоский список всего тензора даёт `TENSOR->LIST`.

> 🐍 `(tref t i j)` — это `t[i, j]`, а `(tref t i)` — `t.reshape(-1)[i]`; `(tensor-item t i)` — то же самое для плоского случая.

### Конечность значений

Release-сборка использует `-ffast-math`, поэтому сравнение плавающих в release ненадёжно (для NaN оно истинно). Конечность проверяется отдельным битовым примитивом:

```lisp
(FINITE? t)   ;; → t, если в тензоре нет NaN/Inf
```

Это единственный надёжный способ проверить NaN/Inf — и в тестах, и в обучающих циклах (подробно — гл. 6 и 7).
