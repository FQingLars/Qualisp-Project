# Глава 3. Основы языка

## 3.1 S-выражения: главный синтаксис

В Qualisp одна форма записи для всего — S-выражения (символьные выражения):

```lisp
(+ 1 2)            ; вызов: оператор первый, 1 + 2
(* (+ 1 2) 3)      ; вложенность вместо приоритетов: (1+2)*3
(print "hi")       ; вызов функции
```

> 🐍 **Python-аналогия.** `(+ 1 2)` — это `1 + 2`, а `(* (+ 1 2) 3)` — `(1 + 2) * 3`. Скобки заменяют и приоритеты операторов, и круглые скобки вызова: `f(x, y)` → `(f x y)`.

Reader разбирает пробелы, табы и переводы строк; `;` начинает комментарий до конца строки. Списки пишутся `( … )`, точечные пары — `(a . b)`; числа — int64 (`42`, `-7`) и f64 (`3.14`, `1e-5`); строки — `"…"` с escape-последовательностями `\n`, `\t`, `\r`, `\\`, `\"`. Символы интернируются без учёта регистра и печатаются в верхнем регистре; `:name` — keyword, самовычисляемая константа. Char-литералы: `#\a`, `#\space`, `#\newline`, `#\tab`.

`0xFF` и `1/2` числами не являются: reader их не разбирает, а checker сообщает `unbound variable 0XFF`. Незакрытая строка даёт `error at 1:1: unterminated string`; незакрытая скобка в REPL продолжает ввод (`... `).

Сахар reader'а:

| Запись | Разворачивается в | Смысл |
|---|---|---|
| `'x` | `(quote x)` | данные без вычисления |
| `` `x `` | `(quasiquote x)` | шаблон |
| `,x` | `(unquote x)` | подстановка в шаблоне |
| `,@x` | `(unquote-splicing x)` | вставка списка в шаблоне |
| `\` | `lambda` | синоним лямбды: `(\ (x) …)` ≡ `(lambda (x) …)` |

Векторов `#(...)`, `#'` и блочных комментариев `#| |#` в языке нет. Reader не типизирует и не исполняет форму: его работа — получить S-выражение со спаном (файл/строка/колонка), которое дальше пойдёт через expander, checker и эмиттер.

## 3.2 Типы данных

Внутреннее представление значения — тегированный union `Value`: `nil`, `t`, `int`, `float`, `char`, `symbol`, `string`, `cons`, `func`, `tensor`, `future`, `structure`, `result`, `ptr`. Cons-ячейки неизменяемы; строка — атом с rope-носителем; вектор `#(...)` в язык не входит.

| Тип | Пример | Python-аналог |
|---|---|---|
| Fixnum (int64, wrap) | `42`, `-7` | `int` |
| Flonum (f64) | `3.14`, `1e-3` | `float` |
| Bool | `t`, `nil` | `True` / `False` |
| Строка | `"hello"` | `str` |
| Символ | `x`, `MY-SYM` | интернированное имя (`enum`) |
| Keyword | `:linux`, `:f32` | самовычисляемая константа |
| Список (cons) | `(1 2 3)`, `(1 . 2)` | `list` |
| nil | `nil` | `None` / `[]` |
| Char | `#\a`, `#\space` | символ из `str` |
| Тензор | `(tensor ((1.0) (2.0)))` | `np.ndarray` |
| Функция | `(lambda ((x . :fixnum)) x)`, `+` | callable |
| Структура | `(defstruct pt ((x . :fixnum)))` → `(pt 1)` | `@dataclass` |
| Result | `#<result>` из `catch-error` | `Result`-обёртка |
| `:syntax` | `'(+ 1 2)` | дерево S-выражения как данные |

`type-of` печатает `INT`, `FLOAT`, `STRING`, `SYMBOL`, `NIL`, `BOOL`, `LIST`, `TENSOR`, `RESULT`, `STRUCT`; символы — в верхнем регистре.

**Типизация статическая.** Имена типов пишутся с двоеточием: `:fixnum`, `:flonum`, `:bool`, `:string`, `:symbol`, `:nil`, `:char`, `:syntax`. Составные типы: `(:list T)` (непустой список), `(:option T)` (значение или `nil`), `(:func (PARAMS...) R)`, `(:tensor :f32 (2 2))` с dtype `:f16/:f32/:f64/:u8/:i64`, `(:struct Name)`, `(:result T)`, переменные типов `:a`, `:b`. `:i64` — dtype тензора для точных целочисленных данных, отдельного скалярного `:i64` нет. Общий `:any` запрещён; исключение — ранговый wildcard `(:tensor DTYPE :any)`. Повторный `defun` с тем же набором типов/арности — ошибка, но новый набор добавляет статическую перегрузку (§3.4).

`nil` — одновременно ложь, «отсутствие значения» и пустой список; других ложных значений нет. `if` принимает **только** `:bool`: `(if lst …)` — ошибка, правильно `(if (null lst) …)`.

**Символы регистронезависимы.** `Print`, `print`, `PRINT` — один и тот же интернированный символ; `(quote a)` печатается `A`. Keyword `:name` самовычисляем и не требует кавычек: `(equal :linux :linux)` → `t`.

Литеральные данные — через квотирование:

```lisp
'(1 2 3)          ; список-данные, не вызов
'foo              ; символ
`(a ,b ,@c)       ; квази-цитирование: шаблон с подстановками
#\A               ; char
```

> 🐍 В Python `'(1 2 3)` близок к `[1, 2, 3]`, а `(1 . 2)` — к паре `(1, 2)`. Квотирование — не «строчка кода», а те же S-выражения в роли данных.

## 3.3 Переменные: defvar, setq, let

```lisp
(defvar y (20 . :fixnum)) ; глобальная переменная, тип обязателен
(setq y 21)               ; изменить существующую, тот же тип

(let ((a 1) (b 2))        ; локальные биндинги, параллельные
  (+ a b))                ; → 3
```

`defvar` требует типизированное значение: `(defvar y 20)` и `(defvar y 20 :fixnum)` дают `error at 1:1: defvar expects a name, a typed value and nothing else`. Рабочая форма — `(name (value . :type))`: тип в cdr пары, саму пару reader читает как данные, поэтому она не принимается за вызов. Тип `defvar` фиксируется, `setq` принимает только значение этого же типа и только для существующего биндинга: `(setq z 5)` → `setq of unbound variable Z`. `defvar` копирует значение в stable-память (`(defvar b (a . :fixnum))` — копия, не алиас), `setq` перемещает значение в биндинг; `clear` отвязывает имя. В REPL `defvar` печатает имя символа — `Y`.

`let` биндит в текущем scope и создаёт **параллельные** связи: все правые части считаются до связывания. `let*` в языке отсутствует (`unknown function LET*`); последовательные зависимости записываются вложенными `let`:

```lisp
(let ((a 1))
  (let ((b (+ a 1)))
    b))                   ; → 2
```

> 🐍 **Python-аналогия.** `defvar` ≈ объявление глобальной переменной с аннотацией (`y: int = 20`), `setq` ≈ повторное присваивание, `let` ≈ `a, b = 1, 2` (параллельно). ⚠️ Синтаксис `(defvar b (a . :fixnum))` — не псевдоним, а копия: изменения `a` на `b` не отражаются.

## 3.4 Функции: defun, lambda, \

```lisp
(defun sq ((x . :fixnum)) ((* x x) . :fixnum))
(sq 7)                   ; → 49

(defun add ((a . :fixnum) (b . :fixnum)) ((+ a b) . :fixnum))
(add 2 3)                ; → 5
```

Типы параметров и возвращаемого значения на верхнем уровне обязательны. Аннотация — это dotted pair: `(param . :type)` для параметра и `(expr . :type)` для результата, где `expr` — само выражение результата, последняя форма тела. Cdr пары — тип, поэтому reader читает аннотацию как данные, а не как вызов. Простой тип — keyword (`:fixnum`), составной — keyword-возглавляемый список (`(:list T)`, `(:tensor :f32 (4))`). Каноническая форма:

```lisp
(defun name ((p1 . :type1) (p2 . :type2) &optional (p3 . :type3) &rest (p4 . :type4))
  body...
  (expr . :return))
```

Позиционная запись `(x :fixnum)` не принимается: `(defun sq (x :fixnum) :fixnum (* x x))` даёт `error at 1:1: defun expects parameters, a result and a body`. Все сигнатуры литеральных top-level `defun` публикуются до проверки первой формы, поэтому прямая ссылка вперёд и взаимная рекурсия типизируются; вызов до определения — runtime-ошибка `undefined function`.

### Статические перегрузки

`defun` с новым набором типов параметров и/или другой арностью добавляет вариант функции, а не переопределяет её:

```lisp
(defun show ((x . :fixnum)) ((number-to-string x) . :string))
(defun show ((x . :flonum)) ((number-to-string x) . :string))
(defun show ((x . :string) (n . :fixnum)) ((substr x 0 n) . :string))

(show 7)          ; выбирается fixnum-вариант
(show 7.5)        ; выбирается flonum-вариант
(show "hello" 2)  ; выбирается строковый вариант
```

Ключ сигнатуры — `(имя, арность, типы параметров)`; тип результата в ключ не входит. Повторение того же набора — ошибка компиляции. Вызов разрешается checker'ом статически: точное совпадение побеждает расширение `:fixnum → :flonum`; если подходят несколько равных кандидатов — диагностика `ambiguous overload`, если ни один — `no overload matches the arguments`. Динамического диспетча по типам значений нет. Имя с одной сигнатурой можно использовать как значение функции; для имени с несколькими сигнатурами нужна явная аннотация. `clear` удаляет публичное имя и все его варианты.

`&optional` и `&rest` остаются маркерами, тип — внутри пары; значений по умолчанию нет:

```lisp
(defun g ((x . :fixnum) &optional (y . :fixnum))
  ((if (null y) x x) . :fixnum))
(g 1)                    ; → 1
(g 1 9)                  ; → 1

(defun rst ((a . :fixnum) &rest (xs . :fixnum)) (a . :fixnum))
(rst 1 2 3)              ; → 1
```

Внутри тела `&optional`-параметр имеет тип `(:option T)`, `&rest` — `(:list T)`. Форма `(p :type default)` не поддерживается; пропущенный аргумент — `nil`, и его надо проверять через `null` перед арифметикой.

Анонимные функции и `\` — синоним `lambda`:

```lisp
(funcall (lambda ((x . :fixnum)) (+ x 1)) 9)   ; → 10
(funcall (\ ((x . :fixnum)) (* x x)) 4)        ; → 16
```

У `lambda` параметры тоже парные, но результат выводится — отдельной аннотации результата нет: `(lambda ((x . :fixnum)) (+ x 1))`.

> ⚠️ **Лямбда-литерал не вызывается напрямую.** `((lambda ((x . :fixnum)) (+ x 1)) 5)` даёт `error: Unsupported`. Значение-функцию вызывают через `funcall` или `apply`; для функции-значения в позиции аргумента нужен объявленный тип, например `(defvar f ((lambda ((x . :fixnum)) (+ x 1)) . (:func (:fixnum) :fixnum)))`.

```lisp
(funcall f 9)                                  ; → 10
(apply (lambda ((a . :fixnum) (b . :fixnum)) (+ a b)) (list 2 3))  ; → 5
```

`apply` ждёт настоящий список: `(apply f '(2 3))` даёт `apply expects a list`, потому что квотированная форма — `:syntax`-данные. Список собирают через `list`/`cons`.

Рекурсия — естественный способ писать циклы. Хвостовой самовызов и взаимные хвостовые вызовы исполняются в постоянном числе кадров:

```lisp
(defun tc-sum ((n . :fixnum) (acc . :fixnum))
  ((if (= n 0) acc (tc-sum (- n 1) (+ acc n))) . :fixnum))
(print (tc-sum 200000 0))    ; → 20000100000
```

Не-хвостовая рекурсия упирается в bump-арену кадров: исчерпание — типизированная ошибка `call depth limit exceeded` с позицией; машинный стек расширен до 256 МБ, чтобы ошибка не превращалась в падение.

> ⚠️ **`defmacro` — исключение.** У макросов параметры и возвращаемое состояние по-прежнему позиционные: `(defmacro name (p :syntax) :syntax …)`, где параметры — символы с состоянием `:atom`/`:syntax` (гл. 12).

> 🐍 **Python-аналогия.** `(defun sq ((x . :fixnum)) ((* x x) . :fixnum))` — это `def sq(x: int) -> int: …`; `funcall f 9` — `f(9)`. У `lambda` в Qualisp нет сокращённого синтаксиса вызова: `(\ ((x . :fixnum)) …)` — просто другое написание `lambda`.

## 3.5 Списки

Список — односвязная цепочка cons-ячеек; `nil` — пустой список. Примитивы:

```lisp
(cons 1 '(2 3))       ; → (1 2 3)   — добавить в начало
(car '(1 2 3))        ; → 1         — голова
(cdr '(1 2 3))        ; → (2 3)     — хвост
(list 1 2 3)          ; → (1 2 3)
(append '(1 2) '(3))  ; → (1 2 3)
(length '(1 2 3))     ; → 3
(reverse '(1 2 3))    ; → (3 2 1)
(nth '(a b c) 1)      ; → B         — сначала список, потом индекс
(null nil)            ; → t
(null '(1))           ; → nil
```

`car`/`cdr` принимают `(:option (:list T))` и возвращают `(:option T)` / `(:option (:list T))`: пустой список — нормальный случай, а не исключение. `(car 5)` даёт `car expects a list`. Комбинаций `cadr`, `caddr`, `member`, `last` как примитивов нет; из `core` доступен, например, `caar`.

Функции высшего порядка — примитивы с типизированными лямбдами:

```lisp
(map (lambda ((x . :fixnum)) (* x x)) (list 1 2 3))           ; → (1 4 9)
(filter (lambda ((x . :fixnum)) (> x 1)) (list 1 2 3))        ; → (2 3)
(reduce (lambda ((a . :fixnum) (b . :fixnum)) (+ a b)) (list 1 2 3) 0)  ; → 6
```

> ⚠️ **Порядок аргументов `reduce`.** Функция вызывается как `(fn элемент аккумулятор)`, начальное значение — последний аргумент. В модуле `collections` есть `range`, `find`, `position`, `take-while`, `drop-while`, `zip-with`, `sum`, `keep-positive`, `any`, `all`, `count-if`, `unique` — их подключают через `(import collections)`.

> 🐍 **Python-аналогия.**
> ```python
> [2*x for x in xs]                  # map
> [x for x in xs if x > 1]           # filter
> functools.reduce(op.add, xs, 0)    # reduce
> ```

Списки создаются новыми операциями: мутаций cons-ячеек (`setcar`/`setcdr`) нет, `append` возвращает новый список, а ячейки живут в scope-пуле.

## 3.6 Управление потоком

```lisp
(if (> x 0) 1 2)          ; if: (if условие then else)
(cond ((= x 0) 0) (t 1))  ; cond = цепочка if/elif
(progn (print "a") (print "b") 3)   ; последовательность, значение последней
(while (< i 3)            ; цикл; каждая итерация — отдельный scope
  (setq i (+ i 1)))
(and t t)                 ; → t
(or nil nil)              ; → nil
```

`if` принимает 2 или 3 аргумента; условие обязано быть `:bool`. `(if 0 1 2)` даёт `condition must be :bool` — ноль истиной не считается; вместо `(if lst …)` пишите `(if (null lst) 1 2)`: `null` возвращает `:bool`. `cond` возвращает значение первой подходящей ветки или `nil`. `while` создаёт scope на итерацию; `progn` — нет.

> 🐍 `(if c a b)` — тернарник `a if c else b`; `(cond ...)` — `if/elif/else`; `(progn ...)` — тело функции; `and`/`or` — одноимённые операторы Python.

### `and` / `or` — короткое замыкание, булевы формы

`and` и `or` — формы с коротким замыканием, обе возвращают `:bool` (`t` или `nil`), а не значение операнда: `(and t t)` → `t`, `(and t nil)` → `nil`, `(and)` → `t`, `(or)` → `nil`. Хвост вычисляется только при нужде. Например, `(or nil 3)` — ошибка `condition must be :bool`: операнды обязаны быть булевыми.

> ⚠️ Это отличается от Common Lisp и Python: `1 and 2` в Python даёт `2`, а `(and 1 2)` в Qualisp — отказ checker'а, потому что `1` не `:bool`. `xor` отсутствует.

### `and` / `or` в типизированном коде

Поскольку `and`/`or` — булевы, их результат можно сразу подавать в `if`, `cond` и предикаты: `(if (and (null xs) flag) 1 2)`. Значения-операнды должны сами быть `:bool`; если нужно проверить «пусто или нет», используйте `(null x)`, который возвращает `:bool`.

## 3.7 Сравнения и равенство

```lisp
(= 1 1)          (= 1.0 1.0)   ; числовое равенство
(< 1 2)  (> 1 2)  (<= 2 2)  (>= 2 3)
(equal "a" "a")               ; t
(equal '(1 2) '(1 2))         ; t — структурно
(eq 'a 'a)                    ; t — один интернированный символ
(string= "a" "a")             ; t
(not nil)                     ; t
(null nil)                    ; t
```

`=` сравнивает числа по значению (`(= 0 0.0)` → `t`), `string=` — строки по содержимому, `equal` — числа по значению, строки и cons по содержимому, символы по id; структуры, тензоры и функции — по идентичности: `(equal (pt 1 2) (pt 1 2))` → `nil`. `eq` — идентичность: для символов это сравнение интернированных id, для кучевых значений — указателя. Отдельного примитива `EQ` с другой семантикой нет.

> 🐍 `(equal a b)` — это `a == b` для чисел, строк и списков и `a is b` для тензоров и функций: объекты с буферами не склеиваются по содержимому.

## 3.8 Арифметика и математика

```lisp
(+ 1 2 3)      ; → 6
(+ 1 2 3 4)    ; → 10   — n-арная сумма
(*)            ; → 1
(* 2 3 4)      ; → 24   — n-арное произведение
(- 10 3)       ; → 7
(- 10 3 2)     ; → 5    — n-арная разность
(- 5)          ; → -5   — унарный минус
(+)            ; → 0
(/ 7 2)        ; → 3.5   — деление целых даёт float
(/ 7.0 2)      ; → 3.5
(mod 7 3)      ; → 1
(sqrt 9)       ; → 3.0
(exp 1.0) (log 2.0) (sin 0.0) (cos 0.0) (atan 1.0)
```

`+`, `*`, `-` — n-арные; `(+)` → `0`, `(*)` → `1`, а `(-)` без аргументов — `arithmetic expects arguments`. `abs` — примитив: для числа возвращает число, для тензора — поэлементный `abs` с backward-ядром `sign`; `min`, `max`, `expt` как функции по-прежнему отсутствуют (`unknown function MIN/MAX/EXPT`), есть `pow`: `(pow 2 10)` → `1024.0`. `sqrt`, `exp`, `log`, `sin`, `cos`, `atan` работают с `:flonum`; `sin`/`cos`/`sqrt`/`atan` имеют forward- и backward-ядра автограда, в том числе в HLO-графе (гл. 7). Смешанная арифметика fixnum/flonum даёт flonum. Для тензоров `abs` входит и в eager-путь, и в `defgraph`.

> ⚠️ **`^` — не функция языка, а синтаксис символьных термов.** `(^ 2)` даёт `unknown function ^`; запись используется внутри `symbolic`/`neuro`: `(term->code '(^ (+ x 1) 3) '(x))` → `(LET ((POW-0 (+ X 1))) (* POW-0 POW-0 POW-0))` — составное основание связывается один раз через `let` (гл. 14).

### `+ - * /` диспетчеризуются по типу операндов

| Тип аргументов | `(+ a b)` | `(- a b)` | `(* a b)` | `(/ a b)` |
|---|---|---|---|---|
| числа | арифметика | арифметика | арифметика | float-деление |
| тензоры | поэлементно | поэлементно | поэлементно (Адамар) | поэлементно |

Операции над тензорами требуют совпадения dtype и поддерживают broadcast: скаляр применяется ко всем элементам. Матричное умножение — отдельная форма `matmul`: ранг ≥2, ведущие оси должны совпадать, две последние перемножаются (batched matmul); broadcast по batch-осям не делается. `reshape`, `transpose`, `t-slice` копируют, `tref` читает элемент, `tset!` пишет его.

```lisp
(print (tensor (1.0 2.0)))               ; #<tensor>
(print (type-of (tensor (1.0 2.0))))     ; TENSOR
(print (+ (tensor (1.0 2.0)) (tensor (3.0 4.0))))  ; #<tensor>
(print (matmul (tensor ((1.0 2.0) (3.0 4.0)))
               (tensor ((1.0 0.0) (0.0 1.0)))))   ; #<tensor>
```

> ⚠️ `*` на тензорах — не матричное произведение: `(* a a)` на `[[1,2],[3,4]]` даёт `[[1,4],[9,16]]`, а `(matmul a a)` — `[[7,10],[15,22]]`.

### Автоград: `param`, `grad!`, `grad-of`

Обучаемый тензор помечается через `param`; отдельного «включить автоград» вызова нет. Градиент считает `grad!` по последнему запуску графа в текущей top-level форме, читается он через `grad-of`:

```lisp
(defvar c ((param (tensor (0.5))) . (:tensor :f32 (1))))
(defgraph sq-sum ((c . (:tensor :f32 (1)))) ((tsum (* c (* c c))) . :flonum))
(grad! (sq-sum c))
(print (tref (grad-of c) 0))    ; градиент параметра той же формы/dtype
```

Суффиксных `!`-операций (`T+!`, `MATMUL!`, `MSE!`) в языке нет: шаг обучения — это `grad!` плюс явное обновление веса через `tset!`. Градиенты накапливаются в stable-памяти параметра; ещё не считанный параметр даёт нули той же формы/dtype.

> 🐍 Ближайший аналог — `requires_grad` и `loss.backward()` в PyTorch, только граф собирается из `defgraph`, а не из невидимых узлов autograd.

### Под HLO-трассой

`defgraph` исполняет тело один раз в режиме трассировки на placeholder-тензорах и компилирует граф. Тело статично: `tref`/`tset!`, вложенные `defgraph`, рекурсия и data-dependent control flow не поддерживаются; `t-copy!` и `rand-like` в трассировке запрещены. Параметры — парные аннотации `(имя . :тип)`, результат — последняя форма тела `(expr . :ret)`; только тензоры с конкретной формой, ранг `:any` здесь отвергается. Константы тела (`tensor`, `zeros`, `ones`, `randn`) сохраняются в stable.

В граф входят elementwise-операции, batched `matmul`, `reshape`, `transpose` с перестановкой, полные и осевые reduction'ы, `softmax`/`log-softmax` по последней оси, `abs`, `t-slice`, `t-concat`, `conv2d`/pooling, а также дискретные `argmax`/`one-hot`/`gather`/`scatter-add`/`gt`/`lt`. Параметры операций (перестановка, `[axis, keep]`, stride/pad/dilation/groups) хранятся в `attrs` узла. Reduction'ы в графе работают только с float dtype, `defgraph` с `:fixnum`-результатом недостижим; `:i64`-тензоры участвуют как индексы/данные, но не дифференцируются.

## 3.9 Строки

```lisp
(strcat "Hello, " "World")     ; → "Hello, World"
(strcat "n=" 5)                ; → "n=5"     — не-строка печатается как WRITE-TO-STRING
(substr "hello" 1 3)           ; → "ell"     (s[1:4])
(number-to-string 42)          ; → "42"      (str(42))
(to-string 42)                 ; → "42"
(string-length "abc")          ; → 3
(string= "a" "a")              ; → t
(to-fixnum "42")               ; → 42       (:option :fixnum)
(to-flonum "2.5")              ; → 2.5      (:option :flonum)
(or-else (to-fixnum "7") 0)    ; → 7        — распаковка option
(write-to-string '(1 "a"))     ; → "(1 \"a\")"
(read-from-string "(1 2)")     ; → (1 2)
```

`to-fixnum`/`to-flonum`/`to-string` возвращают `(:option T)`; `or-else` — санкционированный способ распаковать option, отдающий тип payload. Индексы строковых операций — кодовые точки.

Порядок аргументов у строковых операций зафиксирован:

```lisp
(string-split "a,b,c" ",")        ; → ("a" "b" "c") — сначала строка, потом разделитель
(string-join (list "a" "b") ",")  ; → "a,b"         — сначала список, потом разделитель
(string-upcase "abc")             ; → "ABC"
(string-downcase "ABC")           ; → "abc"
(string-trim "  a ")              ; → "a"
(string-replace "abc" "b" "X")    ; → "aXc"
(string-index "abc" "b")          ; → 1
(import string)
(string-contains "abc" "b")       ; → t — экспорт модуля string
```

Модуль `string` экспортирует также `string-starts-with`, `string-ends-with`, `string-repeat`, `string-blank?`, `string-pad-left`, `string-pad-right`, `string-lines`, `string-words`, `string-to-fixnum`, `string-capitalize`.

### Строки — неизменяемые атомы

Строка — атом с неизменяемым rope-носителем; rope-узлы — внутреннее представление реализации, не значения языка. Окон над строкой нет: `string-ref` и `string-append` как примитивы отсутствуют, `string-view` не существует. Для подстроки используйте `substr`, для сборки — `strcat` или `string-join`.

> 🐍 В Python `s.split(sep)` — метод строки и разделитель задаётся аргументом. В Qualisp приёмника нет, поэтому `(string-split s sep)` — строка первая, разделитель второй. `string-join` тоже берёт список первым: `(string-join xs sep)` ≈ `sep.join(xs)`.

## 3.10 Печать

```lisp
(print "loss: 5")                      ; одна строка, raw + перевод строки
(print (strcat "epoch " (to-string 5) ", loss " (to-string 0.25)))
;; → epoch 5, loss 0.25
(display "x")                          ; без перевода строки
(print '(1 2))                         ; → (1 2)
(write-to-string '(1 "a"))             ; → "(1 \"a\")" — читаемое представление
```

`print` печатает ровно один аргумент и добавляет перевод строки; `display` — без перевода строки; `write-to-string` возвращает читаемое представление со строками в кавычках и escape-последовательностями. Несколько значений собирайте сами через `strcat` или `(list …)`.

Структуры печатаются с тегом: `(defstruct pt ((x . :fixnum) (y . :fixnum)))` и `(pt 1 2)` дают `#<PT 1 2>`, а не `#<struct>`; у ошибок тег модуля, например `#<ERROR::ERROR "boom" nil nil USER>` (гл. 15). `type-of` при этом возвращает `STRUCT`.

> ⚠️ **Ровно один аргумент.** `(print 1 2)` даёт `print: wrong number of arguments`. В файловом раннере результат последней формы не печатается — только явный `print`/`display`.

## 3.11 Собираем вместе: FizzBuzz

```lisp
(defun fizzbuzz ((n . :fixnum))
  ((cond
     ((= (mod n 15) 0) "FizzBuzz")
     ((= (mod n 3) 0)  "Fizz")
     ((= (mod n 5) 0)  "Buzz")
     (t (number-to-string n))) . :string))

(print (map fizzbuzz (list 15 3 5 7 1 2)))
;; → ("FizzBuzz" "Fizz" "Buzz" "7" "1" "2")
```

> 🐍 Тот же код на Python:
> ```python
> def fizzbuzz(n: int) -> str:
>     if n % 15 == 0: return "FizzBuzz"
>     elif n % 3 == 0: return "Fizz"
>     elif n % 5 == 0: return "Buzz"
>     else: return str(n)
>
> [fizzbuzz(i) for i in [15, 3, 5, 7, 1, 2]]
> ```

Здесь все ветви `cond` возвращают `:string`, поэтому тип функции выведен из аннотации; `map` получает типизированную функцию и список `:fixnum`.

## 3.12 Тесты прямо в языке

Мини-фреймворка `deftest`/`run-tests` нет: в модуле `test` есть `assert-fixnum` и `assert-string`. Успех — `t`, провал бросает ошибку с ожидаемым и фактическим значением:

```lisp
(import test)
(assert-fixnum (length '(1 2 3)) 3)   ; → t
(assert-string (number-to-string 42) "42")  ; → t
```

> 🐍 `assert-fixnum` ≈ `assert a == b` в pytest; провал — `throw`, который можно перехватить через `catch-error` и разобрать как структуру `error` с категорией и трассировкой (`result-error`, `format-error`, гл. 15).

⚠️ Точное сравнение плавающих чисел в тестах ненадёжно: сравнивайте метрику с порогом, а не «на ноль». `finite?` как примитив отсутствует.

## 3.13 Гомоиконность: код как данные

Qualisp гомоиконен: программа и данные имеют одну структуру — S-выражения. Тип `:syntax` — это S-выражение как данные (cons **или** атом), а не `:any`: над ним работают `car`/`cdr`/`cons`, `equal`, печать и `eval`. Инвариант одной формы означает: нативный код — кэш, выведенный из S-выражений, и гомоиконная механика работает поверх него без ограничений (гл. 12, 20, 21).

### READ-FROM-STRING / WRITE-TO-STRING

```lisp
(read-from-string "(+ 1 2)")     ; → (+ 1 2)   (S-выражение)
(write-to-string '(+ 1 2))       ; → "(+ 1 2)" (строка)
```

> 🐍 Аналог `ast.literal_eval(...)` и `ast.unparse(...)` в Python — но выражения нативные для языка, а не отдельное AST-дерево.

### EVAL

```lisp
(eval '(+ 1 2))                         ; → 3 на верхнем уровне
(the :fixnum (eval '(+ 1 2)))           ; → 3 — явный тип в типизированном контексте
(eval (read-from-string "(* 6 7)"))     ; → 42
```

`eval : :syntax → :a`; тип `:a` выводится из контекста, форма заново проходит expand → typecheck → emit, несовпадение типа — runtime-ошибка. Это единственная документированная граница статики. Внутри `defun` с фиксированным возвратом тип `eval` консервативен, поэтому нужно приведение `the`.

### `:syntax` и макросы

```lisp
(defmacro twice (form :syntax) :syntax
  `(progn ,form ,form))
(twice (+ 1 2))                          ; → 3
(macroexpand-all '(twice (+ 1 2)))       ; → (PROGN (+ 1 2) (+ 1 2))
(gensym)                                 ; → G-0
```

`defmacro` определяет `:syntax → :syntax`; раскрытие идёт до проверки типов, до неподвижной точки. `defmacro` — исключение из правил парных аннотаций: `(defmacro twice (form :syntax) :syntax …)` использует позиционную запись, где параметры — символы с состоянием `:atom`/`:syntax`, а состояние результата — отдельный `:syntax` атом. Для `defun`/`defvar`/`defstruct` такая запись не принимается. В макросах работают `&rest` (остаток одним `:syntax`-списком) и `&optional` (пропущенный параметр — `nil`), `macroexpand-1`, `macroexpand`, `macroexpand-all` (рекурсивно, не заходя в `quote`) и `gensym` для гигиены. Тело макроса проверяется в живом окружении и видит функции модуля.

### Что недоступно

Примитивов интроспекции `functionp`, `function-params`, `function-body`, `function-env`, `symbol-name`, `boundp`, `set-reader-macro` и генератора `randint`/`random` в релизе нет: вызов даёт `unknown function ...`. Вместо инспекции замыканий используйте мастер-форму S-выражения: `defun`/`defmacro` хранят её, а макросы и `macroexpand-all` работают с кодом как с данными.

### IMPORT-FROM

```lisp
(import-from CORE (identity caar))   ; только названные экспорты
(identity 5)                         ; → 5
```

> 🐍 Аналог `from core import identity, caar` в Python. Имя модуля — символ, список имён — второй аргумент; неизвестный экспорт даёт `UnknownExport`.

## 3.14 Что делает рантайм

Когда вы набираете `(+ 1 2)` в REPL, происходит следующее:

1. **Reader** разбивает ввод на токены со спанами и строит S-выражение.
2. **MacroExpander** раскрывает макросы до неподвижной точки; `quote` при этом не трогается.
3. **Checker** проверяет типы: аннотации сверху, двунаправленный вывод внутри функций. Отказ — диагностика с позицией, а не попытка угадать тип.
4. **Emitter** компилирует форму в JIT-страницу (copy-and-patch, W^X); top-level форма исполняется сразу, тело `defun` — при определении.
5. **Runtime** исполняет страницу, хранит глобалы в плотном массиве, ведёт кадры вызовов в bump-арене и возвращает значение формы.

Интерпретатора/tree-walk нет: каждая форма проходит этот конвейер. Нативная страница не читает дерево в момент исполнения; она — выбрасываемый кэш, который можно пересобрать из мастер-формы. Исходные карты связывают байты страницы со спаном, поэтому runtime-ошибка получает позицию `file:line:col`.

> 🐍 Похоже на `ast.parse` + `compile` + `exec` в Python, но без второго AST как авторитетной формы: S-выражение остаётся мастер-представлением и во время исполнения.

## 3.15 Тензорные примитивы: арность и доступ к элементам

Тензор печатается как `#<tensor>`, `type-of` даёт `TENSOR`. Значения создаются литералом `tensor` или `zeros`/`ones`/`randn` с формой, записанной литеральным списком чисел (без кавычки):

```lisp
(defvar tt ((tensor ((1.0 2.0) (3.0 4.0))) . (:tensor :f32 (2 2))))
(print tt)                     ; → #<tensor>
(print (type-of tt))           ; → TENSOR
(print (tref tt 0 1))          ; → 2.0
(tset! tt 0 1 9.0)
(print (tref tt 0 1))          ; → 9.0
(print (t-shape tt))           ; → (2 2)
(print (tsum tt))              ; → 17.0
(print (zeros :f32 (2 2)))     ; → #<tensor>
(print (reshape tt (4)))       ; → #<tensor>
```

`reshape` и `zeros`/`ones`/`randn`/`rand` принимают форму как обычный список чисел `(2 2)` — квотированная форма `'(2 2)` даёт `tensor dimension must be an integer`. Вместо литерала можно передать `(list n m)`: ранг остаётся статическим, а значения измерений берутся в рантайме. `(tensor :i64 ((1 2) (3 4)))` создаёт точный целочисленный тензор; литерал без dtype всегда `:f32`.

### Доступ к элементу: `tref` и `tset!`

`tref` требует ровно столько индексов, сколько измерений у тензора; индексы — `:fixnum`, выход за границы — ошибка. `tset!` принимает индексы и значение и возвращает тот же тензор:

```lisp
(print (tref (tensor (1.0 5.0 2.0)) 1))   ; → 5.0
(tset! tt 1 0 3.0)                        ; записать 3.0 в строку 1, колонку 0
```

`tensor-item`, `t+`, `t*`, `tensor-shape`, `tensor-dtype`, `sigmoid`, `elementwise` как функции отсутствуют: поэлементные операции — обычные `+ - * /`, интроспекция — `t-shape`.

### Выборки копируют

`t-shape`, `t-column`, `t-rows`, `t-select-rows` — доступ к форме и подвыборкам; `reshape`/`transpose`/`t-slice`/`t-concat` тоже создают копию. Writable views нет:

```lisp
(print (t-shape tt))                 ; → (2 2)
(print (t-column tt 0))              ; → #<tensor> — столбец, копия
(print (t-rows tt 0 1))              ; → #<tensor> — одна строка, копия
(print (t-select-rows tt (list 0)))  ; → #<tensor> — выбранные строки, копия
(print (transpose tt))               ; → #<tensor>; по умолчанию оси в обратном порядке
(print (transpose tt '(1 0)))        ; → #<tensor>; явная перестановка осей
(print (t-slice tt (0 0) (1 2)))     ; → #<tensor>; копия блока
```

> 🐍 В NumPy `a[i:i+n]` — записываемое представление. Здесь выборка — новый тензор; запись идёт в источник через `tset!` или `t-copy!`.

### Формы, индексы и составные операции

```lisp
(softmax t)                       ; по последней оси, ранг ≥ 1
(log-softmax t)                   ; устойчивый log-sum-exp по последней оси
(argmax t axis)                   ; → :i64-тензор; только последняя ось, ранг ≥ 2
(argmax t)                        ; → :fixnum; только 1-D
(t-one-hot labels 10)             ; :i64-метки → :f32-тензор (..., 10)
(t-gather rows table)             ; rows :i64; форма rows ++ table[1..]
(t-scatter-add rows values shape) ; нулевая таблица + строки; повторы суммируются
(t-concat a b 0)                  ; конкатенация по оси
(t-copy! dst src)                 ; точная запись на месте, сохраняет param-идентичность
(t-conv2d x w stride pad [dilation [groups]])
(t-max-pool2d x kernel stride [pad])
(t-avg-pool2d x kernel stride [pad])
(t-gt a b) (t-lt a b)             ; маска 1.0/0.0, без градиента
(rand-like t)                     ; uniform [0,1); запрещён в трассировке
```

`t-gather`/`t-scatter-add` принимают только `:i64`-индексы; градиент идёт по значениям, не по индексам. `t-concat` имеет backward с блочными градиентами. `t-conv2d` работает с `[N,C,H,W]` и `[O,C/groups,KH,KW]`, поддерживает stride/pad/dilation/groups; pooling принимает `pad`, внешние клетки не участвуют в max и не входят в знаменатель avg. `t-one-hot`/`argmax`/`t-gt`/`t-lt` — дискретные операции без градиента.

### Детерминированные reduction'ы

`tsum`, `tmean`, `tmax` без оси — полные свёртки в скаляр; с осью — `(tsum t axis [keep])`, `(tmean t axis [keep])`, `(tmax t axis [keep])`, где `keep` оставляет размер оси равным 1. Полные `tsum`/`tmax` над `:u8`/`:i64` возвращают `:fixnum`, `tmean` всегда `:flonum`; осевые reduction'ы над `:i64` запрещены. Свёртки считаются в фиксированном порядке (для `tsum`/`tmean` — восемью независимыми f64-полосами), поэтому результат детерминирован и совпадает с последовательным проходом побайтово. Точное равенство имеет смысл только для точно представимых значений; `sqrt` и унарные `exp`/`log`/`tanh` работают и с числами, и с тензорами. Примитива `finite?` нет.

## 3.16 Платформа и командная строка

Отдельных форм `target`, `target-feature`, `cfg` в языке нет: платформа задаётся сборкой. JIT-код использует x86-64 SysV (на Windows Zig порождает SysV-функции внутри PE, поэтому байты страниц одинаковы), SIMD — AVX2; W^X — `mmap`/`mprotect` на POSIX и `VirtualAlloc`/`VirtualProtect` на Windows. Основная платформа — Linux x86_64; Windows x86_64 поддерживается с оговорками.

Примитив `(command-line-args)` возвращает `(:list :string)`, первый элемент — путь скрипта (`argv[0]`), список непуст при запуске файла; в REPL он `nil`. Разбором аргументов занимается модуль `argparse`:

```lisp
(import argparse)
(print (command-line-args))
(print (flag? (command-line-args) "verbose"))
(print (option-value (command-line-args) "name"))
(print (positionals (command-line-args) (list "name")))
```

```text
$ qualisp script.qlsp --verbose --name lena input.txt
(script.qlsp --verbose --name lena input.txt)
t
lena
(input.txt)
```

Имена опций пишутся без дефисов (`"verbose"` → `--verbose`/`-verbose`); `option-value` понимает и `--name value`, и `--name=value`; `positionals` требует явного списка опций со значениями. Есть ещё `require-option` — обязательная опция со значением: её отсутствие — ошибка. Примитива `command-line` с кастомным разбором нет.

> 🐍 **Python-аналогия.** `(command-line-args)` ≈ `sys.argv`, а `argparse` — одноимённый модуль Python: `flag?`≈`store_true`, `option-value`≈`args.name`, `require-option`≈`required=True`, `positionals`≈ positional-аргументы.
