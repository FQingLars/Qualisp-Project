# Глава 6. Тензоры

Тензоры — N-мерные массивы, центральный тип данных Qualisp-ML. Аналог `np.ndarray` / `torch.Tensor`, но с линейной моделью владения (гл. 4–5): тензор — атом с dtype, конкретной формой и плоским буфером, а не объект со ссылками.

## 6.1 Структура тензора

Из `src/tensor/tensor.zig` (`src/tensor/CODE.md`):

```zig
pub const DType = enum { f16, f32, f64, u8, i64 };
pub const Owner = enum { scratch, world, pool };
pub const Tensor = struct {
    dtype: DType,
    shape: []usize,          // конкретная форма
    storage: Storage,        // union(DType) { f16/f32/f64: []T, u8: []u8, i64: []i64 }
    owner: Owner = .scratch,
    requires_grad: bool = false,
};
```

Поддерживаемые dtype: **F16, F32, F64, U8, I64**. Размеры: `F16=2, F32=4, F64=8, U8=1, I64=8` байт.

Статический тип тензора — `(:tensor DTYPE (DIMS...))`, где `DTYPE ∈ {:f16, :f32, :f64, :u8, :i64}`, а измерение может быть числом или `_` (неизвестное измерение). Вместо всего списка измерений можно написать `:any` — тогда ранг неизвестен, но dtype известен: `(:tensor :f32 :any)`. Конкретный тензор присваивается такому типу, обратное неверно; операции, которым нужен ранг (свёртка, пулинг, `t-column`, `t-rows`, `defgraph`), `:any` отвергают. Пример:

```lisp
(defvar a ((tensor ((1.0 2.0) (3.0 4.0))) . (:tensor :f32 (2 2))))
(defvar w ((randn :f32 (3 2)) . (:tensor :f32 (_ _))))   ;; ранг и dtype фиксированы, размеры — нет
```

Аннотация `defvar` — парная: `(значение . :тип)`, причём значение — само выражение-инициализатор. Позиционная запись (`(defvar a :tensor :f32 (2 2) …)`) в 0.19.20 не принимается.

Eager-тензор живёт в scope-арене, но его буфер берётся из `TensorBufferPool` (`owner = .pool`); `defvar` и `param` копируют значение в долгоживущую память общего аллокатора (`owner = .world`). Тот же пул обслуживает промежуточные тензоры HLO-графа (гл. 7, 10). `requires_grad` ставит `param`; флаг переживает копирование в world.

Печать тензора — `#<tensor>` (без содержимого), `type-of` даёт `TENSOR`. dtype и форму надо смотреть в статическом типе или через `t-shape`.

## 6.2 Создание

```lisp
;; Литерал — вложенные списки, всегда :f32, форма выводится
(tensor ((1.0 2.0) (3.0 4.0)))     ;; 2×2, :f32; прямоугольность проверяется

;; Фабрики: dtype — keyword, форма — СПИСОК измерений
(zeros :f32 (2 3))                 ;; нули             np.zeros((2,3))
(ones :f32 (4 2))                  ;; единицы          np.ones((4,2))
(randn :f32 (100 1))               ;; N(0,1)           np.random.randn(100,1)
(rand :f32 (2 2))                  ;; равномерно [0,1) np.random.rand(2,2)
(zeros (2 2))                      ;; dtype по умолчанию :f32
(tensor :i64 ((1 2) (3 4)))        ;; точные целые индексы/счётчики
(zeros :f32 (list n m))            ;; ранг статический, размеры — runtime
```

**Важно.** Форма задаётся списком: `(zeros :f32 (2 2))`. Записи `(zeros 2 2)` и `(zeros :f32 '(2 2))` не работают. Вместо литерала можно передать `(list n m)` — ранг всё равно статический, а значения измерений вычисляются в рантайме; результат имеет wildcard-форму `(_ …)` того же ранга, конкретные размеры проверяются при исполнении. Это используют `dl/init-weights` и `adam-state`. Синтаксис `(:tensor :f32 (2 2))` в аннотациях — тот же список без кавычки.

`randn` использует xorshift64* в `Runtime` — быстрый, но не криптостойкий генератор (детерминированный сид). `rand` и `rand-like` дают равномерное `[0,1)`; `rand-like` запрещён внутри трассировки графа.

> 🐍 **Python-аналогия.**
> ```python
> a = np.array([[1., 2.], [3., 4.]])
> np.zeros((2, 3)); np.ones((4, 2)); np.random.randn(100, 1)
> ```
> F16/F64/U8/I64 выбираются фабрикой (`zeros :f16 (4 4)`, `tensor :i64 ...`), а не приведением готового тензора: `tensor`-литерал без dtype всегда `:f32`.

## 6.3 Информация о тензоре

```lisp
(t-shape a)        ;; → (2 2)   — список измерений       a.shape
(tref a 0 0)       ;; элемент по координатам            a[0,0]
(t-column a 0)     ;; столбец — КОПИЯ, только 2-D       a[:, 0]
(t-rows a 0 2)     ;; строки [from, from+count) — КОПИЯ  a[from:from+count]
(t-select-rows a (list 0 2))  ;; строки по индексам — КОПИЯ  np.take(a, [0,2], axis=0)
(t-slice a (0 1) (2 2))       ;; прямоугольный блок — КОПИЯ   a[0:2, 1:3]
(t-copy! dst src)             ;; точное копирование на месте    dst[...] = src
(t-concat a b 0)              ;; конкатенация по оси 0           np.concatenate
(t-gather rows table)         ;; строки table по :i64-индексам   table[rows]
(t-scatter-add rows vals (n m)) ;; прибавить vals в rows        np.add.at
(t-one-hot labels C)          ;; :i64-метки → :f32 one-hot       F.one_hot
(t-gt a b)                    ;; маска 1.0/0.0, broadcast       (a > b).float()
(t-lt a b)                    ;; маска 1.0/0.0, broadcast       (a < b).float()
(rand-like a)                 ;; [0,1) той же формы            torch.rand_like
```

`t-slice` принимает только статические смещения и длины; это копия, а не writable view. `t-copy!` копирует в существующий `dst` и сохраняет идентичность `param` (поэтому пригоден для оптимизаторов), но запрещён внутри трассировки. `t-gather`/`t-scatter-add` работают с `:i64`-индексами; повторные индексы в `t-scatter-add` суммируются в порядке индексов. `t-one-hot` возвращает `:f32`, `t-gt`/`t-lt` — маски без градиента.

`t-shape`, `t-column`, `t-rows`, `t-select-rows`, `t-slice` — интроспекция/выборки из `src/checker.zig`; все они возвращают **новые тензоры**. Функций `tensor-shape`, `tensor-dtype`, `tensor->list`, `tensor-item` в текущей реализации нет: dtype известен статически по аннотации, а форму отдаёт `t-shape`.

### Контракт индексации `tref`

Число индексов ровно равно рангу тензора; каждый индекс — `:fixnum`:

```lisp
(tref (tensor (1.0 2.0)) 1)              ;; → 2.0 — ранг 1, один индекс
(tref (tensor ((1.0 2.0) (3.0 4.0))) 1 0) ;; → 3.0 — ранг 2, два индекса
```

Два индекса на векторе дают `tref expects 2 indices`; на матрице один индекс не подходит. Индекс проверяется по типу и границам: не-fixnum, отрицательный или за границей — ошибка, а не чтение чужой памяти.

### Запись элемента: `tset!`

`(tset! t i j … v)` — мутация **на месте** по координатам (число индексов = ранг), возвращает тот же тензор, поэтому записи можно цеплять.

```lisp
(defvar tt ((tensor ((1.0 2.0) (3.0 4.0))) . (:tensor :f32 (2 2))))
(tset! tt 1 0 9.0)     ;; → тот же tt
(tref tt 1 0)          ;; → 9.0
```

| Кто | Правило |
|---|---|
| float-тензоры (F16/F32/F64) | принимают число; fixnum пишется как float: `(tset! tt 0 0 7)` даёт `7.0` |
| U8 | только fixnum, значение усекается по clamp: `300` → `255`; flonum — ошибка `tset! value has the wrong type` |
| I64 | только fixnum; значение хранится точно, без f64-раундтрипа |
| индекс | неотрицательный fixnum в границах, ровно по рангу |
| значение | нечисло — ошибка |

> 🐍 Это `t[i, j] = v` в NumPy — но с проверкой типа на каждой записи. Именно `tset!`, а не оператор `setf` на элемент: совместимых writable views в языке нет.

### Умная печать

`print`/`display` показывают `#<tensor>` — компактно, без содержимого и без dtype. Это не усечение «для вида»: полная форма значения хранится в тензоре, а печать — только краткое диагностическое представление. Для просмотра отдельных значений используйте `tref`.

## 6.4 Арифметика и матричные операции

| Qualisp | Что делает | NumPy |
|---|---|---|
| `(+ a b)` | поэлементное сложение с broadcasting | `a + b` |
| `(- a b)` | поэлементная разность | `a - b` |
| `(* a b)` | поэлементное умножение | `a * b` |
| `(/ a b)` | поэлементное деление (не для `:u8`) | `a / b` |
| `(matmul a b)` | batched-умножение, ранг ≥2 | `a @ b` |
| `(reshape t (M N))` | изменение формы, глубокая копия | `t.reshape(M, N)` |
| `(transpose t [perm])` | перестановка осей, по умолчанию обратный порядок; копия | `t.permute(...)` / `t.T` |
| `(t-slice t starts lens)` | прямоугольный блок, копия | `t[...]` |
| `(t-conv2d x w stride pad [dilation [groups]])` | свёртка `[N,C,H,W]` | `F.conv2d` |
| `(t-max-pool2d x k s [pad])` / `(t-avg-pool2d …)` | пулинг | `F.max_pool2d` |
| `(tref t i j)` / `(tset! t i j v)` | чтение/запись элемента | `t[i,j]` / `t[i,j] = v` |

`t+`, `t-`, `t*`, `t/` **не существуют** — поэлементные операции делает обычная арифметика `+ - * /`, типовая по своим операндам: числа дают число, тензоры — тензор с broadcast. `*` — Hadamard (поэлементное), матричное произведение — `matmul`.

Арифметика **n-арная**: `(+ a b c …)`, `(* a b c …)`, `(- a b c …)` — все работают и на тензорах, и на числах; `(- a)` — унарный минус. На тензорах n-арные формы складывают/умножают соответствующие элементы с broadcast:

```lisp
(+ 1 2 3 4)    ;; → 10        (* 2 3 4)   ;; → 24
(- 10 3 2)     ;; → 5         (- 5)       ;; → -5
```

Для `exp`, `log`, `sqrt`, `sin`, `cos`, `atan` действует перегрузка по типу аргумента: число → `:flonum`, тензор → elementwise с сохранением dtype. `relu` — elementwise-операция над тензором.

```lisp
(defvar x ((randn :f32 (3 2)) . (:tensor :f32 (3 2))))
(defvar y ((randn :f32 (2 4)) . (:tensor :f32 (2 4))))
(print (t-shape (matmul x y)))   ;; → (3 4)

;; batched: ведущие оси должны совпадать, последние две перемножаются
(matmul (zeros :f32 (2 3 4)) (zeros :f32 (2 4 5)))  ;; → (2 3 5)
;; transpose принимает квотированную перестановку осей
(transpose x '(1 0))             ;; → (2 3)
```

> 🐍 `+`/`*` — `a + b`/`a * b`; batched `matmul` — `a @ b`; `transpose` с `perm` — `a.permute(...)`.

Арность проверяется статически: `(matmul)` даёт `matmul: wrong number of arguments`, `(reshape t 2 2)` — `reshape: wrong number of arguments`; несовпадение известных форм (K в `matmul`, число элементов в `reshape`) — ошибка компиляции. `matmul` требует ранг ≥2 и равные ведущие оси (broadcast партии нет); `transpose` по умолчанию переворачивает порядок осей, явный `'(...)` должен быть перестановкой.

### Writable views нет: reshape/transpose/выборки — копии

`reshape`, `transpose` и `t-slice` всегда возвращают новый тензор со скопированными данными.
`reshape` требует совпадения числа элементов; `transpose` принимает необязательную перестановку осей.
`column`/`rows`/`select-rows` тоже копируют: изменив исходный тензор через `tset!`, вы не измените результат выборки. Единственная запись на месте — `t-copy!` в существующий `dst`; она не создаёт view.

```lisp
(defvar a ((tensor ((1.0 2.0) (3.0 4.0))) . (:tensor :f32 (2 2))))
(defvar b ((reshape a (4)) . (:tensor :f32 (4))))
(tset! a 0 0 9.0)
(tref b 0)      ;; → 1.0 — b — независимая копия
```

Отличается от NumPy, где `a.T` и `a.reshape(...)` — представления над теми же байтами, и от PyTorch, где `view()` делит память. Здесь второго владельца не возникает: у результата ровно один владелец.

### Выборка строк

```lisp
(t-rows a 1 2)                 ;; строки 1 и 2, форма (2 2)      a[1:3]
(t-select-rows a (list 0 2))   ;; строки 0 и 2, форма (2 2)      np.take(a, [0,2], axis=0)
(t-column a 1)                 ;; столбец 1                     a[:, 1]
```

Операции рассчитаны на 2-D (`tablet operations expect a 2-D tensor` для 1-D входа) и возвращают копии. Индексы `t-select-rows` задаются **списком** fixnum.

### Проверка значений

Отдельного примитива `finite?` нет. Проверять содержимое можно только явно — `tref` и сравнения:

```lisp
(= (tref (tensor (1.0 2.0)) 0) 1.0)   ;; → t
```

Числа в редукциях считаются в f64-полосах с фиксированным порядком сведения (§6.6), поэтому результат детерминирован; точное равенство имеет смысл только для точно представимых значений.

## 6.5 Broadcasting

Как в NumPy: операции растягивают измерения размера 1 (скаляр или вектор-строка к матрице), выравнивание измерений — справа налево. Реализовано в тензорных ядрах `elementwise` через `broadcastOffset`.

```lisp
(+ (tensor ((1.0 2.0) (3.0 4.0))) (tensor ((10.0))))  ;; прибавит 10 ко всем
(* (tensor ((1.0 2.0) (3.0 4.0))) 2.0)                ;; скаляр — broadcast
```

**dtypes обязаны совпадать**: `(+ (zeros :f32 (2)) (zeros :f64 (2)))` даёт `tensor dtypes must match`. Автоматического `promote_dtype` нет — смешанные dtype нужно приводить заранее.

## 6.6 Редукции

```lisp
(tsum t)               ;; сумма всех элементов             t.sum()
(tmean t)              ;; среднее                          t.mean()
(tmax t)               ;; максимум                         t.max()
(tsum t axis)          ;; сумма по одной оси              t.sum(axis)
(tsum t axis t)        ;; с сохранением оси размером 1    t.sum(axis, keepdim=True)
(tmean t axis [keep])  ;; среднее по оси
(tmax t axis [keep])   ;; максимум по оси
(argmax t)             ;; индекс максимума, только 1-D, → :fixnum
(argmax t axis)        ;; индекс по последней оси, → :i64-тензор
```

Полные свёртки дают скаляр; осевые формы принимают номер оси и необязательный `keep` (ось остаётся размером 1). Для `:u8` и `:i64` полные `tsum`/`tmax` возвращают `:fixnum`, `tmean` всегда `:flonum`. Осевые редукции для `:i64` отвергаются. `argmax` без оси работает только с 1-D и возвращает `:fixnum`; `(argmax t axis)` работает только с последней осью ранга ≥2 и возвращает `:i64`.

Редукции считаются восемью независимыми f64-полосами с фиксированным порядком сведения. `tsum`/`tmean` параллелятся по группам 8-полосных partial'ов (§6.8); полосы и partial'ы сводятся в строго зафиксированном порядке, поэтому результат **побайтно совпадает** с последовательным вариантом. Осевые редукции используют тот же детерминированный проход. Порядок не «слева направо», как в наивном цикле; сравнение на точное равенство корректно только для точно представимых значений. `tmax` и `argmax` последовательны.

## 6.7 Активации и элементы нейросетей

```lisp
(relu t)        ;; elementwise max(0, x)
(exp t)         ;; elementwise e^x
(log t)         ;; elementwise ln x
(tanh t)        ;; elementwise tanh
(sin t)         ;; elementwise sin
(cos t)         ;; elementwise cos
(sqrt t)        ;; elementwise sqrt
(atan t)        ;; elementwise atan
(exp 1.0)       ;; → 2.7182818284590455 — та же функция на числе
(abs t)         ;; elementwise |x| (для чисел — обычный abs)
(softmax t)     ;; по последней оси, тензор любого ранга ≥1
(log-softmax t) ;; устойчивый log softmax по последней оси
(argmax t)      ;; только 1-D, возвращает :fixnum
(argmax t axis) ;; по последней оси, возвращает :i64-тензор
(t-one-hot labels C) ;; :i64-метки → :f32 one-hot
```

`sin`, `cos`, `sqrt`, `atan`, `abs`, `softmax` и `log-softmax` имеют forward- и backward-ядра и доступны не только в eager-коде, но и внутри `defgraph` (гл. 7). `softmax`/`log-softmax` считаются по последней оси: строки независимы, внутри строки порядок фиксирован; для 2-D это обычный row-wise softmax. Сигмоиды (`sigmoid`) как самостоятельной функции нет. Свёртки, пулинг и dropout живут в `dl` и HLO-примитивах `t-conv2d`/`t-max-pool2d`/`t-avg-pool2d` (гл. 8), а не в списке elementwise-активаций.

> 🐍 Это `torch.nn.functional.relu / softmax / log_softmax / abs / tanh` — но как обычные функции языка, без классов-обёрток. `softmax` сам разбирается с последней осью, вручную собирать его из `exp`/`tsum` нужно только для нестандартной оси.

### Строительные блоки символьного градиента

Четыре операции сохраняют форму тензора и нужны reverse-mode `grad` (гл. 7) как готовые термы градиента:

| Qualisp | Что делает | Python-аналог |
|---|---|---|
| `(ones-like t)` | тензор из единиц той же формы и dtype | `torch.ones_like(t)` |
| `(tmax-mask t)` | `1.0` в позициях максимума, `0.0` в остальных (при нескольких максимумах — `1.0` у всех) | `t.eq(t.max()).float()` |
| `(relu-mask t)` | `1.0` там, где `t > 0`, `0.0` иначе (в нуле — `0.0`) | `(t > 0).float()` |
| `(reshape-like t ref)` | форма `t` заменяется формой `ref`; число элементов обязано совпадать | `t.reshape(ref.shape)` |

```lisp
(defvar tv ((tensor ((1.0 2.0) (3.0 4.0))) . (:tensor :f32 (2 2))))
(tref (ones-like tv) 1 1)                                  ;; → 1.0
(tref (tmax-mask (tensor (1.0 5.0 2.0))) 1)                ;; → 1.0
(tref (relu-mask (tensor (-1.0 2.0 0.0))) 0)               ;; → 0.0
(tref (relu-mask (tensor (-1.0 2.0 0.0))) 1)               ;; → 1.0
(tref (reshape-like (tensor (1.0 2.0 3.0 4.0)) tv) 1 1)    ;; → 4.0
```

Это forward-only операции: у них нет собственного backward-правила — они **сами** являются термами, которые `grad` порождает для `tsum`, `tmax`, `relu` и `reshape`. `reshape-like` проверяет совпадение числа элементов статически, если обе формы известны.

## 6.8 Производительность: SIMD и ядра

- Поэлементные операции (`+ - * /` на тензорах, `relu/exp/log/tanh/sqrt/sin/cos/atan`) идут через `elementwise`/`map` с AVX2: 8×f32 или 4×f64 за итерацию. Для f32/f64, когда операнды уже имеют форму результата, идёт линейный цикл без `broadcastOffset` и без f64-раундтрипа; общий broadcast-путь остаётся для настоящего вещания.
- `matmul` — `i-k-j` с `@Vector` (8 f32 / 4 f64): на 128³ время упало с ~237 мс до ~17 мс.
- `tsum`/`tmean` — блочное суммирование 8 f64-полосами (23 → 7 мс на 200×131k), детерминированный порядок сведения (SPEC §8).
- U8/F16 в `map` остаются на общем пути: там важна точная семантика `Tensor.set` (округление и clamp).
- `TensorBufferPool` — exact-size free lists по `(len, alignment)`, реализация `std.mem.Allocator`. Буферы переиспользуются, финальный выход копируется в scratch. Пул обслуживает и eager-скретч (`Runtime.tensorAlloc`/`allocTensor`), и intermediate-тензоры HLO-графа; долгоживущие `defvar`/`param` идут мимо пула.
- Граф компилируется лениво в x86-64 (`call`-threaded прямой вызов ядер, W^X-страница); первый вызов ждёт фоновую компиляцию, пул компиляции — `N = min(cpu_count, 8)` воркеров.

### Как устроено ядро

- **Ядра** — C-ABI функции в `src/hlo/kernels.zig` (forward) и `bwd_kernels.zig` (backward), SIMD AVX2, типы `f32/f64/u8`.
- **Редукции** — 8 f64-полос, порядок сведения зафиксирован; это даёт воспроизводимость вместо «слева направо».
- **Каждый compiled-вызов создаёт свой `TensorBufferPool`**, поэтому один граф можно вызывать параллельно из futures без mutex.
- `Graph.peak_bytes` — оценка пика live-байт по liveness; жёсткого cap нет.

### Параллельные ядра

Вычислительные ядра параллелятся через отдельный пул `kernel_pool` (`src/kernel_pool.zig`) — не путать с пулом компиляции HLO:

- Потоки создаются **лениво на первом достаточно большом вызове**; число воркеров `max(1, min(cpu-1, 8))`. Маленькие входы остаются последовательными; `QUALISP_SERIAL=1` отключает пул полностью.
- Воркеры — чистые вычислительные потоки: у них нет `Runtime`. Вызывающий выделяет входные/выходные буферы, воркеры пишут в непересекающиеся диапазоны; `frame.pool`, `grads[]`, trace и scope-арены остаются на одном потоке. Вложенный параллелизм на воркерах отключён (иначе дедлок фиксированного пула).
- По элементам: `elementwise`/`map` (порог ~256K) и `broadcastRows` с векторизованным внутренним циклом. По строкам: batched `matmul` (i-k-j, строки результата независимы), `reshape`, `transpose`, `softmax`/`log-softmax` (строки последней оси), `reduceRows` (обратный broadcast). `tsum`/`tmean` — по группам 8-полосных partial'ов. `conv2d`/пулинг параллелятся по batch вперёд и в два прохода назад (`dx` по batch, `dw` по выходным каналам). Последовательны `max`, `argmax` и скалярные свёртки с глобальным порядком.
- Параллельный и последовательный результаты сверены **побайтно** (`src/parallel_test.zig`). Замер A/B ReleaseFast, 16 ядер, min из 11: matmul 15.9 → **7.6 мс (2.10×)**; `softmax`/`conv`/`pool` дают кратный выигрыш на больших партиях (conv fwd+bwd 163 → 40 мс, 4.1×), а `max`/`argmax` остаются последовательными.

## 6.9 dtype: F16, F32, F64, U8, I64

```zig
pub const DType = enum { f16, f32, f64, u8, i64 };
```

- **F32** — default литерала `(tensor ...)` и фабрик без dtype.
- **F16** — IEEE 754 binary16, 2 байта; задаётся фабрикой `(zeros :f16 (4 4))`.
- **F64** — double, 8 байт.
- **U8** — байты, 1 байт; целочисленный. Деление `:u8`-тензоров запрещено статически (`division of :u8 tensors is not supported`), `param`/`grad` на `:u8` отвергаются.
- **I64** — точные 64-битные целые для индексов и счётчиков. Значения не проходят через f64: `tref`/`tset!`, `reshape`, `transpose`, `t-rows`, `t-select-rows` и `+ - *` (с переполнением по модулю 2⁶⁴) сохраняют точность. Полные `tsum`/`tmax` понижают результат до `:fixnum`; `matmul`, `softmax`, унарная математика, `tmean`, осевые редукции и `param`/`grad` для `:i64` запрещены. `tensor`-литерал с `:i64` принимает только целые элементы.

Смешанные dtype в elementwise не приводятся — `tensor dtypes must match`. Приведений `tensor-f16`/`tensor-f32`/`tensor-u8` нет; нужный dtype задаётся при создании тензора. `:i64` — данные, а не новый скалярный тип: `type-of` тензора остаётся `TENSOR`.

## 6.10 Сохранение/загрузка: QSRD

Примитивов `save-npy`/`load-npy` нет. Сериализация идёт через формат QSRD (`src/image/CODE.md`):

```lisp
(save-image "/tmp/world.qimg")                 ;; пользовательский мир: формы + defvar-данные
(load-image "/tmp/world.qimg")                 ;; замена мира и пересборка кода
(save-weights "/tmp/w.qsrd" (list 7 8))        ;; только параметры + состояние
(load-weights "/tmp/w.qsrd")                   ;; → (7 8) — состояние как :syntax
```

`save-weights` пишет QSRD с секциями `meta`, `symbols`, `model`: параметры — стабильные тензоры с `requires_grad` в порядке `SymbolId`, состояние — произвольные данные (шаг, lr, seed), схему формат не навязывает. `load-weights` сначала валидирует **все** параметры (неизвестное имя, несовпадение dtype/формы — ошибка без частичного применения) и только потом заменяет биндинги.

`save-image` сохраняет пользовательские формы и `defvar`-значения — тензоры (dtype+shape+байты), списки, строки, символы, структуры, result, общие и циклические ссылки. Не сериализуются JIT-страницы, скомпилированные HLO-графы и `defuse`-кернелы, планы `ns-if`, `future` и `:ptr` — они пересобираются при загрузке либо отвергаются. `load-image` не атомарен.

> 🐍 `save-weights`/`load-weights` ≈ `torch.save(model.state_dict())` / `load_state_dict()`, а `save-image` — близок к pickle всего пользовательского мира (код пересобирается из мастер-форм).

## 6.11 Полная картина тензорных операций

```text
             ┌────────────────────────────────────────┐
             │  Tensor: dtype, shape, storage, owner │
             └────────────────────────────────────────┘
                │       │        │          │
           создание  elementwise  reduce   matmul/reshape/transpose
                │       │        │          │
                ▼       ▼        ▼          ▼
        scratch/world  AVX2-ядра  f64-полосы  копии + HLO-пул
```

| Слой | Операции |
|---|---|
| Создание | `tensor`, `zeros`, `ones`, `randn`, `rand`, `t-one-hot` |
| Интроспекция/копия | `t-shape`, `t-column`, `t-rows`, `t-select-rows`, `t-slice`, `reshape`, `transpose`, `t-concat` |
| Индексация | `tref`, `tset!`, `t-gather`, `t-scatter-add`, `t-copy!` |
| Элемент | n-арные `+ - * /`, унарный `-`, `relu`, `exp`, `log`, `tanh`, `sqrt`, `sin`, `cos`, `atan`, `abs`, `softmax`, `log-softmax`, `t-gt`, `t-lt`, `rand-like` |
| Термы градиента | `ones-like`, `tmax-mask`, `relu-mask`, `reshape-like` |
| Редукции | `tsum`, `tmean`, `tmax` (полные и по одной оси), `argmax` (1-D или последняя ось) |
| Матричные | batched `matmul` (ранг ≥2) |
| Свёртки/пулинг | `t-conv2d`, `t-max-pool2d`, `t-avg-pool2d` |
| Графовые (гл. 7) | `param`, `defgraph`, `defuse`, `grad!`, `grad-of` |
| Сериализация | `save-image`, `load-image`, `save-weights`, `load-weights` |

## 6.12 Известные ограничения

- `matmul` требует ранг ≥2 и равные ведущие оси; broadcast партии не поддерживается.
- `softmax`/`log-softmax` работают по последней оси любого ранга ≥1. `argmax` без оси — только 1-D, `argmax t axis` — только последняя ось. `t-column`/`t-rows`/`t-select-rows` рассчитаны на 2-D. `max` и `argmax` пока не параллелятся.
- Writable views нет: `reshape`, `transpose`, `t-slice` и все выборки копируют. `t-slice` принимает только статические смещения/длины; `t-copy!` — единственная запись на месте, и она запрещена в трассировке.
- `tensor`-литерал без dtype всегда `:f32`; нужный dtype задаётся фабрикой или `(tensor :i64 ...)`.
- Mixed dtype в elementwise отвергается; `:u8` — целый, деление и `param` на нём запрещены; `:i64` не дифференцируется и не участвует в `matmul`/`softmax`/осевых редукциях.
- Нет `tensor-shape`, `tensor-dtype`, `tensor->list`, `tensor-item`, `finite?`, `t+`/`t*`.
- Нет сигмоиды и отдельного `batchnorm`; свёртки/пулинг есть как `t-conv2d`/`t-*-pool2d`, `dropout` — в `dl`.
- `ones-like`, `tmax-mask`, `relu-mask`, `reshape-like` — forward-only термы градиента, собственного backward у них нет (гл. 7).
- Нет NPY; сериализация — QSRD (`save-image`/`save-weights`).
- `randn` — xorshift64*, не криптографический ГПСЧ.
- Редукции детерминированы, но их порядок сведения отличается от наивного «слева направо».
