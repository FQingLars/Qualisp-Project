# Глава 12. Макросы

Макросы — главная суперспособность Лиспа, и Qualisp здесь не исключение. Макрос — это **функция, которая получает код как данные и возвращает новый код**, выполняющаяся на этапе макрораскрытия, до исполнения программы.

## 12.1 Почему это возможно

Qualisp гомоиконен: программа — это S-выражения, те же структуры данных, что и списки в вашей программе. `(defmacro ...)` сохраняет замыкание макроса в stable-память (root scope) — макросы доступны, расширяемы и интроспектируемы всё время работы (гл. 5).

```lisp
'(+ 1 2)              ;; данные: список из 3 элементов
(eval '(+ 1 2))       ;; → 3: данные исполнены как код
(macroexpand '(when x y))   ;; интроспекция раскрытия (§12.13)
```

> 🐍 **Python-аналогия.** Ближайшие аналоги в Python — декораторы, метаклассы и `ast`-модуль. Но декоратор получает уже *готовый объект-функцию*, а макрос получает *синтаксис* и может сделать из него что угодно. Это разница между «переименовать главы готовой книги» и «написать книгу заново по плану».

## 12.2 defmacro

```lisp
;; Макрос unless: исполняет тело, если условие ложно
(defmacro unless (cond body)
  `(if ,cond nil ,body))

(unless (= 1 2) (print "1 не равен 2"))
```

- `` ` `` (backquote) — **шаблон**: почти-цитата с дырками.
- `,` — вставка значения (unquote).
- `,@` — вставка списка «россыпью» (splice).

> 🐍 Аналог — f-строки для кода: `` `(if ,cond nil ,body) `` ≈ `f"if {cond}: None else {body}"`, только это не текст, а готовое AST.

Реализация: `Interpreter::eval_cons` проверяет, не является ли голова cons-ячейки макросом через `MacroExpander::expand` (`src/macros/expander.cpp`). Если да — рекурсивно раскрывает до тех пор, пока не получится код, который уже не макрос.

### Контракт тела макроса: возвращается **форма**

Тело макроса исполняется, и возвращённое значение — это **код, который затем исполнится**. Если вернуть не форму, а значение, интерпретатор попытается исполнить это значение — это правила Common Lisp, а не побочный эффект:

| тело | вызов | что получится |
|---|---|---|
| `(cons a nil)` | `(m 1)` | ошибка вызова: раскрытие `(1)` пытаются применить |
| `(list 'quote a)` | `(m 1)` | `1` — раскрытие `(quote 1)` исполняется |
| `` `(+ ,a 1) `` | `(m 1)` | `2` — канонический идиом |

Канонический идиом — backquote: он строит форму, а не вычисляет её.

### Backquote: unquote и splice

Для backquote подформа — обычный список, и **unquote внутри цитаты раскрывается**:

```lisp
(defmacro k (a) `(quote ,a))
(k 7)          ;; → 7
```

То есть `` `(quote ,a) `` — это форма, которая вычисляется в `7`, а не «цитата, внутри которой запятая лежит мёртвым грузом».

Splice `,@` разворачивает список в место, где стоит:

```lisp
(defmacro my-when (test . body)
  `(if ,test (progn ,@body) nil))
```

Макросы **не гигиеничны** (как в Common Lisp): если макрос вводит временную переменную, её имя может конфликтовать с переменной пользователя — лечится `gensym` (§12.5).

## 12.3 Вариативные макросы: dotted-параметры

Точка в списке параметров = «всё остальное» (rest-аргументы):

```lisp
(defmacro my-when (test . body)
  `(if ,test (progn ,@body) nil))

(my-when (> x 0)
  (print "positive")
  (print "indeed"))
```

> 🐍 `def macro(*args, *body)` — то же самое.

## 12.4 Реальный пример из stdlib: `let*` через `let`

Из `stdlib/core.qlsp` — `let*` (последовательные биндинги) реализован макросом над `let`:

```lisp
(defmacro let* (bindings . body)
  (if (null bindings)
    `(progn ,@body)
    `(let (,(car bindings))
       (let* ,(cdr bindings) ,@body))))
```

Читается: «пустые биндинги → `progn`; иначе возьми первый биндинг в `let` и рекурсивно разверни остальные».

> 🐍 В Python аналогичное «раскрытие» пишут вручную или генерируют через `ast` — в Qualisp это четыре строки.

## 12.5 gensym: гигиена

Если макрос вводит временные переменные, они могут конфликтовать с переменными пользователя. `gensym` генерирует уникальный символ:

```lisp
(defmacro swap (a b)
  (let ((tmp (gensym "tmp")))
    `(let ((,tmp ,a))
       (setq ,a ,b)
       (setq ,b ,tmp))))
```

`gensym` возвращает символ с уникальным именем (например, `#:tmp0`), которого нет ни в одном биндинге.

> 🐍 Проблема та же, что у макросов в C (`#define SWAP(a,b)` и `SWAP(x, tmp)`); `gensym` — решение уровня языка.

## 12.6 Модуль `errors`: макрос `try`

Макросы — обычный инструмент библиотек. Модуль `ERRORS` реализует `try/catch` макросом:

```lisp
(import ERRORS)
(try (risky-operation)
  (e (print (error-msg e))))
```

Из `stdlib/errors.qlsp`:

```lisp
(defmacro try (body catch-clause)
  (let ((err-sym (gensym "e")))
    `(let ((,err-sym (catch-error (lambda () ,body))))
       (if ,err-sym
         (let ((,(car catch-clause) ,err-sym))
           ,@(cdr catch-clause))
         nil))))
```

Раскрытие: тело оборачивается в лямбду и вызывается через `catch-error`; если возвращается ошибка, переменная из `catch-clause` (здесь `e`) связывается с ней.

`CATCH-ERROR` — **настоящий примитив**: возвращает `((T result) | (NIL "message"))`, и stdlib-`try` сохраняет результат тела, а не только обрабатывает ошибку:

```lisp
(let ((res (catch-error (lambda () (* 6 7)))))
  res)          ;; → (T 42) — результат сохранён
```

## 12.7 Compiler macros: оптимизационные макросы

`(define-compiler-macro name ...)` — макрос, который работает **на этапе макрораскрытия** и может заменить вызов функции на оптимизированную форму, например склеить константы. Реализовано в `MacroExpander::defcompiler_macro` (`src/macros/expander.cpp`).

```lisp
(define-compiler-macro square (x)
  (if (constantp x)              ;; если аргумент — константа
    (* x x)                      ;; посчитать при раскрытии (x — литерал)
    `(* ,x ,x)))
```

`constantp` — примитив `prim_constantp`, проверяет «литерал ли» (`is_fixnum()`, `is_flonum()`, `is_nil()`, `is_string()`, `is_symbol()`).

> ⚠️ **Инвалидация JIT.** Любое (пере)определение `defmacro` или `define-compiler-macro` повышает эпоху и **сбрасывает все JIT-страницы** (`jit::invalidate_all`): раскрытие могло быть «запечено» в скомпилированные тела. Страницы восстанавливаются лениво из master-копий (подробности — гл. 20).

> 🐍 Это то, что делают `@lru_cache`-хитрости или frTpl-оптимизации, только на уровне компилятора: `(constantp x)` ≈ проверка «литерал ли».

## 12.8 Локальные макросы

Механизм локальных макросов живёт в расширителе: `MacroExpander::push_local_env` / `pop_local_env` (реестр локальных макросов, видимых только в своём протяжении). Их отличие от глобальных — область видимости: локальное определение не инвалидирует глобальные макросы и не попадает в глобальный реестр.

> ⚠️ Перед использованием проверьте, что форма локальных макросов связана с интерпретатором в вашей сборке: в выпущенной сборке вызов `macrolet` даёт «Unbound variable: MACROLET». Уровень C++ готов (окружение макросов входит и в инвалидацию кэша раскрытия), но это не то же самое, что доступная из Lisp форма.

## 12.9 Пользовательские reader-макросы

`(SET-READER-MACRO ...)` позволяет расширять сам ридер — свои литеральные синтаксисы (как `#(...)` для векторов). Примитив `prim_set_reader_macro` (`src/eval/interpreter.cpp`).

## 12.10 Гомоиконные примитивы: EVAL, READ-FROM-STRING, FUNCTION-BODY

В Qualisp код — данные, и в рантайме доступны примитивы для работы с этой эквивалентностью напрямую (без обхода через строки).

### `EVAL` — вычислить S-выражение

```lisp
(eval '(+ 1 2))                     ; → 3
(eval (read-from-string "(* 6 7)"))  ; → 42
```

Используется в **meta-circular interpreter**'ах и DSL-движках. В отличие от `eval("print('hi')")` в Python, здесь нет строкового прохода — `eval` работает с cons-структурой напрямую.

### `READ-FROM-STRING` / `WRITE-TO-STRING`

```lisp
(read-from-string "(+ 1 2)")     ; → (+ 1 2) — cons-структура
(write-to-string '(+ 1 2))       ; → "(+ 1 2)" — строка для логов
```

Круговой путь: `(read-from-string (write-to-string expr)) ≡ expr` (с точностью до quote).

### Макросы + `EVAL` = `DEFEVAL`

```lisp
;; Свой eval для кастомного AST (например, арифметика в polish notation)
(defvar ast '(+ 1 (* 2 3)))

;; Прямой eval: работает
(eval ast)                        ; → 7

;; Свой интерпретатор: для нестандартных форм
(defun my-eval (expr)
  (if (atom expr) expr
    (let ((op (car expr)) (args (cdr expr)))
      (case op
        (+ (reduce + (map my-eval args)))
        (* (reduce * (map my-eval args)))))))

(my-eval ast)                     ; → 7
```

### `FUNCTION-BODY` — AST-инспекция

```lisp
(defun square (x) (* x x))
(function-body 'square)           ; → ((* X X))   (cons-структура)

;; Можно трансформировать
(defun negate-body (fn-sym)
  `(\ ,(function-params fn-sym)
     (- ,@(function-body fn-sym))))

(eval (negate-body 'square))      ; → замыкание, делающее (- (* x x))
```

> 🐍 В Python аналог — `inspect.getsource(f)` возвращает **исходный текст**, который нужно парсить. В Qualisp — структурное представление, готовое к трансформации.

### Полный пример: REPL внутри REPL

```lisp
(defun mini-repl ()
  (while t
    (print "mini> ")
    (let ((line (read-line)))
      (if (equal line "q") nil
        (let ((result (eval (read-from-string line))))
          (print (strcat "=> " (write-to-string result))))))))
```

`mini-repl` использует `READ-FROM-STRING` (вместо чтения из STDIN вручную) и `EVAL`. В Python это было бы `eval(input("> "))`.

## 12.11 Макро-слоты и EVAL-SANDBOXED

### Макро-слоты политики

**Слот** — именованная макро-точка, хранящая одну Qualisp-форму (клон в stable scope). Вызов `(name args...)` расширяется в operator позиции; раскрытие происходит после host-макросов; незаданный слот — обычная unbound-переменная.

```lisp
(slot-set 'strategy '(lambda (x) (* x 2)))  ;; записать форму (clone в stable)
(slot-form 'strategy)                        ;; → форма | nil
(slot-p 'strategy)                           ;; → T | nil
(strategy 21)                                ;; → 42: (форма 21) — операторная позиция
```

- `SLOT-SET` переобучает слот **заменой формы** — host-код не меняется. Так агент переписывает собственное поведение без перекомпиляции программы.
- Слоты — точка стыка с NS-IF: роутер маршрутизирует по слотам (`ns-route`/`ns-route-sample`/`ns-route-index`, гл. 14).

### `EVAL-SANDBOXED` — безопасное исполнение сгенерированного кода

```lisp
(eval-sandboxed form steps depth alloc)
```

- **Бюджеты**: шаги eval, глубина рекурсии, рост cons — исчерпание = ошибка, а не зависание.
- **Запреты**: `DEF*`-формы, файловые/сетевые/sleep-примитивы, кэш компиляции HLO, dashboard/log-стоки, `setq` в глобальные биндинги. Запрещённая форма даёт внятную ошибку, например `sandbox: DEFVAR is denied`.
- **Разрешено**: чтение глобалов (веса модели); вложенный `EVAL` наследует песочницу.

> 🐍 Грубый аналог — ограничение `eval` через `RestrictedPython`/`ast`-валидацию, только бюджеты (шаги/глубина/память) встроены в сам интерпретатор, а не эмулируются на уровне исходника.

Пара «слот + песочница» — базовый цикл NS-RL-агента (blackit): агент собирает код текстом из DSL-макросов → `READ-FROM-STRING` → слот → песочница; награда — доля зелёных проверок (`examples/nsrl_coder.qlsp`, гл. 14).

## 12.12 Правила хорошего стиля

1. **Функции по умолчанию, макросы по необходимости.** Макрос — если нужен ленивый аргумент, новая синтаксическая форма или вычисление на этапе раскрытия.
2. Макрос должен раскрыться в **идиоматичный код** — сначала убедитесь, что `MACROEXPAND` на вашем билнарнике действительно раскрывает (см. §12.13), потом проверяйте раскрытие через неё.
3. Временные символы — только через `gensym`.
4. Помните: аргументы макроса вычисляются **каждый раз при подстановке** — `(unless expensive-call ...)` вызовет `expensive-call` столько раз, сколько вставили.
5. Тело макроса возвращает **форму** (см. §12.2) — это главный источник «странного» поведения макросов.

## 12.13 Что есть в Qualisp: macroexpand

### Кэш раскрытия

`MacroExpander` кэширует раскрытие на уникальную форму-источник: без кэша дерево раскрытия перестраивается заново на каждой оценке, и любой макрос в цикле даёт линейную утечку scratch. Ключ — адрес формы, поэтому запись держит root-клон источника, а попадание проверяется по контенту (у `EVAL` адреса scratch-форм перерабатываются).

Два инварианта кэша:

- **Раскрытие самодостаточно.** `expand()` чеканит спайн в root, но листья (атомы вывода макроса) указывают в scratch-ячейки, которые умирают на границе формы; кэш хранит глубокий клон раскрытия, иначе пул перерабатывает листья и раскрытие гниёт.
- **Инвалидация.** `defmacro`/`define-compiler-macro`/локальные макросы и `SLOT-SET` чистят кэш целиком; внутри локального протяжения макросов кэш не используется вовсе (область видимости локальная).

Контракт чистоты: раскрытие — чистая функция от формы. Макрос, зависящий от внешнего состояния (RNG, трассировка), кэшируется один раз — это документированное ограничение, а не баг.

Третий инвариант, выученный на ASan-свипе: **кэш не может владеть памятью, которую читатель берёт без ссылки**. Форма может вызвать инвалидацию кэша изнутри той самой формы, чьё раскрытие лежит в кэше, — освобождение на месте даёт use-after-free. Поэтому записи кэша паркуются и умирают на границе формы. Альтернатива — клон-на-хит, но он дороже.

### `MACROEXPAND-1` и `MACROEXPAND`

Специальные формы интроспекции раскрытия: они принимают форму и возвращают форму — по замыслу это результат одного шага раскрытия (`MACROEXPAND-1`) и раскрытие до не-макроса (`MACROEXPAND`).

```lisp
(macroexpand-1 '(let* ((a 1) (b 2)) (+ a b)))
(macroexpand   '(let* ((a 1) (b 2)) (+ a b)))
```

> ⚠️ **Проверьте форму на своём билнарнике, прежде чем опираться на неё.** В выпущенной сборке обе формы возвращают переданный аргумент без раскрытия — результат совпадает с исходной формой. Проверка — одна строка:
>
> ```lisp
> (print (equal (macroexpand-1 '(let* ((a 1) (b 2)) (+ a b)))
>                '(let* ((a 1) (b 2)) (+ a b))))
> ;; T — форма не раскрыта; NIL — раскрыта
> ```

## 12.14 Имена символов: Lisp-стиль

Символы в Qualisp **регистронезависимы** и пишутся в kebab-case; примитивы — заглавными, через дефис, с префиксом `TENSOR-` для доступа к тензорам:

| Правило | Как выглядит | Примеры |
|---|---|---|
| Символы регистронезависимы | `print` = `PRINT` | это Lisp, не двойной API |
| Kebab-case, верхний регистр у примитивов | `WRITE-TO-STRING`, `TENSOR-ITEM` | |
| Доступ к тензору несёт `TENSOR-` | `TENSOR-SHAPE`, `TENSOR-DTYPE` | `(shape t)` не существует |

`INTERN` приводит имя к правилу читателя, поэтому `(intern "print")` — тот же символ, что `PRINT`, и код, собранный как данные, исполним.

Оговорка про регистр: из-за регистронезависимости лисп-обёртка с именем примитива **затеняет сам примитив** — `(defun sample (x) (SAMPLE x))` вызовет саму себя. Это не ошибка, а свойство Lisp; в коде на Qualisp примитивы пишутся заглавными, а свои функции именуют так, чтобы не совпадать.
