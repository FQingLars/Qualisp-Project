# Глава 22. Tablet: типизированная таблица в stdlib

В stdlib есть **Tablet** — компактный модуль табличных данных: `src/stdlib/tablet.qlsp`, 176 строк чистого Qualisp поверх примитивов (гл. 15). Модель честно ограничена: «числовая таблица одного dtype» — имена колонок `(:list :symbol)` плюс один двумерный тензор `(:tensor :f32 (_ _))`. Гетерогенных колонок нет: в языке нет сумм-типов и `:any`, поэтому колонки разных dtype нельзя положить в один типизированный список.

> 🐍 **Python-аналогия.** `import TABLET` ≈ очень компактный `import pandas as pd`: `tablet` ≈ `DataFrame`, `column` ≈ `df["col"]`, `select-columns` ≈ `df[[...]]`, `where` ≈ `df[mask]`, `sort-by` ≈ `sort_values`. Но `groupby`, `merge`, CSV/JSON, NA-дисциплина и categorical-аксессоры из pandas здесь **не реализованы** — ниже по разделам описано, что есть на самом деле.

API — псевдо-ООП: `deftrait tablet-ops`, `defstruct tablet` с трейтом и `impl tablet` с методами. Диспетч — по тегу первого аргумента, без vtable. Модуль экспортирует `(export tablet make-tablet)` — структуру и конструктор; **методы не являются отдельными экспортами**, они приходят вместе с тегом и вызываются как обычные функции `(nrows tab)`, `(column tab 'age)` и т. п.

## 22.1 Контракт детерминизма

Единственное жёсткое правило модуля: **результат зависит только от входа**. Никаких unordered-структур на путях вывода; порядок колонок — порядок вставки; `select-columns` возвращает колонки **в запрошенном порядке**; `sort-by` переставляет индексы через общий примитив `sort` с компаратором по значениям колонки, а сами данные не мутирует; `where` берёт **первый** совпавший индекс, а остальные добавляет от последней строки назад к первой, то есть порядок строк после фильтрации — `first`, затем убывающие индексы (§22.3). Методы чистые: `where`/`head`/`row`/`column` возвращают **новые** тензоры — `t-rows`, `t-column`, `t-select-rows` в v1 копируют. Исходная таблица после любой операции неизменна.

Иммутабельность — не удобство, а следствие модели: слот `data` держит один `:f32`-тензор, а `t-*` создают копии. Двойной прогон на одних и тех же данных даёт ту же таблицу — именно это проверяют тесты.

## 22.2 Быстрый старт

Конструктор принимает список имён-символов и 2-D `:f32`-тензор; число имён обязано совпадать с числом колонок `(t-shape data)`:

```lisp
(import TABLET)
(defvar tab ((make-tablet (list 'city 'age)
                          (tensor ((1.0 33.0) (2.0 25.0) (3.0 41.0)))) . (:struct tablet)))
(print (nrows tab))            ;; → 3
(print (ncols tab))            ;; → 2
(print (column-names tab))     ;; → (CITY AGE)
(print (column tab 'age))      ;; → #<tensor>
(print (row tab 1))            ;; → #<tensor>  (форма (1 C))
(print (head tab 2))           ;; → #<TABLET::TABLET (CITY AGE) 2 2 #<tensor>>
```

Проверено бинарём 0.19.20. Принтер структур печатает `#<tag ...>` (гл. 3, 15), поэтому `head` показывает приватный тег модуля с префиксом `TABLET::`, а не `#<struct>`. Методы работают как обычные функции `(nrows tab)`, `(column tab 'age)` и т. д. — диспетч по тегу первого аргумента; все примеры ниже проверены на этом же бинаре. Имена — именно символы: `(list 'a 'b 'c)`, а не `'(a b c)` — цитата даёт `:syntax`, а не `(:list :symbol)`. Числа в тензоре пишутся с точностью `f32`: `(tensor ((1.0 2.0) (3.0 4.0)))`.

`make-tablet` кэширует `rows`/`cols` в слотах, чтобы методы не дёргали `t-shape` на каждый вызов. При несовпадении числа имён и колонок — `error: tablet: number of column names does not match data columns`.

## 22.3 Выбор и фильтрация

Реальные «выборки»:

```lisp
(column tab 'age)                       ;; ≈ df["age"] — 1-D :f32
(row tab 1)                             ;; ≈ df.iloc[1] — 2-D формы (1 C)
(select-columns tab (list 'age 'city))  ;; ≈ df[["age","city"]] — порядок запрошенный
(where tab (tensor (1.0 0.0 1.0)))      ;; ≈ df[mask] — строки с маской > 0.0
```

- `column` ищет имя через `name-index`; нет имени → `error: tablet: unknown column name`.
- `row` проверяет границы; выход → `error: tablet: row index out of bounds`.
- `select-columns` — transpose → `t-select-rows` → transpose, без новых примитивов; неизвестное имя в списке → `error: tablet: unknown column name`.
- `where` принимает **1-D :f32-маску по строкам** и проверяет её длину заранее (`error: tablet: where mask length does not match rows`) — иначе короткая маска молча прочитала бы не те строки, а длинная упала бы в ядре без контекста таблицы.
- `where` без единого положительного значения — **ошибка**, а не пустая таблица: `error: tablet: where mask has no positive entries`. Нулевой таблиц в модели нет. `head 0`, напротив, разрешён — это явный срез «ни одной строки».

Проверено бинарём: `(nrows (where tab (tensor (1.0 0.0))))` → `1`; `(column-names (select-columns tab (list 'age 'city)))` → `(AGE CITY)`.

Порядок строк после `where` — **не исходный**. `match-indices` сначала находит `first` (первый индекс с маской > 0.0), а `rest-matches` спускается от последней строки вниз до `first + 1`. Для маски `(0 1 1 1 0)` на таблице со значениями `(1 2 3 4 5)` результат — `(2 4 3)`, то есть индексы `(1 3 2)`: первый матч, затем остальные в убывающем порядке. Это наблюдаемое поведение реализации, а не ошибка в примере — если важен порядок строк, учитывайте его.

## 22.4 Сортировка и уникальность

`(sort-by tab 'age)` возвращает новую таблицу со строками в порядке возрастания значений колонки `age`. Реализация — сортировка **списка индексов** общим `sort` с компаратором `(lambda ((a . :fixnum) (b . :fixnum)) (< (tref column a) (tref column b)))`, затем `t-select-rows` по этому порядку. Данные самой колонки не меняются; аргументов `desc`/multi-key нет — компаратор можно заменить только правкой модуля.

Проверено: `(column (sort-by tab 'age) 'age)` возвращает отсортированную колонку. Отдельной функции «уникальные значения» в модуле нет — см. §22.11.

## 22.5 NA-дисциплина

NA в Tablet **отсутствует как понятие**. Колонка — тензор `(:tensor :f32 (_))`, а тензор :f32 не может содержать `nil`: `nil` в языке — это ложь, пустой список и «нет значения» для `(:option T)`, но не элемент числового тензора. Поэтому:

- нет `fillna`/`dropna`/`isna` и dtype `empty`;
- «пропуск» можно закодировать только числом (например, `0.0` или `-1.0`) по соглашению вызывающего;
- маска `where` — числовая: строка отбирается, если `tref mask i > 0.0`, а не если «не nil».

Единственное место, где `nil` встречается в API, — внутренние хелперы `rest-matches` инициализируют хвост списка индексов как `(:option (:list :fixnum))`; наружу `nil` не попадает: `match-indices` всегда строит **непустой** список через `cons first …`.

> 🐍 **Python-аналогия.** Если в pandas `NaN` — полноценное значение со своими правилами сравнения и `dropna`, то здесь честно говорят: модель типизирована, `nil` несовместим с `:f32`, поэтому NA-дисциплины просто нет.

## 22.6 Группировка и агрегации

`groupby`/`tgroup-agg` в модуле **нет**. Вместо этого таблица даёт доступ к колонке как к тензору, и агрегация делается стандартными примитивами:

```lisp
(tsum (column tab 'age))     ;; → 99.0   сумма по колонке
(tmean (column tab 'age))    ;; → 33.0   среднее
(tmax (column tab 'age))     ;; → 41.0
(argmax (column tab 'age))   ;; → 2      индекс максимума
```

Проверено бинарём. Если нужна агрегация по подмножеству строк — сначала `where` с явной маской, потом `column` и редукция. Схемы «колонка + функция», мультиключа и сортировки ключей groupby в текущей реализации нет; порядок строк после `where` — первый матч, затем индексы в убывающем порядке (§22.3).

## 22.7 Соединения

`merge`/`join`/`append` в Tablet **нет**: модуль не знает ничего о двух таблицах сразу. Доступные операции над одной таблицей — `select-columns` (проекция колонок), `row`/`head`/`where` (выбор строк), `sort-by` (перестановка строк). Объединение двух таблиц по ключу пришлось бы собирать вручную из `column`-тензоров и списков индексов — готового API для этого нет.

> 🐍 **Python-аналогия.** `pd.merge(..., how='left')` и её режимы сохранения порядка здесь не представлены; ближайшее, что есть, — `select-columns` для перестановки/выбора колонок в заданном порядке.

## 22.8 Типы, категории, строки

Типов в таблице ровно один: `:f32`. `column-names` — список символов (`(:list :symbol)`), при печати они uppercase. Строковых колонок, `astype`, `categorical` и строковых аксессоров (`tstr-upper`, `tstr-contains`) нет — они потребовали бы `:string`-колонок, а модель этого не допускает. Нет и `tiso-format`: колонок даты-времени в таблице нет. Сам модуль `datetime` в 0.19.20 есть (`utc-datetime`, `epoch->utc`/`utc->epoch`, `iso-utc`, `parse-iso-utc`, `seconds->hms`, таймеры и примитивы `now`/`now-ms`/`monotonic-ns`) — но это обычные значения вне таблицы; результат надо держать в обычном списке Qualisp или строке.

Если нужны строки — они живут вне таблицы, в обычных списках Qualisp; таблица предназначена для числовых данных и напрямую стыкуется с ML-кодом через `column`.

## 22.9 IO: CSV, JSON, тензоры

Модуль `tablet` **не содержит** CSV/JSON-функций — ни `tcsv-read`, ни `tjson-rows`. Для ввода-вывода есть модуль `io` (гл. 16): `read-file`/`write-file`/`append-file`, `file-exists?`, потоковые `open-file`/`read-line`/`read-all`/`write-string`/`write-line`/`close-file`, макрос `with-file`, а также `read-lines`/`write-lines` в модуле. Построить таблицу из CSV можно только вручную: прочитать строки, распарсить числа, собрать `:f32`-тензор и вызвать `make-tablet`.

```lisp
(column tab 'age)             ;; → :f32-тензор — сразу можно в defgraph/grad!
```

Именно для этого таблица и сделана: её колонка — уже тензор, без конверсии.

## 22.10 Статистика и окна

Оконных функций (`rolling`/`expanding`), `shift`/`diff`, `cumsum`/`cummax`, `rank`, `cov`/`corr` в модуле нет. Доступные сокращения — те, что определены для тензоров: `tsum`, `tmean`, `tmax`, `argmax`, применённые к `(column tab 'name)` (примеры в §22.6). Для «окна» можно вручную выделить поддиапазон строк через `where` с маской и посчитать ту же редукцию; готового `trolling` нет.

## 22.11 Чего в Tablet нет (честно)

- **Гетерогенные колонки** — только `:f32`; нет `:string`/`:int`/`:bool`-колонок и сумм-типов.
- **NA** — только числа; `nil` не может быть ячейкой (§22.5).
- **groupby/merge**, `unique`/`value-counts`, `desc`/multi-key sorting — нет (§22.4, §22.6, §22.7).
- **CSV/JSON** — только `io`, ручная сборка тензора (§22.9).
- **Оконные/статистические функции** — только базовые редукции над `column` (§22.10).
- **Категории/строковые аксессоры/колонки datetime** — нет в таблице (§22.8); модуль `datetime` при этом есть и работает вне неё.
- **Форма `(N C)` в слотах** — можно записать только wildcard `(_ _)`; конкретную форму даёт `t-shape` в рантайме.
- **Нулевые таблицы** — `where` без совпадений бросает ошибку; `head 0` разрешён.

Тесты модуля — `src/stdlib_tablet_test.zig` (23 теста): конструктор, каждая экспортируемая функция/метод (`nrows`, `ncols`, `column-names`, `column`, `row`, `head`, `where`, `select-columns`, `sort-by`), границы/ошибки, неизменяемость данных. Тесты на каждую экспортируемую функцию stdlib-модулей — часть стандарта 0.19.20. Отдельного `tests/tablet.qlsp` в репозитории нет.
