# Глава 21. Образы: мир как данные

`save-image`/`load-image` — снапшот пользовательского мира Qualisp в файл и обратно. Это логическое завершение «инварианта одной формы»: раз S-выражение — единственная авторитетная форма программы, то и весь пользовательский мир — биндинги, функции, замыкания, макросы, структуры, тензоры — можно записать как данные и загрузить в другом процессе. Формат называется **QSRD**; файлы образов традиционно имеют расширение `.qimg`, но внутри — та же магия `QSRD`, что и у файлов весов `.qsrd`. Старого формата с магией `QLSI` в реализации нет.

> 🐍 **Python-аналогия.** Как `pickle` словаря `globals()` + `torch.save` весов в одном флаконе — только в Qualisp это один примитив над одним графом значений, плюс отдельный примитив для весов. Ближайшая лисп-родня — `sb-ext:save-lisp-and-die` в SBCL. Разница с `pickle` принципиальная: в образ **не пишется машинный код** — только формы, из которых он пересобирается.

Релиз 0.19.16 различает два уровня сохранения:

- **QSRD v1** (`save-image`/`load-image`) — пользовательский мир: формы определений и снимок `defvar`-значений;
- **QSRD Q2** (`save-weights`/`load-weights`) — только параметры модели и произвольное состояние.

## 21.1 Быстрый старт

```lisp
(defvar x (42 . :fixnum))
(save-image "/tmp/world.qimg")
(setq x 0)
(load-image "/tmp/world.qimg")
(print x)                     ;; → 42 — мир откатился к моменту снимка
```

Проверено бинарём 0.19.16: файл 199 байт, первый вызов печатает `42`, `load-image` возвращает `nil`. Кстати, `(save-image)` без пути даёт `error: BadImage`, а форм `qsrd-save`/`qsrd-load` в языке нет (unknown function) — сохранение идёт только через `save-image`/`save-weights`.

Более содержательный пример: функция, замыкание, тензор и структура переезжают целиком.

```lisp
(defvar counter (0 . :fixnum))
(defun bump ((n . :fixnum))
  (setq counter (+ counter n))
  (counter . :fixnum))
(print (bump 5))                                  ;; → 5
(defvar weights ((tensor ((0.5 0.25))) . (:tensor :f32 (1 2))))
(defstruct pt ((x . :fixnum) (y . :fixnum)))
(defvar p ((pt 3 4) . (:struct pt)))

(save-image "/tmp/book21.qimg")
(setq counter 0)
(setq p (pt 0 0))

(load-image "/tmp/book21.qimg")
(print counter)                                   ;; → 5 (не 0!)
(print (bump 3))                                  ;; → 8 — мир продолжается с момента снимка
(print p)                                         ;; → #<PT 3 4>
```

Файл тут ~810 байт (проверено бинарём 0.19.16). Принтер структур печатает `#<tag ...>` вместо `#<struct>` (гл. 3, 15), поэтому `pt` выводится как `#<PT 3 4>`. Стандартная библиотека в образ **не входит** — поэтому размер маленький и не зависит от числа загруженных модулей.

**Спины списков.** Энкодер и декодер проходят cdr-спайн списка итеративно, а не рекурсивно: длинный список не кладёт хвост на стек. Каждая ячейка спайна регистрируется в memo-таблице, общий и циклический хвост кодируется обратной ссылкой. Общие и циклические `cons`/`struct`/`result` кодируются через `ref`; идентичность сохраняется.

## 21.2 Формат QSRD

Файл обрата — бинарный QSRD, little-endian, versioned:

```
0    4   "QSRD"
4    2   major            // несовместимое изменение кодирования значений
6    2   minor            // добавленные секции; читатель обязан их пропускать
8    4   flags            // bit0: little-endian
12   4   section_count
16   …   section_count × { u32 kind, u32 offset, u32 length, u32 crc32 }
…        payload секций
```

Реальные первые байты файла из примера §21.1 (hex-дамп):

```text
00000000: 5153 5244 0100 0000 0100 0000 0400 0000  QSRD............
00000010: 0100 0000 5000 0000 1700 0000 22e3 9db7  ....P......."...
```

Здесь major=1, minor=0, flags=1 (little-endian), `section_count=4`; дальше таблица секций со смещениями, длинами и crc32. Проверено бинарём 0.19.16: файл из §21.1 — те же 199 байт и тот же hex-дамп, а `save-weights` пишет три секции (`meta`, `symbols`, `model`) с тем же заголовком `meta` (crc `22e3 9db7`). Формат QSRD и кодирование значений именно такие, как описано ниже.

| kind | имя | статус | содержимое |
|---|---|---|---|
| 1 | `meta` | есть | генератор (`qualisp-zig`), major/minor |
| 2 | `symbols` | есть | `u32 count`, затем `u32 len + байты` |
| 3 | `forms` | есть | `u32 count`, затем формы определений по порядку |
| 4 | `data` | есть | `u32 count`, затем `(u32 symbol-index, value)` |
| 5 | `model` | есть (Q2) | `u32 count`, затем `(symbol-index, tensor)` для каждого параметра, затем одно значение состояния |

- **crc32 на секцию.** Обрезанный или исправленный файл отвергается с `CorruptImage`, а не читается как данные.
- **Неизвестные секции пропускаются** — это механизм minor-совместимости.
- **Символы пишутся один раз** в `symbols`; значения ссылаются по `u32`-индексу. Индексы файла не связаны с рантайм-`SymbolId`.
- **Значения** — поток тегов `nil/t/int/float/char/symbol/string/cons/tensor/struct/result/ref/func`. `ref` даёт общие и циклические структуры; id сквозные на весь файл.
- Функции: именованные — по имени глобала; замыкания — мастер-форма лямбды + имена захватов + значения env, восстановление через `(let ((capture value)…) lambda)`. Placeholder сохраняет идентичность ссылок при вложенных замыканиях.

Отдельный читатель `tools/qsrd` на Rust (`inspect`, `verify`, `cat`, `params`, `symbols`, `extract`) и конформанс-корпус `tools/qsrd/corpus/` (`basic.qlsp`, `weights.qlsp`) сверяют вывод с эталоном. В снапшоте исходников читателя нет — есть только корпус; поэтому здесь описан формат, а не код читателя.

> ⚠️ **Образ и нативный код.** В образе есть `defgraph`/`defuse`, но нет скомпилированных HLO-кернелов и JIT-страниц: при `load-image` формы перевыполняются и граф/кэш пересобираются. Результат загруженной программы совпадает с результатом исходной — это и есть проверка round-trip.

### Q2: веса отдельно от кода

```lisp
(defvar w ((param (tensor ((1.0 2.0) (3.0 4.0)))) . (:tensor :f32 (2 2))))
(defvar b ((param (tensor (0.5))) . (:tensor :f32 (1))))
(save-weights "/tmp/w.qsrd" (list 7 8))
(print (load-weights "/tmp/w.qsrd"))     ;; → (7 8)
```

Проверено бинарём 0.19.16: файл из трёх секций (`meta`, `symbols`, `model`), `load-weights` возвращает состояние как `:syntax` — здесь `(7 8)`.

- `(save-weights path [state])` пишет QSRD только с `meta`, `symbols`, `model`. Параметры — стабильные тензоры с `requires_grad` (то есть `param`), в порядке `SymbolId`. `state` — произвольные данные (шаг, lr, seed); схему формат не навязывает.
- `(load-weights path)` заменяет одноимённые биндинги и возвращает состояние. Сначала валидируются **все** параметры: неизвестное имя или несовпадение dtype/формы — ошибка без частичного применения. Замыкания в состоянии дают `UnsupportedValue`: на момент загрузки нет программы, относительно которой их разрешать.

## 21.3 Что сериализуется

- глобальные `defvar`-значения (числа, строки, символы, списки, структуры, `(:result T)`, тензоры);
- `defun`/`defgraph`/`defuse`/`defmacro` — как **мастер-формы**, не как машинный код;
- определения `defstruct`/`deftrait`/`impl` — включая структуры с именами вроде `error`, `call-frame` или `utc-datetime` — и формы `ffi-load`/`ffi-defun`; встроенные модули `error` и `datetime` — часть stdlib, в образ не пишутся и остаются доступными после `load-image`;
- тензоры: dtype + shape + сырые байты в world;
- списки, строки, символы (по именам), char/bool, результат;
- общие и циклические cons/struct/result через memo/`ref`;
- `Func`: именованные функции — по имени глобального биндинга; замыкания — мастер-форма лямбды + имена захватов + значения env, восстанавливаются через `(let ((capture value)…) lambda)`.

Принтер структур печатает `#<tag ...>` (гл. 3, 15): структура ошибки — `#<ERROR::ERROR "42" 42 (…) USER>`, кадр — `#<ERROR::CALL-FRAME LAMBDA "<repl>" 1 "(THROW 42)">`, дата из `datetime` — `#<DATETIME::UTC-DATETIME 1970 1 1 0 0 0>`. Пользовательские структуры с такими тегами идут в образ тем же потоком тега `struct`, что и любые другие.

## 21.4 Что не сериализуется (и почему это честно)

Нативное состояние в образ **не пишется**. Это не потеря, а следствие архитектуры:

- JIT-страницы, скомпилированные HLO/defuse-кернелы, планы `ns-if` — производные кэши, они пересобираются из мастер-форм (план `ns-if` детерминированно выводится из формы через ROBDD);
- `future` и сырые `:ptr` → `UnsupportedValue`;
- FFI-указатели — `ffi-load`/`ffi-defun` переигрываются как формы, библиотеки должны быть доступны на машине загрузки;
- stdin/fd, потоки и внешние ресурсы — не переносятся.

`load-image` заменяет пользовательский мир по шагам:

1. чистит пользовательские биндинги/структуры/трейты/макросы;
2. заново исполняет формы из обрата (пересобирает JIT/HLO/defuse/макросы);
3. накладывает снимок `defvar`-значений.

Стандартная библиотека и её функции остаются. Ограничения: замыкания с неименованными env-слотами не восстанавливаются (такие слоты пропускаются); экзотические циклы `Func↔Env` могут не восстановиться; загрузка **не атомарна** при ошибке после начала очистки; старые world-объекты после замены живут до teardown (GC/RC нет). Снимок накладывается после форм, поэтому форма, зависящая от мутированного значения глобала, может дать иной порядок — держите это в уме при чекпоинтах.

Итого: образ — это данные и только данные; всё нативное в нём восстанавливается из формы, а не переносится бинарно.

## 21.5 Практика

- **Чекпоинт обучения.** `save-weights` после эпохи + `load-weights` в свежем процессе — те же веса и состояние оптимизатора; `save-image`, если нужно перенести ещё и пользовательские функции, макросы и структуры.
- **Дисциплина тестов.** Каждый тест делает свой `load-image` и проверяет сразу после: мир одного теста не должен течь в другой. Тесты формата — `src/image_test.zig`; конформанс — `tools/qsrd/corpus/` и `check.sh`.
- **Граница между форматами.** QSRD как поток значений — сериализация **значения** (тензора, объекта), образ — сериализация **мира** (глобального окружения целиком). `save-weights` — промежуточный вариант: только параметры плюс состояние.
- **Круговой рейс.** `save-image → (изменить мир) → load-image → сравнить поведение` — и есть основная проверка формата; бинарём проверены числа, строки, списки, тензоры, структуры, функции и замыкания.
- Форм `save-image`/`load-image` внутри песочницы нет: песочницы как языковой формы в текущей реализации тоже нет (§20.8).
