# Глава 13. Структуры и методы

Основной способ объявить собственный тип данных в Qualisp — **структура**: запись с фиксированным набором полей, методами через `IMPL` и полиморфизмом через трейты. Никакой vtable и наследования: у структуры один layout, методы диспетчатся по первому аргументу.

```lisp
(defstruct pt (x y))          ;; имя + поля
(defvar p (pt 1 2))           ;; конструктор — функция
(slot-value p 'x)             ;; → 1
(set-slot p 'x 10)            ;; запись поля
(type-of p)                   ;; → STRUCT
(print p)                     ;; → #<struct ...>
```

## 13.1 Определение и конструктор

`(defstruct name (field...))` объявляет структуру: имя и список полей. Полей может не быть вовсе — `(defstruct empty ())` создаёт структуру без полей.

Конструктор — **функция с именем структуры**; она берёт значения полей по порядку:

```lisp
(defstruct pt (x y))

(defvar p (pt 1 2))
(type-of pt)                  ;; → FUNCTION — конструктор это функция
(type-of p)                   ;; → STRUCT — значение это структура
```

Конструктор — обычная функция-значение, его можно передавать аргументом и вызывать из любого места. Контракты строгие: конструктор проверяет **число аргументов** (недостаточно или слишком много — ошибка), а чтение несуществующего поля — тоже ошибка:

```lisp
(pt 1)                        ;; ошибка: не хватает аргумента
(slot-value p 'z)             ;; ошибка: нет такого поля
```

Печать структуры — `#<struct ...>`: `(print p)` показывает отладочный вид с именем типа и полями.

> 🐍 **Python-аналогия.** Это `@dataclass` с позиционным конструктором:
> ```python
> @dataclass
> class Point:
>     x: int
>     y: int
> p = Point(1, 2); p.x
> ```
> Отдельных `make-pt`/`pt-x` не нужно: конструктор называется как структура, а доступ к полям общий — `slot-value`/`set-slot`.

## 13.2 Поля: slot-value и set-slot

```lisp
(slot-value p 'x)        ;; → 1 — чтение поля
(set-slot p 'x 10)       ;; запись поля
(slot-value p 'x)        ;; → 10
```

Имя поля — символ. `set-slot` пишет в ту же структуру, ничего не копируя; поле можно перезаписывать сколько угодно раз.

В слоте живёт обычное значение — число, список, другая структура:

```lisp
(defstruct one (v))
(slot-value (one (pt 1 2)) 'v)       ;; структура в слоте структуры
(slot-value (one (list 1 2 3)) 'v)   ;; список в слоте
```

Структуры — обычные значения языка: их можно класть в списки, передавать аргументами функций и возвращать из них; по памяти они живут по правилам HibLin (гл. 5, подробности — 13.7).

> 🐍 `slot-value`/`set-slot` ≈ `p.x` и `setattr(p, "x", 10)`, только имя поля — символ, а не атрибут-идентификатор.

## 13.3 Равенство — по идентичности

> ⚠️ **Структуры сравниваются по идентичности.** `(equal p p)` — истинно (рефлексивность), `(equal a b)` для двух разных структур — `nil`, даже при полностью одинаковых полях: у мутабельной записи равенство живёт по адресу, как `a is b` в Python. Для чисел, cons-ячеек, строк и символов `=`/`equal` сравнивают по значению (гл. 3).

## 13.4 Методы: IMPL и диспетч по первому аргументу

Методы структуры объявляются формой `IMPL` — внутри обычные `defun`, сколько угодно в одной форме. Первый аргумент метода — `self`, сама структура:

```lisp
(defstruct v2 (x y))

(IMPL v2
  (defun len2 (self)
    (+ (* (slot-value self 'x) (slot-value self 'x))
       (* (slot-value self 'y) (slot-value self 'y))))
  (defun dist (self p)
    (let ((dx (- (slot-value self 'x) (slot-value p 'x)))
          (dy (- (slot-value self 'y) (slot-value p 'y))))
      (+ (* dx dx) (* dy dy)))))

(len2 (v2 3 4))              ;; → 25
(dist (v2 0 0) (v2 3 4))     ;; → 25
```

**Диспетч идёт по первому аргументу.** Одно и то же имя метода у разных структур — это разные реализации, и выбор зависит от того, что передано первым аргументом:

```lisp
(defstruct a-st (v))
(defstruct b-st (v))

(IMPL a-st (defun show (self) (list 'a (slot-value self 'v))))
(IMPL b-st (defun show (self) (list 'b (slot-value self 'v))))

(list (show (a-st 1)) (show (b-st 2)))   ;; → ((a 1) (b 2))
```

Диспетч устроен просто: методы — обычные функции (FUNC-атомы), лежащие в таблице методов структуры, а выбор реализации идёт по указателю дескриптора первого аргумента — без поиска по имени типа.

Граничные случаи дают внятные ошибки:

- **нет метода у типа** — ошибка: `(show (pt 1 2))`, если для `pt` метод не объявлен;
- **первый аргумент не структура** — ошибка: `(show 42)`.

Метод — полноценная функция-значение: `(type-of show)` → `FUNCTION`, `(functionp show)` → `t`.

Методы мутируют `self` через `set-slot`:

```lisp
(defstruct mut (n))

(IMPL mut
  (defun bump (self)
    (set-slot self 'n (+ (slot-value self 'n) 1))
    self))

(slot-value (bump (mut 41)) 'n)   ;; → 42
```

**Переопределение метода видно живым** — сразу и уже созданным значениям: новый `IMPL` с тем же именем перекрывает старый без каких-либо дополнительных шагов.

Метод может вызывать методы своего типа — обычным вызовом, диспетч тот же:

```lisp
(IMPL v2
  (defun step (self) (twice self))
  (defun twice (self) (* (slot-value self 'x) 2)))
```

> 🐍 **Python-аналогия.** Это `functools.singledispatch` — диспетчеризация по типу первого аргумента:
> ```python
> @singledispatch
> def area(s): ...
> @area.register
> def _(s: Circle): return 3.14159 * s.r ** 2
> ```
> Только в Qualisp методы лежат в таблице самой структуры, а не в одном глобальном реестре.

## 13.5 Трейты: контракты методов

**Трейт** — именованный набор методов (имя + арность) с необязательными дефолтными телами. Структура заявляет трейты в `defstruct`, а реализует методы через `IMPL`:

```lisp
(TRAIT t-display (show self))                     ;; сигнатура: имя + арность
(TRAIT t-fallback (defun announce (self)          ;; дефолтное тело
                    (list 'default (slot-value self 'v))))

(defstruct box (v) (t-display t-fallback))        ;; структура заявляет трейты

(IMPL box (defun show (self) (list 'box (slot-value self 'v))))

(show (box 7))       ;; → (box 7) — реализация перекрывает дефолт
(announce (box 7))   ;; → (default 7) — без реализации работает дефолт
```

Трейт **не значение**, а контракт: имя трейта нельзя вызвать или передать как объект — вызов имени трейта даёт ошибку. Неизвестный трейт в списке `defstruct` — тоже ошибка.

**Цепочка диспетча** для метода трейта:

1. реализация структуры (`IMPL`);
2. дефолт последнего трейта, объявившего этот метод;
3. ошибка — «нет ни метода, ни дефолта».

**Дефолты живут глобально по имени метода: последний определённый выигрывает.** Если два трейта объявляют один метод, берётся дефолт трейта, определённого последним. Повторный `TRAIT` с тем же именем заменяет определение — и новый дефолт сразу виден уже объявленным структурам.

Арность метода фиксируется объявлением трейта: `IMPL` с чужой арностью — ошибка на определении. В рантайме проверок формы нет — цепочка диспетча это lookup и ветка, которую JIT вырезает статически (гл. 20).

Дефолтное тело получает `self` и может вызывать другие методы структуры через обычный диспетч:

```lisp
(TRAIT t-chain (defun outer (self) (inner self)) (inner self))

(defstruct x-st (v) (t-chain))

(IMPL x-st (defun inner (self) (* (slot-value self 'v) 2)))

(outer (x-st 5))   ;; → 10
```

**Полнота реализации** проверяется явно: `(trait-complete-p 'box 't-display)` → `t`, если каждый метод трейта либо реализован в `IMPL`, либо имеет дефолт, иначе — `nil`. Неизвестный трейт в проверке — ошибка.

Структура без трейтов работает как обычно: диспетч по первому аргументу не меняется, а структуры с методами переживают промоушен в глобал (`defvar`/`setq`) — методы работают и на промоушенённых значениях (гл. 5).

> 🐍 **Python-аналогия.** Трейт ≈ `typing.Protocol` или ABC: интерфейс из методов, у части методов — дефолтные реализации, класс объявляет соответствие. `(defstruct box (v) (t-display t-fallback))` ≈ `class Box(Displayable, Fallback): ...`. Но проверка полноты не встроена в создание объекта — её вызывают явно через `trait-complete-p`.

## 13.6 Типизированные поля и byte

Поля структур могут быть **типизированными**. Два синтаксиса равнозначны:

```lisp
(defstruct p (x: byte y: i64))
(defstruct q ((x : byte) (y : byte)))
```

Типы полей: `byte`, `i16`, `u16`, `i32`, `u32`, `i64`, `u64`, `f32`, `f64`, `ptr`. Поле без типа — boxed: в нём живёт обычное значение языка. Все типизированные поля живут **raw** — записи фиксированной ширины в массиве слотов, без boxed-обёртки (детали и таблица — гл. 4.5).

Typed- и boxed-поля свободно смешиваются в одной структуре:

```lisp
(defstruct mix (n: byte f: f64 s))

(let ((m (mix 7 2.5 'sym)))
  (list (slot-value m 'n) (slot-value m 'f) (slot-value m 's)))   ;; → (7 2.5 sym)
```

**byte** — сырое слово со значением `0..255`:

- **чтение — fixnum**: `(slot-value p 'x)` → `200`; байт участвует в арифметике как обычное число;
- **запись строго типизирована**: `-1`, `256`, `1.5`, строка и `nil` — ошибка-структура (гл. 15); допустимы ровно `0` и `255` как границы;
- **boxed byte-атома нет**: байт в списке — это fixnum.

Проверки едины для всех typed-полей: **конструктор проверяет типы и диапазоны**, запись через `set-slot` — тоже; неизвестный тип поля в `defstruct` — ошибка.

> 🐍 **Python-аналогия.** Раскладка и смысл полей — как у `ctypes.Structure` с полями `c_uint8`/`c_double`: сырые слова фиксированной ширины вместо boxed-объектов. Но в отличие от `ctypes`, где значение молча приводится к типу поля, Qualisp строго проверяет тип и диапазон и бросает ошибку.

## 13.7 Владение: жизнь структуры по HibLin

Структуры живут по общим правилам владения HibLin (гл. 5), с одной особенностью: массив слотов — отдельный блок памяти. Для stable-структур он берётся через `malloc`, для scratch — блоком арены; каскад смерти освобождает массив слотов и отдаёт rc-ссылки значений из полей. Практические следствия:

- **Промоушен работает.** `(setq *g* p)` переносит структуру в глобал, поля и методы продолжают работать.
- **Перезапись биндинга снимает старую структуру.** rc-каскад освобождает и ячейку, и массив слотов: счётчик `stable-cells` в `MEM-REPORT` не растёт от циклов перезаписи структур.
- **Вложенность обычная.** Структура в слоте структуры, список в слоте — rc-ссылки отдаются каскадом как у любых других значений.
- **Переопределение структуры не ломает старые значения.** Повторный `defstruct` с новым списком полей даёт новый layout новым значениям; уже созданные структуры живут по старому layout, и их поля читаются как прежде.

## 13.8 Функциональный стиль: слои вместо структур

Важно понимать идиоматику ML-кода Qualisp: **модели обычно пишут не структурами, а замыканиями** (гл. 8):

```lisp
(defvar model (linear 4 2))     ;; замыкание с параметрами внутри
(model x)
```

Структуры уместны для **данных** (датасеты, конфиги, узлы деревьев), замыкания — для **поведения** (слои, модели). Это противоположно PyTorch, где `nn.Module` — класс.

## 13.10 Известные ограничения

- **Наследования нет**: layout структуры фиксирован, полиморфизм — через трейты.
- **Trait-объекты не реализованы**: диспетч статический (таблица методов структуры → дефолт трейта), динамического dispatch по «объекту трейта» нет.
- **Трейт не значение**: его нельзя передать аргументом или вызвать.
- **Равенство структур — только по идентичности**: пополевого сравнения нет — сравнивайте поля явно.
