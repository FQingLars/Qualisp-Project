# Глава 1. Введение

## 1.1 Что такое Qualisp

**Qualisp** (до v2.8.5 — QLISP) — диалект Лиспа, спроектированный специально для машинного обучения и AI. Четыре кита языка:

1. **Нативная скорость без отдельного компилятора.** Код исполняет интерпретатор S-выражений; горячие замыкания JIT-компилируются в нативные RX-страницы методом copy-and-patch (v2.5.0), а тензорный код — через HLO-пайплайн (по мотивам XLA): трассировка в граф, оптимизации, стенсил-эмиттер — машинный код с fusion-оптимизациями, без Python-интерпретатора в горячем цикле. Всё это без промежуточного IR и без LLVM в рантайме (v2.7.0).

2. **ML — часть языка, не библиотека.** Тензоры, автоградиент, оптимизаторы, классические алгоритмы ML, аудио-обработка, нейросимвольный движок, строковые утилиты, табличный модуль Tablet — всё встроено в бинарник. 13 вшитых модулей. Не нужен `pip install torch numpy sklearn pandas`.

3. **Гомоиконность.** Код — это данные (S-выражения). С v2.3.0 в рантайме доступны `EVAL`, `READ-FROM-STRING`, `WRITE-TO-STRING`, `FUNCTIONP`, `FUNCTION-PARAMS`, `FUNCTION-BODY`, `FUNCTION-ENV`, `SYMBOL-NAME` — то есть вы можете строить и исполнять код динамически. Слои DL, факты rule engine, compiler-макросы живут в immortal-памяти и переживают reset scratch-области.

4. **Нейросимвольный слой.** Символьные развилки `NS-IF`/`NS-GRAD!` с guilt detector (v2.2.0+) маршрутизируют данные между нейросетевыми ветвями и направляют градиент только в виновный сегмент — это встроено в ядро языка, а не надстройка.

Пайплайн v2.7.0:

```text
Source → CharStream → Reader → SExpr (ConsCellPool)
  → MacroExpander (backquote, defmacro, compiler-macros)
  → Interpreter::eval (special forms, function application, primitives)
    → Tensor-операции → GradientTape (autograd recording)
    → GradientTape::backward (reverse-topo AD, blocked-ноды для NS)
    → горячее замыкание → jit::compile_closure → copy-and-patch → RX-страница (гл. 20)
  → HloGraph (START-TRACE … HLO-COMPILE)
    → compile_hlo_stencil → AVX2-стенсилы → W^X-страница (гл. 10)
  → NS-router (NS-IF/NS-GRAD! → per-sample routing + guilt detection)
                     ↓
                LSP Server ←→ Editor
```

Ни одного промежуточного представления: интерпретатор и оба компилятора потребляют S-выражения (и выведенный из них HLO-граф — тоже данные), а нативные страницы — выбрасываемый кэш (гл. 20).

## 1.2 Почему не Python

| Проблема Python в ML | Решение Qualisp |
|---|---|
| GIL и медленный интерпретатор | JIT copy-and-patch и стенсил-компиляция HLO (нативные страницы без IR и LLVM) |
| GC-паузы на больших графах объектов | HibLin — гибридная линейная память без GC (гл. 5) |
| `torch.compile` — внешняя надстройка | HLO-компиляция — часть ядра языка (гл. 10, 20) |
| Зависимости: `pip`, версии, окружения | Всё в одном бинарнике ~2 МБ (13 вшитых модулей) |
| Декораторы/метаклассы — хрупкая метапрограмма | Настоящие макросы над S-выражениями (гл. 12) + гомоиконные примитивы `EVAL`/`READ-FROM-STRING`/`FUNCTION-BODY` (гл. 3) |
| Сериализация — pickle/json, теряет dtype/shape | QSRD v2 — бинарный формат с типами (гл. 16) |
| Символьный AI (правила, унификация) — отдельные библиотеки | Rule engine и унификация в ядре (гл. 14) |
| Нейросимвольная маршрутизация — отдельный фреймворк | `NS-IF`/`NS-GRAD!` + guilt detector в ядре (гл. 14) |
| `from x import y` — частичный импорт через `__all__` | `(import-from (ml knn-predict nb-fit))` — глобальный import-from (гл. 3) |

При этом Qualisp не изолирует вас от Python-экосистемы: есть `LOAD-NPY`/`SAVE-NPY` для NumPy-массивов, JSON, CSV и FFI для вызова любых C-библиотек (гл. 16).

## 1.3 Философия языка

### Лисп-наследие

- **S-выражения** — единый синтаксис для кода и данных:

```lisp
(+ 1 2)              ; это вызов функции → 3
'(+ 1 2)             ; это данные: список из трёх элементов
(eval '(+ 1 2))      ; данные можно исполнить → 3   (v2.3.0+)
(read-from-string "(+ 1 2)")  ; строка → S-выражение → 3   (v2.3.0+)
(function-body 'square)        ; AST-инспекция замыканий   (v2.3.0+)
```

- **Макросы** — функции, которые преобразуют код в код *до* исполнения. В Python ближайшая аналогия — декораторы, но макросы мощнее: они работают на уровне синтаксического дерева, а не объектов-функций.
- **REPL-first** разработка, как в Clojure и Common Lisp.
- **Инвариант одной формы (v2.4.0).** S-выражение — единственная авторитетная форма программы: всё нативное (JIT-страницы, HLO-кёрнелы) — кэш, выведенный из S-выражений, который можно выбросить и пересобрать без изменения поведения. Поэтому гомоиконные примитивы работают поверх скомпилированного кода без ограничений — подробности в гл. 20 (JIT) и гл. 21 (образы).

### ML-наследие

- **Тензоры первого класса.** `(tensor ((1.0 2.0) (3.0 4.0)))` — литерал, как `[[1,2],[3,4]]` в NumPy.
- **Автоградиент через ленту.** Операции с суффиксом `!` записываются на градиентную ленту, `(grad! loss)` — это `loss.backward()` + `tape.clear()`. Операции без `!` — чистые вычисления (`with torch.no_grad():`). С v2.3.0 лента **корректно переживает границы форм**: `defvar` промоутит промежуточные тензоры в stable, `reset_scratch` запечатывает незакрытые графы, Adam-состояние (`m`/`v`/`step`) живёт на самом параметре.

- **Компиляция графов.** `(START-TRACE)` … `(HLO-COMPILE out)` — это `torch.compile()`: код трассируется в граф, оптимизируется (CSE, DCE, fusion) и компилируется в нативный код через **стенсил-эмиттер** `compile_hlo_stencil` (v2.7.0): один проход по графу, байтовые AVX2-стенсилы с дырками, патч и копирование в W^X-страницу процесса — без LLVM и без дискового кэша.

### HibLin-память

Уникальная модель памяти Qualisp — **HibLin** (Hybrid Linear, «гибридная линейная», гл. 5). Всё, что вы вычисляете, — черновик: живёт в текущем scope (scratch) и при выходе возвращается в пулы. Сохранить можно только явным переписыванием «в тетрадь» — `defvar` (stable). Никакого GC, никакого borrow-checker, никакого ручного `free`. Внутри Interpreter держит два scope: `root_arena_` (stable/StableMemory) и `scratch_arena_` (disposable). С v2.3.0 `reset_scratch` дополнительно «запечатывает» незакрытые графы: scratch-тензоры, на которые ссылаются живые tape-узлы, клонируются в stable один раз на тензор, и рёбра переписываются — обучающие циклы ничего не платят (tape пуст после каждого `GRAD!`).

### Нейросимвольный слой (S1–S9)

В ядре Qualisp — полный GOFAI-стек: pattern matching (`match`), структурная унификация с occurs-check (`unify`/`subst`), property lists (`put`/`get`/`remprop`/`symbol-plist`), forward-chaining rule engine (`defrule`/`assert-fact`/`run-rules`/`query`), backtracking (`amb-let`/`require`/`amb-collect`), compiler-macros. И поверх — нейросимвольный маршрутизатор: `NS-IF` маршрутизирует данные в одну из нейросетевых ветвей, `NS-GRAD!` через guilt detector направляет градиент только в виновный сегмент (v2.2.0+ — per-sample маршрутизация, OR-aware `resolve_correct`, softmax-weighted STE).

С v2.3.4 поверх этого работает **движок blackit** (NS-RL, роадмап T1–T4; до v2.8.5 носил кодовое имя susuwatari): REINFORCE-ядро на примитивах языка (`SAMPLE`/`reinforce-loss!`), макро-слоты политики с песочницей исполнения (`EVAL-SANDBOXED`), RL-агент-кодер, который пишет Qualisp-код текстом и переобучает слоты заменой формы, и маршрутизация по слотам (`ns-route*`). Подробности — гл. 14.9–14.10.

## 1.4 Где Qualisp уместен

- **Обучение и инференс моделей**, где важна производительность нативного кода и отсутствие пауз GC.
- **Нейросимвольные системы**: экспертные правила + нейросети в одном рантайме, с общим автоградиентом и маршрутизацией вины (гл. 14, `NS-IF`).
- **Встраиваемые ML**: бинарник ~2 МБ без внешних зависимостей.
- **Быстрые прототипы алгоритмов ML** в REPL — с мгновенной перезагрузкой определений и инспекцией AST через `FUNCTION-BODY`.
- **DSP/аудио**: FFT, STFT, mel-шкалы встроены (гл. 15).
- **Бинарная персистенция ML-моделей**: QSRD v2 хранит S-выражения, тензоры с dtype и шейпом, скаляры (гл. 16).

## 1.5 Чего в Qualisp нет (честно)

- Многопоточности общего назначения (тензорные ядра SIMD-параллелятся, BLAS — тоже, но пользовательских потоков нет).
- Богатой экосистемы пакетов — она только формируется (гл. 16).
- Unicode-строк в полной мере, отладчика с пошаговым исполнением.
- Production CUDA-бэкенда — `src/gpu/kernels.cu` присутствует, но не тестирован на реальном GPU.
- HLO-fallback (без `HLO-COMPILE`) держит константы формы трассировки — кросс-форменное использование такого HLOPROG небезопасно (`TEMP_ISSUES` #23).

## 1.6 Что нового в v2.4–v2.8

- **v2.4.0** — «инвариант одной формы»: S-выражение — единственная форма программы; легаси-AOT (`qlispc`) удалён, нативный код — выбрасываемый кэш; `EVAL`/`READ-FROM-STRING`/`FUNCTION-BODY` работают как раньше (гл. 20, 21).
- **v2.5.0** — JIT copy-and-patch: `(JIT f)` компилирует тело замыкания в RX-страницу одним проходом по S-дереву, без промежуточного IR (гл. 20).
- **v2.5.1–v2.5.2** — инвалидация по макросам (любое `defmacro` сбрасывает все страницы) и самозаживление: stale-обёртка пересобирается после 64 интерпретируемых вызовов.
- **v2.5.3–v2.5.5** — решётка типов слотов (Unknown/Fixnum/Flonum, unboxed-арифметика), `while`/`setq` в JIT-теле, специализация параметров по наблюдаемым типам (`JIT-SIG`).
- **v2.6.0** — `SAVE-IMAGE`/`LOAD-IMAGE`: образ мира как данные (`.qimg`, формат QLSI: S-манифест + тензорные блобы); нативное состояние не сериализуется и восстанавливается лениво (гл. 21).
- **v2.6.1–v2.6.3** — AVX2-стенсилы HLO, range-кёрнелы (`HLO-HAS-RANGE`), fail-loudly `tref`.
- **v2.7.0** — единый стенсил-эмиттер `compile_hlo_stencil`: LLVM-путь и дисковый кэш HLO удалены, интроспекция `HLO-STENCIL-P` (гл. 10).
- **v2.7.1** — mingw-портируемость (полностью зелёный CI на Linux и Windows); срезы H4a/H4b: нативные стенсилы для `SOFTMAX`/`ARGMAX`/`LOOKUP`/`WEIGHTED_LOOKUP` и CODEGEN-видов (`tanh`/`fabs`/`fneg`/`clamp01`/`copy`); stdlib: CSV по RFC-4180, честные тип-предикаты, потери и стабильный softmax в `ml` (гл. 9, 10, 15).
- **v2.7.2** — модуль **Tablet**: детерминированный DataFrame-аналог pandas (T0–T9, 156 тестов; гл. 22); строгий `if` (4-й аргумент — ошибка программы, JIT зеркалит); `read-csv` разворачивает переводы строк внутри кавычек.
- **v2.7.3** — HibLin OOM-фиксы: `setq` в цикле re-home в loop store (20k cons-setq: 12.5 ГБ OOM → пик 35 МБ), автоочистка un-backpropagated графов ленты на границе формы (+494 МБ → 31.7 МБ).
- **v2.7.4** — память под давлением: пул тензоров 256 МБ с эвикцией крупнейшей корзины (1.13 ГБ → 52 МБ), cons-блоки 64k ячеек, guard глубины рекурсии с `(EVAL-MAX-DEPTH)` (гл. 3), итеративные `equal` и списочные примитивы.
- **v2.7.5** — O(1) spine-append для `setq`-накопителей: хвост списка переиспользуется, а не клонируется (глобальный аккумулятор на 12k: 6.6 ГБ → 1.8 МБ).
- **v2.7.6** — время жизни loop store = граница формы: выход из `while` больше не промоутит биндинги в бессмертный root, биндинг переживает итерацию через zero-copy adoption (рекурсивный лес: 745 МБ → 4 КБ).
- **v2.7.7** — part-time HLO: скомпилированная программа владеет своими артефактами (граф, sealed-константы, W^X-страница) и умирает сама, если не привязана к имени (гл. 5.5).
- **v2.8.0** — лесное правило бессмертной зоны: имя якорит своё поддерево, перепись имени выпускает старое; аудитор контрактов смерти `QLISP_AUDIT=1` (валил CI; удалён в 2.8.3), интерактив `(clear …)`/`(drop-model m)`/`(mem-report)`.
- **v2.8.1** — property lists в том же лесу (release-on-put, `remprop` как досрочная смерть); итеративный cdr-спайн в энкодере/декодере образов.
- **v2.8.2** — **tail-call optimization**: self-хвостовой вызов пере-биндит кадр, глубина рекурсии не растёт (200 000 хвостовых вызовов — без стека, гл. 3); кэш раскрытия макросов закрывает ~1 КБ утечки scratch на оценку `let*` в цикле (200k итераций: 217 МБ → 22.7 МБ, гл. 12); **DEBUG-TRACE** — кольцевой журнал событий владения (`TRACE-STATS`, `TRACE-DUMP`), гл. 19.
- **v2.8.3** — **подсчёт ссылок на стабильных ячейках**: у ячейки появился счётчик `refs_`, каждое место разделения берёт ссылку, смерть последнего владельца — каскад (`stable_release`); якоря-владельцы и аудитор `QLISP_AUDIT` удалены, вместо них CI-свип под ASan и хук `QUALISP_RC_POISON` (гл. 5.5). **Live-глобалы**: замыкание больше не захватывает глобальный кадр — глобалы резолвятся в момент вызова, как в Common Lisp; **отложенная смерть**: замена значения посреди формы паркуется и умирает на границе формы. Попутно закрыт регресс `&optional` из 2.8.2. Гл. 5.5, 19.
- **v2.8.4** — **контракт памяти закрыт**: CI-шаг `leak_watch` переведён на LeakSanitizer (`detect_leaks=1`) — теперь утечки ловятся автоматически, а не только UAF; добиты последние источники (двойное закрепление курсора в `FILTER`/`REDUCE`, UAF в `reduce` без seed, утечка на исключении из колбэка, нерефлексивный `equal` для инстансов и тензоров, неслитые реестры символики) — корпус без утечек целиком, было 55/87 на старте раунда (гл. 5.5, 19).
- **v2.8.5** — **rebrand QLISP → Qualisp**: неймспейс `qualisp`, бинарники `qualisp`/`qualisp-lsp`, переменные окружения `QUALISP_*`, проект CMake `qualisp`; кодовое имя NS-RL-движка теперь **blackit** (гл. 14.10); сохранены расширение `.qlsp`, файловые magic `QLSI`/`QSRD` и имя `qvalent`. Вместе с тем — серия «громких отказов» вместо тихого мусора: `strcat` печатает не-строковые аргументы как `WRITE-TO-STRING`, `print`/`display` принимают ровно один аргумент, лишние аргументы вызова без `&rest` — ошибка, `tref` проверяет границы (один индекс — плоский номер), `amb-collect` перечисляет **все** решения, QSRD сериализует тензоры на любой глубине структуры, а непрочитанный градиент на границе формы даёт предупреждение вместо молчаливых нулей (гл. 3, 6, 7, 14, 16).
