# Глава 1. Введение

## 1.1 Что такое Qualisp

**Qualisp** — диалект Лиспа, спроектированный специально для машинного обучения и AI. Четыре кита языка:

1. **Нативная скорость без отдельного компилятора.** Код исполняет интерпретатор S-выражений; горячие замыкания JIT-компилируются в нативные RX-страницы методом copy-and-patch, а тензорный код — через HLO-пайплайн (по мотивам XLA): трассировка в граф, оптимизации, стенсил-эмиттер — машинный код с fusion-оптимизациями, без Python-интерпретатора в горячем цикле. Всё это без промежуточного IR и без LLVM в рантайме.

2. **ML — часть языка, не библиотека.** Тензоры, автоградиент, оптимизаторы, классические алгоритмы ML, аудио-обработка, нейросимвольный движок, строковые утилиты, табличный модуль Tablet — всё встроено в бинарник. 13 вшитых модулей. Не нужен `pip install torch numpy sklearn pandas`.

3. **Гомоикончность.** Код — это данные (S-выражения). В рантайме доступны `EVAL`, `READ-FROM-STRING`, `WRITE-TO-STRING`, `FUNCTIONP`, `FUNCTION-PARAMS`, `FUNCTION-BODY`, `FUNCTION-ENV`, `SYMBOL-NAME` — то есть вы можете строить и исполнять код динамически. Слои DL, факты rule engine, compiler-макросы живут в долговечной (stable) памяти и переживают reset scratch-области.

4. **Нейросимвольный слой.** Символьные развилки `NS-IF`/`NS-GRAD!` с guilt detector маршрутизируют данные между нейросетевыми ветвями и направляют градиент только в виновный сегмент — это встроено в ядро языка, а не надстройка.

Пайплайн:

```text
Source → CharStream → Reader → SExpr (ConsCellPool)
  → MacroExpander (backquote, defmacro, compiler-macros)
  → Interpreter::eval (special forms, function application, primitives)
    → Tensor-операции → GradientTape (autograd recording)
    → GradientTape::backward (reverse-topo AD, blocked-ноды для NS)
    → горячее замыкание → jit::compile_closure → copy-and-patch → RX-страница (гл. 20)
  → HLO-граф (START-TRACE … HLO-COMPILE)
    → понижение (CSE, DCE, FUSION) → compile_hlo_stencil → AVX2-стенсилы → W^X-страница (гл. 10)
  → NS-router (NS-IF/NS-GRAD! → per-sample routing + guilt detection)
                     ↓
                LSP Server ←→ Editor
```

Ни одного промежуточного представления: интерпретатор и оба нативных эмиттера потребляют S-выражения (и выведенный из них HLO-граф — тоже данные), а нативные страницы — выбрасываемый кэш (гл. 20).

## 1.2 Почему не Python

| Проблема Python в ML | Решение Qualisp |
|---|---|
| GIL и медленный интерпретатор | JIT copy-and-patch и стенсил-компиляция HLO (нативные страницы без IR и LLVM) |
| GC-паузы на больших графах объектов | HibLin — гибридная линейная память без GC (гл. 5) |
| `torch.compile` — внешняя надстройка | HLO-компиляция — часть ядра языка (гл. 10, 20) |
| Зависимости: `pip`, версии, окружения | Всё в одном бинарнике ~2 МБ (14 вшитых модулей) |
| Декораторы/метаклассы — хрупкая метапрограмма | Настоящие макросы над S-выражениями (гл. 12) + гомоиконные примитивы `EVAL`/`READ-FROM-STRING`/`FUNCTION-BODY` (гл. 3) |
| Сериализация — pickle/json, теряет dtype/shape | QSRD v2 — бинарный формат с типами (гл. 16) |
| Символьный AI (правила, унификация) — отдельные библиотеки | Rule engine и унификация в ядре (гл. 14) |
| Нейросимвольная маршрутизация — отдельный фреймворк | `NS-IF`/`NS-GRAD!` + guilt detector в ядре (гл. 14) |
| `from x import y` — частичный импорт через `__all__` | `(import-from (ml knn-predict nb-fit))` — глобальный import-from (гл. 3) |

При этом Qualisp не изолирует вас от Python-экосистемы: есть `LOAD-NPY`/`SAVE-NPY` для NumPy-массивов, JSON, CSV и FFI для вызова любых C-библиотек (гл. 16).

## 1.3 Философия языка

### Лисп-наследие

- **S-выражения** — единый синтаксис для кода и данных:

```lisp
(+ 1 2)              ; это вызов функции → 3
'(+ 1 2)             ; это данные: список из трёх элементов
(eval '(+ 1 2))      ; данные можно исполнить → 3
(read-from-string "(+ 1 2)")  ; строка → S-выражение → 3
(function-body 'square)        ; AST-инспекция замыканий
```

- **Макросы** — функции, которые преобразуют код в код *до* исполнения. В Python ближайшая аналогия — декораторы, но макросы мощнее: они работают на уровне синтаксического дерева, а не объектов-функций.
- **REPL-first** разработка, как в Clojure и Common Lisp.
- **Инвариант одной формы.** S-выражение — единственная авторитетная форма программы: всё нативное (JIT-страницы, HLO-кёрнелы) — кэш, выведенный из S-выражений, который можно выбросить и пересобрать без изменения поведения. Поэтому гомоиконные примитивы работают поверх скомпилированного кода без ограничений — подробности в гл. 20 (JIT) и гл. 21 (образы).

### ML-наследие

- **Тензоры первого класса.** `(tensor ((1.0 2.0) (3.0 4.0)))` — литерал, как `[[1,2],[3,4]]` в NumPy.
- **Автоградиент через ленту.** Операции с суффиксом `!` записываются на градиентную ленту, `(grad! loss)` — это `loss.backward()` + `tape.clear()`. Операции без `!` — чистые вычисления (`with torch.no_grad():`). Лента **корректно переживает границы форм**: `defvar` промоутит промежуточные тензоры в stable, `reset_scratch` запечатывает незакрытые графы, Adam-состояние (`m`/`v`/`step`) живёт на самом параметре.

- **Компиляция графов.** `(START-TRACE)` … `(HLO-COMPILE out)` — это `torch.compile()`: код трассируется в граф, оптимизируется (CSE, DCE, fusion) и компилируется в нативный код через **стенсил-эмиттер** `compile_hlo_stencil`: один проход по графу, байтовые AVX2-стенсилы с дырками, патч и копирование в W^X-страницу процесса — без LLVM и без дискового кэша. Мастер-копия программы — форма графа, а пониженный граф — переиспользуемый кэш (гл. 10).

### HibLin-память

Модель памяти Qualisp — **HibLin** (Hybrid Linear, «гибридная линейная», гл. 5). Данные по умолчанию disposable: живут в текущем scope (scratch) и при выходе возвращаются в пулы; сохранить значение можно только явным действием — `defvar` переносит его в stable. Структурные данные (S-выражения, cons-ячейки) при этом живут под подсчётом ссылок и шарятся, а данные тензоров — один владелец, точный размер, глубокая копия. Никакого GC, никакого borrow-checker, никакого ручного `free` на стороне пользователя.

Три пула: `TensorBufferPool` (тензоры, exact-size, кэш по паре shape+dtype), `ConsCellPool` (S-выражения, фиксированная ячейка, O(1) alloc/free) и `StableMemory` (долговечные данные). Бессмертие — флаг в данных, а не исключение по идентичности: у ячейки есть счётчик ссылок и бит бессмертия; `nil` бессмертен. `reset_scratch` «запечатывает» незакрытые графы: scratch-тензоры, на которые ссылаются живые tape-узлы, клонируются в stable один раз на тензор, и рёбра переписываются — обучающие циклы ничего не платят.

### Нейросимвольный слой (S1–S9)

В ядре Qualisp — полный GOFAI-стек: pattern matching (`match`), структурная унификация с occurs-check (`unify`/`subst`), property lists (`put`/`get`/`remprop`/`symbol-plist`), forward-chaining rule engine (`defrule`/`assert-fact`/`run-rules`/`query`), backtracking (`amb-let`/`require`/`amb-collect`), compiler-макросы. И поверх — нейросимвольный маршрутизатор: `NS-IF` маршрутизирует данные в одну из нейросетевых ветвей, `NS-GRAD!` через guilt detector направляет градиент только в виновный сегмент (per-sample маршрутизация, OR-aware `resolve_correct`, softmax-weighted STE).

Поверх этого работает **движок blackit** (NS-RL): REINFORCE-ядро на примитивах языка (`SAMPLE`/`reinforce-loss!`), макро-слоты политики с песочницей исполнения (`EVAL-SANDBOXED`), RL-агент-кодер, который пишет Qualisp-код текстом и переобучает слоты заменой формы, и маршрутизация по слотам (`ns-route*`). Подробности — гл. 14.9–14.10.

## 1.4 Где Qualisp уместен

- **Обучение и инференс моделей**, где важна производительность нативного кода и отсутствие пауз GC.
- **Нейросимвольные системы**: экспертные правила + нейросети в одном рантайме, с общим автоградиентом и маршрутизацией вины (гл. 14, `NS-IF`).
- **Встраиваемый ML**: бинарник ~2 МБ без внешних зависимостей.
- **Быстрые прототипы алгоритмов ML** в REPL — с мгновенной перезагрузкой определений и инспекцией AST через `FUNCTION-BODY`.
- **DSP/аудио**: FFT, STFT, mel-шкалы встроены (гл. 15).
- **Бинарная персистенция ML-моделей**: QSRD v2 хранит S-выражения, тензоры с dtype и шейпом, скаляры (гл. 16).

## 1.5 Чего в Qualisp нет (честно)

- Многопоточности общего назначения «как в Python»: ядра берут все доступные потоки внутри тензорных операций (OpenMP, OpenBLAS), а для работы вне одной операции есть асинхронный слой с пулом задач (гл. 15.12); собственных потоков у программы нет.
- GPU-бэкенда: вычисления идут на CPU (SIMD-ядра, OpenBLAS). Интерфейс `Device` оставлен как точка расширения, но реализация в проекте одна — CPU (гл. 11).
- Богатой экосистемы пакетов — она только формируется (гл. 16).
- Unicode-строк в полной мере, отладчика с пошаговым исполнением.
- HLO-fallback (без `HLO-COMPILE`) держит константы формы трассировки — кросс-форменное использование такого HLOPROG небезопасно.

## 1.6 Подсистемы Qualisp

Qualisp — не одна большая функция, а набор подсистем, связанных единым представлением программы:

| Подсистема | Что делает | Глава |
|---|---|---|
| Reader и макро-экспандер | Текст → S-выражения; backquote, `defmacro`, compiler-макросы | 3, 12 |
| Интерпретатор | Специальные формы, вызовы функций, примитивы | 3, 19 |
| Память HibLin | Три пула, exact-size тензоры, подсчёт ссылок для структур | 5 |
| Тензоры | Линейные типы, dtype, отсутствие views, точный учёт буферов | 4, 6 |
| Автоград | Лента, backward, оптимизаторы, проверка конечности | 7 |
| DL- и ML-слои | Модели, train-step, метрики, CV, grid search | 8, 9 |
| HLO-стенсили | Трассировка в граф, CSE/DCE/FUSION, нативные кёрнелы | 10 |
| JIT | Copy-and-patch для горячих замыканий | 20 |
| Символьный слой | Pattern matching, унификация, rule engine, backtracking | 14 |
| NS-маршрутизация | `NS-IF`/`NS-GRAD!`, guilt detector | 14 |
| Стандартная библиотека | 14 вшитых модулей: core, string, dl, ns, ml, io, regex, audio, datetime, pkg, errors, visual, tablet, async | 15 |
| LSP-сервер | Диагностика, навигация, автодополнение по `.qlsp` | 2, 19 |
| Образы и пакеты | `SAVE-IMAGE`/`LOAD-IMAGE`, QSRD, `qvalent` | 16, 21 |

Свойства, которые из этого следуют:

- **Одна форма на всю систему.** S-выражение — единственное представление программы; нативный код — кэш, который можно выбросить и пересобрать.
- **Никакого GC.** Память освобождается по scope, структурные данные — по счётчику ссылок, тензорные буферы — по точному размеру.
- **CPU-only.** SIMD-ядра и BLAS; GPU-бэкенда в проекте нет.
- **Гомоиконность поверх всего.** `EVAL`, макросы и compiler-макросы работают поверх скомпилированного кода без ограничений.
- **Всё в одном бинарнике.** Стандартная библиотека, JIT и HLO-эмиттер — внутри `qualisp`.

Лицензия компилятора — **GPLv3** (сама книга — по-прежнему MIT).
