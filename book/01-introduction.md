# Глава 1. Введение

## 1.1 Что такое Qualisp

**Qualisp** — статически типизированный Lisp с единственным представлением программы (S-выражение) и JIT copy-and-patch. Реализация написана на Zig; основная платформа — Linux x86-64 SysV с AVX2, Windows x86-64 поддерживается с оговорками. Четыре кита языка:

1. **Нативная скорость без отдельного компилятора.** Ни AOT, ни интерпретатора/tree-walk: конвейер `read → macroexpand → typecheck → emit → run`. Тело `defun` компилируется при определении (`emitDefun` строит `FunctionTemplate` с готовым `entry`), top-level форма — сразу. JIT-страница — выбрасываемый кэш, выведенный из S-выражения; мастер-форма хранится в функции и страницу можно пересобрать. Тензорный код трассируется в HLO-граф (`defgraph`) или компилируется в fused-ядро (`defuse`).
2. **ML — часть языка, не библиотека.** Тензоры с dtype и формой, autograd через `param`/`grad!`/`grad-of` и reverse-mode `grad`, HLO-графы, свёртки/пулинг, NS-маршрутизация, классические метрики — всё в одном бинарнике. В состав входят 13 модулей стандартной библиотеки, включая `error` и `datetime`; обычная сборка вшивает их, edge-профиль выносит 11 модулей в `stdlib.qlsl`. Не нужен `pip install torch numpy sklearn pandas`.
3. **Гомоикончность при полной статике.** Код — данные: `:syntax`, `quote`/backquote, `defmacro`, `macroexpand-all`, `eval`. При этом общий `:any` запрещён, верхний уровень аннотирован, а невыводимый локальный тип — отказ компиляции, а не неявная динамика. `defun` поддерживает статические перегрузки по набору типов и арности; ранговый wildcard `(:tensor DTYPE :any)` — единственное исключение из правила `:any`.
4. **Нейросимвольный слой.** Дискретное условие задаётся NS-функцией — непрерывной level-функцией, знак которой равен истинности. `ns-if` маршрутизирует строки по знакам атомов, покрытие проверяется через ROBDD, `ns-band` строит eager-маску по `|atom| < eps`, а градиент идёт только по исполненным веткам. Это примитивы языка, а не отдельный модуль.

Пайплайн:

```text
Исходник → Reader → S-выражения (Cons/атомы)
  → MacroExpander (defmacro, backquote, macroexpand-all)
  → Typechecker (аннотации, двунаправленный вывод, статические перегрузки)
  → Emitter → JIT-страницы (copy-and-patch, SysV, W^X) → Runtime
       ↑
       ├─ defgraph / defuse → HLO-граф (dims + attrs) → ядра AVX2 → grad! / grad-of
       └─ ns-if / ns-band → знаковый спуск → ROBDD-покрытие → роутинг строк
```

Никакого второго AST, байткода или обязательного IR: нативный код — выведенный из S-выражений кэш, а HLO-граф — производный одноразовый артефакт, хозяин которого — форма `defgraph` (гл. 10, 20). Готовый граф можно упаковать вместе с модулями в `.qlsl` (`qualisp-pack`), а рантайм — встроить через `libqualisp` или Python-пакет `qualisp` (гл. 16).

## 1.2 Почему не Python

| Проблема Python в ML | Решение Qualisp |
|---|---|
| GIL и медленный интерпретатор | JIT copy-and-patch: `read → typecheck → emit → run`, нативные страницы без IR и LLVM в рантайме |
| GC-паузы на больших графах объектов | HibLin: линейная память по scope, без GC и без счётчика ссылок (гл. 5) |
| `torch.compile` — внешняя надстройка | `defgraph`/`defuse` — часть языка: трассировка в граф и компиляция ядер (гл. 10) |
| Зависимости: `pip`, версии, окружения | Всё в одном бинарнике: JIT и 13 модулей; edge-профиль — бинарь + `stdlib.qlsl`; Python-обёртка — опциональный wheel |
| Декораторы/метаклассы — хрупкая метапрограмма | Настоящие макросы над S-выражениями (гл. 12) и `eval` с `:syntax` (гл. 3) |
| Динамические типы: ошибка обнаруживается на прогоне | Полная статика: `:any` запрещён, сигнатуры на верхнем уровне обязательны |
| Сериализация — pickle/json, теряет dtype/shape | QSRD: бинарный формат с секциями и crc32, `save-image` / `save-weights` (гл. 21) |
| Символьный AI (правила, унификация) — отдельные библиотеки | Модуль `symbolic`: `match`, `subst`, `rewrite`, `unify`, `diff`, reverse-mode `grad` (гл. 14) |
| Нейросимвольная маршрутизация — отдельный фреймворк | `ns-if` с проверкой покрытия через ROBDD в ядре (гл. 14) |
| `from x import y` — частичный импорт через `__all__` | `(import-from m (a b))` — только названные экспорты модуля (гл. 2, 3) |

Python-совместимость — это API, а не стиль: функциональность stdlib переносится как лисповый набор функций, а не имитацией Python-синтаксиса.

## 1.3 Философия языка

### Лисп-наследие

- **S-выражения** — единый синтаксис для кода и данных:

```lisp
(+ 1 2)                         ; вызов: 3
'(+ 1 2)                        ; данные: список из трёх элементов
(eval '(+ 1 2))                 ; данные можно исполнить: 3
(read-from-string "(+ 1 2)")    ; строка → S-выражение
`(1 2 ,(+ 1 2))                 ; шаблон с подстановкой → (1 2 3)
```

- **Макросы** — функции `:syntax → :syntax`, которые преобразуют код в код *до* проверки типов. В Python ближайшая аналогия — декораторы, но макросы работают на уровне дерева S-выражений, а не объектов-функций.
- **REPL-first** разработка: баннер `Qualisp`, промпт `> `, каждая форма исполняется сразу.
- **Инвариант одной формы.** S-выражение — единственная авторитетная форма программы; нативный код — кэш, выведенный из него и пересобираемый без изменения поведения. Гомоиконные примитивы работают поверх скомпилированного кода без ограничений — подробности в гл. 12, 20, 21.

### ML-наследие

- **Тензоры первого класса.** `(tensor ((1.0 2.0) (3.0 4.0)))` — литерал с формой `(:tensor :f32 (2 2))`, как `np.array([[1,2],[3,4]])` в NumPy.
- **Автоград через граф.** `(param t)` помечает тензор обучаемым; `defgraph` трассирует тело один раз и компилирует forward/backward; `grad!` считает градиент по последнему запуску графа, `grad-of` отдаёт накопленный градиент параметра. Reverse-mode `grad` строит символьный градиент скалярного лосса; `sin`/`cos`/`sqrt`/`atan` имеют forward- и backward-ядра. Отдельной ленты в исходном коде нет: лента — деталь реализации HLO-слоя (гл. 7, 10).
- **Компиляция графов.** `(defgraph name ((p . :type) ...) ((expr . :ret)))` — мастер-форма: параметры и результат аннотированы парными формами, результат — последняя форма тела. Граф и скомпилированный код — производные артефакты. Ядра работают с `f16`/`f32`/`f64`/`u8`/`i64`, используют AVX2; `defuse` компилирует одно elementwise-выражение в цикл без промежуточных тензоров. `softmax`/`log-softmax` считаются по последней оси тензора любого ранга, `argmax`/`one-hot`/`gather`/`scatter-add` работают с `:i64`-данными, `conv2d` и пулинг дифференцируемы.

### HibLin-память

Модель памяти Qualisp — **HibLin** (Hybrid Linear, «гибридная линейная», гл. 5). Данные живут в scope, в котором созданы, и при выходе из него возвращаются в пул; сохранить значение можно явным действием — `defvar` копирует его в stable. Память организована в три пула: `ConsCellPool` (S-выражения, cons-ячейки, замыкания), `StableMemory` (`defvar`, глобалы, веса, JIT-страницы) и `TensorBufferPool` (eager-скретч и буферы HLO-графа). Есть отдельная bump-арена кадров вызова со строгим LIFO; машинный стек поднят до 256 МБ, чтобы исчерпание арены диагностировалось ошибкой, а не падением.

Замыкание захватывает локальные биндинги копией, глобалы — live; `nil`, `t` и символы бессмертны; `setq` перемещает значение в биндинг, `defvar` копирует в stable, unstable-ссылок из stable нет. GC нет, счётчика ссылок нет, ручного `free` нет; явное удаление имени — `clear`. Циклы в мутабельных stable-структурах не собираются до завершения процесса — осознанная цена отсутствия GC. Запись `set-slot` в stable-структуру и `setq` захваченного биндинга копируют только scratch-часть значения (`Runtime.stabilize`), stable-узлы сохраняют идентичность, а циклы копируются через memo.

### Нейросимвольный слой

Примитивы `ns-grt`/`ns-geq`/`ns-lss`/`ns-leq`, `ns-and`/`ns-or`/`ns-not`, `ns-eq`/`ns-neq` возвращают `:flonum`; знак значения — это булева истинность. Роутер `ns-if` строит знаковое дерево, разбивает строки на ветки, проверяет покрытие через ROBDD (непокрытие, пересечение, пустая ветка — ошибки компиляции) и исполняет только непустые ветки. `(ns-band ns-expr eps)` — отдельная форма: она строит eager-маску `[B]` по строгому `|atom| < eps`; в `defgraph`/`defuse` узла для неё пока нет. Per-row тензор нельзя захватывать в ветку `ns-if` (скалярные захваты разрешены). R-комбинация `p + q ∓ hypot(p,q)` масштабируется и не переполняется на экстремальных значениях; знаковый проход живёт в `plan.fillMasks`. Значение R-комбинации как данные дифференцируется там, где использовано; градиента по самому решению роутера нет. Non-goals: blending, per-cell boundary, обучаемый `eps`, counterfactual-ветви (гл. 14).

## 1.4 Где Qualisp уместен

- **Обучение и инференс моделей**, где важны нативный код и отсутствие пауз GC.
- **Нейросимвольные системы**: экспертные правила и нейросети в одном рантайме, жёсткая маршрутизация с проверкой покрытия (гл. 14).
- **Встраиваемый ML**: один бинарник со встроенной стандартной библиотекой и JIT.
- **Быстрые прототипы алгоритмов** в REPL: определения переигрываются сразу, ошибки несут позицию `file:line:col`.
- **Табличные данные**: модуль `tablet` — числовая таблица одного dtype с методами `nrows`, `where`, `sort-by` (гл. 22).
- **Бинарная персистенция моделей**: QSRD хранит формы, данные и тензоры с dtype и формой (гл. 21).
- **Обучение языку**: статическая типизация, макросы и S-выражения в одном маленьком языке.

## 1.5 Чего в Qualisp нет (честно)

- AOT-компиляции и интерпретатора/tree-walk: код всегда проходит `read → macroexpand → typecheck → emit → run`; нативный код создаётся в рантайме.
- Второго AST, байткода или обязательного IR: авторитетна только форма `defgraph` / S-выражение.
- Общего `:any`, неявных динамических типов и HM-вывода сигнатур: невыводимый локальный тип — отказ компиляции. Допустим только ранговый wildcard `(:tensor DTYPE :any)`.
- Динамических перегрузок: перегрузки статические, ключ — `(имя, арность, типы параметров)`; тип результата в ключ не входит, имя с несколькими сигнатурами нельзя использовать как значение без явной аннотации. `abs` — примитив; `min`/`max`/`expt` как перегрузки по-прежнему не существуют.
- GC и счётчика ссылок: циклы в мутабельных stable-структурах не собираются до завершения процесса.
- GPU/Device: вычисления идут на CPU x86-64 через JIT и AVX2-ядра; бэкенда Device нет.
- Writable views: `t-shape` возвращает форму, `t-rows`/`t-select-rows`/`t-column` копируют, `reshape`/`transpose` копируют, `t-slice` возвращает копию блока, а не view (гл. 6).
- Отладчика с точками останова: source map есть и даёт `file:line:col` в ошибках, но step/bt/locals-сервера нет.
- Реестра пакетов: `.qlsl` собирается `qualisp-pack` и распространяется файлом; `pkg-install`/`qvalent` нет. Поиск задаётся `--path`/`QUALISP_PATH`, воспроизводимость — `qualisp.lock` с SHA-256 (гл. 16). Готового LSP-сервера в релизных ассетах тоже нет: LSP собирается локально, в ассеты входят `qualisp`, `qprof`, wheel и `SHA256SUMS.txt` (гл. 2, 16).
- Модуля `async`: есть примитивы `future`/`await` и тип `(:future T)`, но модуля с таким именем в stdlib нет.
- `deftest`/`run-tests`: в модуле `test` есть `assert-fixnum` и `assert-string` (гл. 3).
- `let*`: `let` создаёт параллельные биндинги; последовательные зависимости записываются вложенными `let`.

## 1.6 Подсистемы Qualisp

Qualisp — не одна большая функция, а набор подсистем, связанных единым представлением программы:

| Подсистема | Что делает | Глава |
|---|---|---|
| Reader и printer | Текст → S-выражения; `quote`/backquote, `read-from-string`/`write-to-string`, печать | 3 |
| Статический checker | Типы, аннотации, двунаправленный вывод, отказ с диагностикой | 3, 4 |
| JIT и calling convention | `read → typecheck → emit → run`, copy-and-patch, W^X-страницы, `entry(frame, env, rt, out)`, хвостовые вызовы, raw `:fixnum`/`:flonum`-слоты, инлайн-вызов глобала, ленивый traceback | 20 |
| Макросы, `:syntax`, `eval` | `defmacro`, `macroexpand-all`, `gensym`, раскрытие до проверки типов; `eval` — единственная граница статики | 3, 12 |
| Память HibLin | `Store` world/scratch, stable, bump-арена кадров, `TensorBufferPool` для eager и HLO, без GC/RC | 5 |
| Тензоры и autograd | dtype/shape, eager-операции, `:i64`-данные, `param`, `grad!`, `grad-of`, parallel-safe ядра | 6, 7 |
| HLO | `defgraph`, `defuse`, граф с `dims`/`attrs`, batched `matmul`, conv/pool, forward/backward, компиляция ядер, O(n)-backward; reverse-mode `grad` | 7, 10, 14 |
| Статические перегрузки | ключ `(имя, арность, типы)`, разрешение на компиляции, диагностика `ambiguous overload`/`no overload matches` | 4, 19 |
| NS-логика | NS-примитивы, `ns-if`, `ns-band`, знаковый спуск, ROBDD-покрытие, параллельный роутинг строк | 14 |
| Параллельные ядра | `kernel_pool`, elementwise/map, batched matmul, reshape/transpose, осевые редукции, `softmax`, conv/pool; `QUALISP_SERIAL=1` | 6 |
| Ошибки и трассировка | модуль `error`, структуры `error`/`call-frame`, категории, `result-error`, `format-error`, печать `#<tag …>` | 3, 15 |
| Стандартная библиотека | 13 модулей: core, error, string, collections, test, ml, dl, symbolic, argparse, tablet, io, datetime, neuro; prelude — `core` и `error` | 15 |
| Пакеты и встраивание | `qualisp-pack` → `.qlsl`, `--package`/`--path`/`QUALISP_PATH`, `qualisp.lock`, edge-профиль `stdlib.qlsl`, `libqualisp` C ABI, Python-пакет `qualisp` | 15, 16 |
| FFI и образы | `ffi-load`/`ffi-defun`, QSRD v1/Q2, `save-image`, `save-weights`/`load-weights` | 16, 21 |
| CLI, REPL, профиль | `qualisp`, REPL с промптом `> `, `--trace`, `--package`, `--path`, `--lock` и `qprof` | 2, 19 |
| LSP (только исходники) | `libqualisplsp` (analysis-only C ABI), `qualisp-lsp` (Rust), расширение VSCodium; исполняющий `libqualisp` — отдельная библиотека, в wheel/из исходников | 2, 16 |

Свойства, которые из этого следуют:

- **Одна форма на всю систему.** S-выражение — единственное представление; нативный код — кэш, который можно выбросить и пересобрать.
- **Никакого GC.** Память освобождается по scope; cons-ячейки и буферы возвращаются в пулы; `clear` отвязывает имя.
- **CPU-only.** SIMD-ядра AVX2 и параллельные вычислительные ядра; GPU-бэкенда в проекте нет.
- **Гомоиконность поверх всего.** `:syntax`, макросы и `eval` работают над кодом как над данными.
- **Всё в одном бинарнике (обычная сборка).** Стандартная библиотека, checker и JIT-эмиттер внутри `qualisp`; edge-профиль оставляет в бинаре только `core`+`error` и читает `stdlib.qlsl`.

Книга описывает текущую реализацию; язык развивается, и книга будет обновляться.
