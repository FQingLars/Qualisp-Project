# Глава 14. Символьное и нейросимвольное программирование

Qualisp — статически типизированный Lisp: программа и данные — одно и то же S-выражение. Символьный слой стоит на трёх опорах:

- **субстрат** — тип `:syntax`, `quote`/`quasiquote`, `read-from-string`/`write-to-string`, `gensym`, `defmacro`, `macroexpand`, `eval`;
- **модуль `symbolic`** — сопоставление с образцом, подстановка, переписывание, упрощение, символьное дифференцирование, унификация, прямой вывод и полиномы;
- **NS-логика** — непрерывные level-функции, знак которых задаёт дискретное условие, жёсткий построчный роутер `ns-if` и eager-маска `ns-band`.

Примитивы `ns-grt`/…/`ns-if`/`ns-band` доступны глобально; модули `symbolic` и `neuro` подключаются явно: `(import SYMBOLIC)` и `(import NEURO)`. Отдельного модуля `ns` в релизе нет — NS-слой живёт в ядре (`src/ns/`).

## 14.1 Pattern matching: `match`

В текущем языке `match` — обычная функция модуля `symbolic`, а не special form с ветками:

```lisp
(match pattern term)   ; → (:option :syntax) — окружение или nil
```

Переменные образца — символы с префиксом `?` (`?x`, `?acc`). Окружение — ассоциативный список `((?X . 1) (?Y . 2))`; пустое окружение — `t` (не `nil`, потому что `nil` означает «не совпало»). Повторная переменная требует `equal`-совпадения; `nil` в образце — атом и совпадает только с `nil`.

```lisp
(import SYMBOLIC)

(match '(+ ?x ?y) '(+ 1 2))   ; → ((?Y . 2) (?X . 1))
(match '(f) '(f))             ; → T, пустое окружение — успех
(match '(f ?x) '(f 1 2))      ; → nil, нет совпадения
```

| Паттерн | Что сопоставляет |
|---|---|
| `?x` | что угодно, связывает переменную `x` в окружении |
| `42`, `3.14`, `"hi"`, `'sym` | литерал через `equal` |
| `(f ?x ?y)` | список той же длины, рекурсивно по `car`/`cdr` |
| `nil` | только `nil` (атом, не пустой список-шаблон) |

Сопоставление идёт сверху вниз, по `car`, затем по `cdr`; первое совпадение связывает переменные. Нет `_`, `(or …)`, `(when …)` и броска при отсутствии совпадения — «не подошло» это `nil`.

Рядом с `match` работают:

```lisp
(variable? '?x)              ; → T — символ с префиксом ?
(free-of? '?x '(+ ?y 1))     ; → T — переменная не входит в терм
(subst '((?X . A)) '(f ?x b)) ; → (F A B)
```

> 🐍 **Python-аналогия.** Это не `match/case` со встроенными биндингами, а скорее `re.match` + `groupdict()` или `unification`-библиотека над AST: `(pattern, term) → dict` подстановок.

## 14.2 Унификация: `unify` и `subst`

Унификация — двустороннее согласование двух термов с occurs-check (переменная не может связаться с термом, в котором сама встречается):

```lisp
(unify '(f ?x b) '(f a b))   ; → ((?X . A))
(unify '(+ ?x ?y) '(+ 1 2))  ; → ((?Y . 2) (?X . 1))
(unify '?x '(+ ?x 1))        ; → nil, occurs-check
```

Возвращаемый тип — `(:option :syntax)`: `nil` при неудаче, `t` при пустой подстановке и alist иначе. Цепочки связей (`?x → ?y`, `?y → 3`) разрешаются до замкнутого результата; occurs-check гарантирует завершение. `subst env term` применяет подстановку и принимает `t`, `nil` и настоящий alist — вызывающему не нужно ветвиться на маркере.

> 🐍 В Python унификацию делают `unification`/`kanren`; здесь она — 40 строк типизированного Qualisp в `src/stdlib/symbolic.qlsp`.

## 14.3 Окружения подстановок вместо property lists

Глобальных словарей свойств у символов (`put`/`get`/`symbol-plist`) в текущем языке нет. Их роль в символьном слое выполняют **окружения** — alist вида `((?x . term) …)`, которые передаются явно:

- пустое окружение — `t`; `nil` зарезервирован за «совпадения нет»;
- `env-lookup` ищет связь по `equal` имени переменной;
- `bind-var` отказывается связывать переменную второй раз, если значение отличается;
- окружение живёт ровно столько, сколько длится рекурсия `match`/`unify`, и не сохраняется в символе.

Иначе говоря, «свойства» переменной — это не мутабельная таблица на символе, а неизменяемый alist, который функция получает аргументом и возвращает новым значением. Это укладывается в общую модель памяти: cons-ячейки скоупа, deep-copy в stable при `defvar`, никаких скрытых глобальных мутаций.

> 🐍 Ближе всего `dict[str, Term]`, передаваемый по значению в рекурсивных функциях, а не атрибуты на объектах `Symbol`.

## 14.4 Прямой вывод: `derive` и `matches`

Классического rule engine с `assert-fact`/`defrule`/`run-rules`/`query` в релизе нет. Вместо него `symbolic` предлагает два примитива над обычными `:syntax`-данными:

```lisp
(derive facts rules limit)   ; → :syntax, прямой вывод до неподвижной точки
(matches facts pattern)      ; → (:option :syntax)
```

Факты и правила — те же S-выражения, что и любой терм; их строят `quote`, макросами или `read-from-string`. Лимит итераций обязателен: правила могут зацикливаться, а `while` в языке есть.

```lisp
(import SYMBOLIC)
(derive '((p)) '((p q)) 10)   ; → ((P)) — из p выведено q, оба факта в наборе
(matches '((p) (q)) '(p))     ; → (T) — факт найден
```

`derive` и `matches` возвращают `:syntax`, а не `(:list :syntax)`: последний тип неконструируем, потому что `cons` с `:syntax`-аргументом сам даёт `:syntax`. Набор фактов — это список в `:syntax`-представлении, а не типизированный список.

> 🐍 Прямого аналога в Python нет — территория pyDatalog/CLIPS/Prolog. Здесь это пара функций, работающих со списками S-выражений, без отдельного языка правил.

## 14.5 Детерминированный перебор: `rewrite-all` с лимитом

Недетерминизма в виде `amb-let`/`require`/`amb-collect` в текущем языке нет. Вместо него — детерминированное переписывание до неподвижной точки:

```lisp
(rewrite rule term)          ; один шаг, сверху вниз, первое совпадение
(rewrite-all rules term n)   ; до неподвижной точки, не более n шагов
```

Правило — ровно `(pattern template)`, набор правил — список таких пар; неверная форма — `throw` с сообщением, а не тихое усечение. Лимит обязателен: правила вроде `(+ ?x 0) → ?x` сходятся, а циклические — нет.

```lisp
(import SYMBOLIC)
(rewrite '((+ ?x 0) ?x) '(+ y 0))          ; → Y
(rewrite-all '(((+ ?x 0) ?x)) '(+ (+ y 0) 0) 10) ; → Y
```

> 🐍 Аналог — не `itertools.product` с бэктрекингом, а `while` + `str.replace` в цикле с ограничением числа проходов: стратегии задаются списком правил, а не генератором вариантов.

## 14.6 Чтение и печать: цикл «терм → текст → терм»

Reader-макросов (`set-reader-macro`) в релизе нет. Субстрат символьных преобразований — встроенные формы чтения и печати:

- `read-from-string : :string → :syntax` — текст → S-выражение;
- `write-to-string : :a → :string` — читаемое представление со строками в кавычках и escape;
- `quote`/`quasiquote`/`unquote`/`unquote-splicing`, `gensym` — построение термов с гигиеной;
- `equal` сравнивает `:syntax` структурно.

Для данных round-trip точен: `(write-to-string …)` → `(read-from-string …)` возвращает тот же терм. `eval : :syntax → :a` заново проходит expand → typecheck → emit и остаётся единственной границей статики.

> 🐍 Это `ast.parse`/`ast.unparse` и `eval(compile(...))` в одном type-безопасном конвейере с проверкой типа на входе.

## 14.7 Макросы и символьные преобразования

Вместо `define-compiler-macro` работают обычные макросы Qualisp: `defmacro` задаёт `:syntax → :syntax`, раскрытие идёт до typecheck до неподвижной точки, тело макроса типизируется и JIT-компилируется в живом окружении. Есть `macroexpand-1`, `macroexpand`, `macroexpand-all` (рекурсивно, не заходя в `quote`) и `gensym`; `&rest` и `&optional` работают. Загрузчик раскрывает макросы модуля, поэтому модуль может пользоваться своими макросами. Тела `defgraph`/`defuse` также раскрывают макросы до трассировки.

Поверх этого субстрата модуль `symbolic` даёт CAS-минимум и немного больше:

```lisp
(import SYMBOLIC)

(diff '(* x x) 'x)              ; → (+ X X) — упрощает, но не приводит подобные
(diff-canonical '(* x x) 'x)    ; → (* 2 X) — приведение подобных
(simplify '(+ x 0))             ; → X — константы и x+0, x*1, x*0, x^1, x^0
(collect '(+ (* 2 x) (* 3 x)))  ; → (* 5 X) — нормальная форма «сумма мономов»
(poly-coeffs '(+ x 1) 'x)       ; → (1 1) — плотно от степени 0
(poly-eval '(+ (* 2 x) 1) 'x 3.0) ; → 7.0
```

`diff` — поэлементная производная. Арифметика n-арная (как в `term`): `+` суммирует, `*` раскрывает правило произведения для любого числа множителей, `-` — левая свёртка с унарным минусом; `/` и `^` бинарные, степень числовая. Унарные `sin/cos/exp/log/sqrt/tanh/atan` знают свои производные; `relu` отказывает (`diff: relu is not differentiable symbolically`), тензорные операции — `diff: not elementwise; use grad`. Результат упрощается, но **не приводит подобные**: производная `x·x` — `(+ X X)`, а не `(* 2 X)`. Приведение — отдельный слой S3 (`collect`/`diff-canonical`/`poly-*`). Полином — только `+ - * ^`, числа и одна переменная с неотрицательными целыми показателями; нулевой полином — `(0)`.

Унарная математика и n-арная арифметика на бинаре:

```lisp
(diff '(sin x) 'x)              ; → (COS X)
(diff '(cos x) 'x)              ; → (* -1 (SIN X))
(diff '(sqrt x) 'x)             ; → (/ 1 (* 2 (SQRT X)))
(diff '(atan x) 'x)             ; → (/ 1 (+ 1 (^ X 2)))
(diff '(- x) 'x)                ; → -1
(diff '(+ x 1 2) 'x)            ; → 1
(diff '(* 2 3 x) 'x)            ; → 6
(diff '(^ x 3) 'x)              ; → (* 3 (^ X 2))
(diff '(^ (+ x 1) 3) 'x)        ; → (* 3 (^ (+ X 1) 2))
```

Экспорты модуля: `variable?`, `free-of?`, `match`, `subst`, `rewrite`, `rewrite-all`, `simplify`, `diff`, `grad`, `unify`, `derive`, `matches`, `collect`, `diff-canonical`, `poly?`, `poly-coeffs`, `poly-eval`.

> 🐍 Это «20 строк Lisp вместо sympy» для базовых CAS-задач: сопоставление, переписывание, упрощение и производные работают на обычном `:syntax`, без собственного AST.

### Reverse-mode `(grad term var)`

`grad` решает другую задачу, чем `diff`: это градиент **скалярного лосса `(tsum term)`** по `var`, а не поэлементная производная. Он нужен там, где поэлементной производной нет, — `matmul`, `transpose` и свёртки. В отличие от `grad!` (гл. 10), который идёт по последнему запуску HLO-графа, `grad` работает с термом `:syntax` и возвращает терм.

```lisp
(import SYMBOLIC)
(grad '(tsum x) 'x)                       ; → (ONES-LIKE X)
(grad '(tmean x) 'x)                      ; → (/ (ONES-LIKE X) (TSUM (ONES-LIKE X)))
(grad '(tmax x) 'x)                       ; → (TMAX-MASK X)
(grad '(tsum (matmul x y)) 'x)            ; → (MATMUL (ONES-LIKE (MATMUL X Y)) (TRANSPOSE Y))
(grad '(tsum (transpose x)) 'x)           ; → (TRANSPOSE (ONES-LIKE (TRANSPOSE X)))
(grad '(tsum (reshape x (2 3))) 'x)       ; → (RESHAPE-LIKE (ONES-LIKE (RESHAPE X (2 3))) X)
(grad '(tsum (relu x)) 'x)                ; → (* (ONES-LIKE (RELU X)) (RELU-MASK X))
(grad '(tsum (softmax x)) 'x)             ; → (* (SOFTMAX X) (- (ONES-LIKE (SOFTMAX X)) (TSUM (* (ONES-LIKE (SOFTMAX X)) (SOFTMAX X)))))
```

Правила `grad-step` (g — пришедший градиент):

| Узел | Правило |
|---|---|
| `+` | сумма градиентов аргументов (`grad-add-list`) |
| `-` | унарный минус / разность градиентов |
| `*` | `∂a = g·b`, `∂b = g·a`; n-арное сводится к `b = (* …)` |
| `/` | `g/b` и `−g·a/(b·b)` |
| `^` | `g·n·a^(n−1)`, показатель должен быть числом |
| `tsum` | `g · ones-like(a)` |
| `tmean` | `(g · ones-like(a)) / tsum(ones-like(a))` |
| `tmax` | `g · tmax-mask(a)` |
| `matmul` | `matmul(g, transpose(b))` и `matmul(transpose(a), g)` |
| `relu` | `g · relu-mask(a)` |
| `softmax` (1-D) | `s · (g − tsum(g·s))`, где `s = softmax(a)` |
| `transpose` | `transpose(g)` |
| `reshape` | `reshape-like(g, a)` |
| `ones-like`/`tmax-mask`/`relu-mask` | `0` |
| унарные `sin…atan` | `g · unary-derivative-form(op, a)` |

`grad` — это `(simplify (grad-step term var 1.0))`. Формы сохраняются отдельными тензорными операциями (`ones-like`, `tmax-mask`, `relu-mask`, `reshape-like`), поэтому `simplify` не склеивает их в арифметику и не теряет форму. Производные унарных операций берутся из той же таблицы, что и у `diff`. Аналитические градиенты сверены с autograd по каждому оператору (`src/stdlib_neuro_test.zig`). Это **символьное подмножество**: правило `softmax` здесь по-прежнему 1-D, тогда как HLO-autograd (`grad!`) умеет `softmax`/`log-softmax` по последней оси любого ранга, `abs`, `conv2d`/pooling, `gather`/`scatter-add`, `t-slice` и `t-concat`. Новые операции в `grad-step`/`diff` не добавлены — для них используйте `grad!`.

## 14.8 Нейросимвольный слой: NS-примитивы и `ns-if`

**Принцип.** Дискретное условие — не булев предикат, а NS-функция: непрерывная level-функция, знак которой совпадает с истинностью условия. Компараторы `>`/`<` и формы `and`/`or` остаются булевыми и не перегружаются.

Три утверждения:

1. `sign(ns-and p q) = sign(p) ∧ sign(q)` (аналогично `ns-or`, `ns-not`) — знак комбинации — точная булева формула над знаками атомов;
2. значение NS-функции — обычные данные `:flonum`, его можно передать в ветку как признак или gate;
3. роутер `ns-if` использует **только знак**; значение дифференцируется там, где реально использовано.

| Форма | Роль | Значение |
|---|---|---|
| `(ns-grt a b)` | атом-полупространство | `a - b` |
| `(ns-geq a b)` | алиас `ns-grt` | `a - b` |
| `(ns-lss a b)` | атом (нормализуется) | `b - a` |
| `(ns-leq a b)` | алиас `ns-lss` | `b - a` |
| `(ns-eq a b d)` | сахар-полоса | `|a - b| < d` |
| `(ns-neq a b d)` | дополнение полосы | `|a - b| ≥ d` |
| `(ns-and p …)`, `(ns-or p …)` | R-конъюнкция/дизъюнкция, ≥2 арг. | левая свёртка `p+q∓√(p²+q²)` |
| `(ns-not p)` | R-отрицание | `-p` |

Все формы возвращают `:flonum` (скаляр или тензор по broadcast). Проверено на бинаре:

```lisp
(ns-grt 1.0 0.0)     ; → 1.0
(ns-lss 0.0 1.0)     ; → 1.0
(ns-and 1.0 2.0)     ; → 0.7639320225002102
(ns-or 1.0 -2.0)     ; → 1.2360679774997898
(ns-not 1.0)         ; → -1.0
(ns-eq 1.0 2.0 0.1)  ; → -1.2212670403551895
(ns-neq 1.0 2.0 0.1) ; → 1.2212670403551895
```

Важные детали: n-арные `ns-and`/`ns-or` — **левая свёртка бинарной** операции, а не `Σaᵢ ∓ √(Σaᵢ²)` (та формула знаково неверна при n ≥ 3). Сама бинарная R-комбинация считается устойчиво: `p + q ∓ hypot(p,q)` с масштабированием, поэтому большие `p`/`q` не переполняются, а знак, NaN и inf сохраняются; нули дают `p+q` с сохранением `-0`. `ns-lss(a,b)` нормализуется в `(b,a)` плюс отрицание, поэтому K — число **неупорядоченных пар**; `d` в `ns-eq`/`ns-neq` — положительная compile-time константа. NS-формы доступны и вне guard'ов — отдельного «soft-режима» у `ns-if` нет.

### Форма `ns-if`

```lisp
(ns-if
  (:payload x)        ; обязательна: тензор с ведущей batch-осью B
  (:eps eps-expr)     ; опционально, по умолчанию 0.0; вычисляется на каждый вызов
  ((ns-and (ns-grt score.0 1) (ns-grt score.1 2)) branch-a)
  ((ns-or  (ns-grt score.0 1) (ns-grt score.2 6)) branch-b)
  ((ns-not (ns-or (ns-grt score.0 1) (ns-grt score.1 2))) branch-c)
  (else branch-band))
```

- `(:payload e)` — обязательна; её ведущая ось задаёт строки, которые роутятся.
- `(:eps e)` — `:flonum`, `e ≥ 0`, вычисляется на каждый вызов; annealing не требует перекомпиляции.
- Клауза — `(guard body)`, ровно одно тело; guard-клауз **не меньше двух**.
- `body` — функция одного аргумента `(:func ((:tensor DT (B …))) (:tensor DT2 (B …)))`, применяется к компактифицированным строкам ветки.
- `(else body)` ровно одна: это **boundary-ветка**, а не default для непокрытых ячеек. Непокрытие — ошибка компиляции.
- Все ветки возвращают одинаковый тип; `:axis` в v1 нет; вложенный `ns-if` разрешён.

Рабочий пример (уменьшенная версия `bench/nsif_eager.qlsp`):

```lisp
(defvar x ((randn :f32 (4 8)) . (:tensor :f32 (4 8))))
(defvar a0 ((randn :f32 (4)) . (:tensor :f32 (4))))
(defvar a1 ((randn :f32 (4)) . (:tensor :f32 (4))))

(ns-if (:payload x) (:eps 0.02)
  ((ns-grt a0 0)
   (lambda ((v . (:tensor :f32 (4 8)))) (* v 2.0)))
  ((ns-and (ns-lss a0 0) (ns-grt a1 0))
   (lambda ((v . (:tensor :f32 (4 8)))) (* v 3.0)))
  ((ns-and (ns-lss a0 0) (ns-lss a1 0))
   (lambda ((v . (:tensor :f32 (4 8)))) (* v 5.0)))
  (else
   (lambda ((v . (:tensor :f32 (4 8)))) (* v 11.0))))
```

### Форма `ns-band`

`(ns-band ns-expr eps)` — отдельная форма, которая возвращает eager-маску `(:tensor :u8 (B))`: единица там, где строгий `|atom| < eps`, и ноль иначе. Атомы проверяются теми же правилами, что в `ns-if`; `eps` — числовое выражение, `eps ≥ 0`, вычисляется на каждый вызов. Источник — `router.bandMask`/`ql_ns_band`. В `defgraph`/`defuse` отдельного узла для `ns-band` в v1 нет: внутри графа используйте арифметику атомов и `t-gt`/`t-lt`. Градиента у маски нет.

```lisp
(defvar near ((ns-band (ns-grt a0 0) 0.1) . (:tensor :u8 (4))))
```

### Смешанный батч: построчное слияние

Работает роутер из `src/ns/router.zig`:

1. atomic columns `[B, K]` → знаки → маски guard'ов (дизъюнктные);
2. `band[i] = ∃j |atom_j[i]| < ε`; NaN-атом всегда отправляет строку в boundary, строгое сравнение: `|atom| == ε` — уже интерьер;
3. `branch[i] = band[i] ? BOUNDARY : Σ_g guard_g[i]·g`;
4. `countingSort` (stable) по branch → `counts`, `offsets`, `order[]`;
5. для каждой ветки с `count > 0`: `gatherRows` → вызов тела → `scatterRows` в результат;
6. tape: `branch`, `order`, `counts/offsets`, `band`, `atoms`.

Ветвь без строк не исполняется вовсе; порядок строк внутри бакета возрастающий, поэтому результат детерминирован. `gatherRows`/`scatterRows` работают со всеми пятью dtype (`f16/f32/f64/u8/i64`) побайтовым копированием строки. Результат ветки обязан быть по-строчным (`NsIfNotPerRow`). Reduction внутри ветки считается по компакту: ветка, получившая 3 строки из 10, усредняет 3 — документированный footgun.

### Покрытие ветвей: ROBDD-доказательство

Guards разворачиваются в булевы формулы над K атомами; строится ROBDD с детерминированным порядком переменных (первое появление атома). С инвариантом `I` из сахара полосы (`I ⊇ ¬(G1 ∧ G2)`) проверяются три условия:

```
I ∧ ¬covered    UNSAT   иначе NsIfUncovered
I ∧ Gi ∧ Gj     UNSAT   иначе NsIfOverlap   (i ≠ j)
I ∧ Gi          SAT     иначе NsIfEmptyBranch
```

Witness удовлетворяет `I`, то есть контрпример физически реализуем; печатаются знаки и выражения атомов. Менеджер ROBDD живёт в пределах одной проверки, GC нет. Проверка coverage — обязательная часть компиляции `ns-if`: «покрытие по умолчанию» не выводится. В v1 сняты прежние потолки: `plan.fillMasks` растит буфер под любое число атомов (не только ≤12), пустая ветка проверяется как `I ∧ Gi`, а `cell_table` строится лишь при ≤255 ветвях — при большем числе роутер обходит дерево. `router.signs` удалён, знаковый проход общий с eager-путём.

### Диагностика

| Код | Условие |
|---|---|
| `NsIfBoolGuard` | guard имеет тип `:bool` |
| `NsIfDerivedAtom` | операнд атома — NS-выражение |
| `NsIfBadSlab` | `d` в `ns-eq`/`ns-neq` не положительная константа |
| `NsIfUncovered` | ячейка не покрыта ни одной веткой (+ witness) |
| `NsIfOverlap` | ячейка покрыта ≥2 ветками (+ witness) |
| `NsIfEmptyBranch` | guard невыполним |
| `NsIfBranchCount` | меньше двух guard-ветвей |
| `NsIfShapeMismatch` | ветки расходятся по dtype/форме |
| `NsIfNotPerRow` | результат ветки не по-строчный |
| `NsIfPerRowCapture` | ветка захватывает per-row тензор из внешнего scope; скалярные захваты разрешены |
| `NsIfZeroEps` | *warning*: `ε = 0`, band пуст |

Все перечисленные коды — отказы компиляции с диагностикой, а не значения `error`. Структурированные `error`/`call-frame` (модуль `error` в prelude, гл. 15) относятся к рантайм-исключениям `throw`/`catch-error`: брошенное значение попадает в `cause`, а кадры трейса наполняются из source map Q4a.

### Annealing `ε` вместо конфигурационных ключей

Конфигурационных ключей `:psi`, `:verify-gate` и `:buffer_size` в текущем языке нет. Единственный настраиваемый параметр роутера — `(:eps e)` в самой форме `ns-if`: он вычисляется на каждый вызов, поэтому annealing ширины полосы делается обычным `setq` переменной, без перекомпиляции. Значения `e < 0` и NaN отвергаются. Ограничение strict band: `|atom| == eps` уже считается интерьером.

> 🐍 Это гибрид `nn.Module` с `torch.gather`-маршрутизацией и hard attention: дерево if-ов, где развилку выбирает знак непрерывной функции, а в исполненную ветку течёт обычный тензорный градиент. В PyTorch такого из коробки нет.

## 14.9 Два спуска, forward и backward

Одно NS-выражение компилируется двумя способами:

- **знаковый (булев)** — атом → компаратор `atom_j ≥ 0`, комбинация → `and/or/not`. Используется роутером и проверкой покрытия; `sqrt` и делений нет.
- **числовой (float)** — считается только там, где значение используется как данные gate'а или признака.

Диспетчеризация **никогда** не берёт знак float-значения R-комбинации: у смешанных по знаку комбинаций результат — катастрофическое сокращение (~1e-12 с плавающим знаком), и знак ненадёжен. `|combined|` не вычисляется никогда — band считается только по атомам.

Forward:

```
1. atoms = [atom_0 … atom_{K-1}]            ; [B,K]
2. band[i]   = ∃j |atom_j[i]| < ε
3. branch[i] = band[i] ? BOUNDARY : Σ_g guard_g[i]·g
4. counting sort по branch → counts, offsets, order[]
5. для каждой ветки с count > 0: gather → run subgraph → scatter в y
6. tape: branch[], order[], counts/offsets, band[], atoms
```

Стоимость — `O(B·K)` на роутер плюс `Σ branch_rows`; ветки без строк не исполняются. Память — `atoms [B,K]`, `branch [B]u8`, `order [B]u32`, counts/offsets — в per-run `TensorBufferPool` рядом с активациями (гл. 10).

Backward:

```
1. разложить g по веткам через order[]
2. backward только исполненных веток → dx, dparams
3. scatter dx обратно по строкам
4. d(atoms) — сумма вкладов отовсюду, где атомы использованы как данные
5. backward через подграф атомов (если они вычислены в графе) → d(logits)
```

Неисполненные ветки не компилируются в backward, не исполняются, `VJP = 0`. Маски на градиент исполненной ветки не умножаются: он в точности такой, как если бы ветка была всем графом. Градиента по **решению роутера** не существует (`∂H/∂atom = 0` вне поверхности). Если атом нигде не использован как значение, `d(atom) = 0`; диагностики `NsIfNoAtomGradient` в v1 больше нет — это штатный случай, а не предупреждение.

В `defgraph` (гл. 10.7) маршрутизация пересчитывается из сохранённых атомов и `eps` — отдельный tape не нужен; для каждой непустой ветки повторяется forward подграфа (активации для backward'а), запускается скомпилированный backward, и результат накапливается в градиенте payload'а. Атомы градиента через роутинг не получают.

> 🐍 Это `torch.gather` + `scatter_add_` с двумя проходами: знаковый решает, какой кусок графа исполнять, числовой даёт дифференцируемое значение; производной по самому решению нет.

## 14.10 Мост `neuro`: символьный терм → тензорный код

Модуль `neuro` — мост между символьным термом и кодом над тензорами. Его экспортируют три формы: `term`, `term->code` и `term-problem` (проверка терма без `throw`):

```lisp
(import NEURO)

(defun f ((x . (:tensor :f32 (4))))
  ((term '(+ (sin x) (* x x)) '(x)) . (:tensor :f32 (4))))
```

- `(term 'ТЕРМ '(vars))` — **макрос**, оба аргумента обязаны быть литералами; раскрывается в код над тензорами.
- `(term->code term vars)` — то же над значением `:syntax`:

```lisp
(term->code '(+ x 1) '(x))       ; → (+ X 1) — код как S-выражение
(term->code '(* (sin x) x) '(x)) ; → (* (SIN X) X)
```

Трансляция покрывает арифметику `+ - * /` (n-арные), `matmul`, унарные `sin cos tanh exp log sqrt relu atan`, свёртки `tsum tmean tmax`, `transpose`, `reshape`, `reshape-like`, `ones-like`, `tmax-mask`, `relu-mask`, `softmax`; скаляры арифметики идут broadcast. `^ n` разворачивается в произведение (`n = 0 → 1.0`, `n = 1 → основание`, `n < 0 → (/ 1.0 (* …))`); составное основание связывается один раз через `let`, а не дублируется n раз. Переменные обязаны быть перечислены в `vars`; глобал в графе — константа без градиента. Проверка отделена от генерации: внутренний `term-problem` возвращает первое сообщение, не бросая, а `term->code` бросает ровно один раз (после `throw` функции возвращают `nil`, и размазанная проверка давала бы вторичную диагностику). Экспорт: `term term->code term-problem`; макрос `(term FORM VARS)` требует оба аргумента-литерала (`quote`).

Новые операции и `^` над составным основанием (проверено на бинаре):

```lisp
(term->code '(^ (+ x 1) 3) '(x))   ; → (LET ((POW-0 (+ X 1))) (* POW-0 POW-0 POW-0))
(term->code '(transpose x) '(x))   ; → (TRANSPOSE X)
(term->code '(reshape x (2 3)) '(x))     ; → (RESHAPE X (2 3))
(term->code '(reshape-like a b) '(a b))  ; → (RESHAPE-LIKE A B)
(term->code '(ones-like x) '(x))   ; → (ONES-LIKE X)
(term->code '(tmax-mask x) '(x))   ; → (TMAX-MASK X)
(term->code '(relu-mask x) '(x))   ; → (RELU-MASK X)
(term->code '(softmax x) '(x))     ; → (SOFTMAX X)
```

Один терм годится во всех трёх ролях: eager-функция, обучаемый `defgraph` (`(term …)` с `param`-переменными становится графом, в том числе в ветке `ns-if`) и сверка с аналитическим `diff`. Отрывок из `examples/term.qlsp` (`xs`/`ys` — обучающие данные, `lr` — шаг):

```lisp
(defgraph loss ((c . (:tensor :f32 (1))) (x . (:tensor :f32 (4))) (y . (:tensor :f32 (4))))
  ((term '(tmean (* (- (* c (* x x)) y) (- (* c (* x x)) y))) '(c x y)) . :flonum))

(grad! (loss c xs ys))
(tset! c 0 (- (tref c 0) (* lr (tref (grad-of c) 0))))
```

| Что | Где | Результат |
|---|---|---|
| `term` | макрос `neuro.qlsp` | тензорный код на месте вызова |
| `term->code` | функция `neuro.qlsp` | `:syntax` с трансляцией |
| `symbolic/diff` | функция `symbolic.qlsp` | аналитическая производная терма |
| `symbolic/grad` | функция `symbolic.qlsp` | reverse-mode градиент `(tsum term)` (см. §14.7) |
| сверка | тесты `stdlib_neuro_test.zig` | `diff`/`grad` совпадают с autograd |

> 🐍 Это `sympy.lambdify(expr)` в варианте «выражение → типизированный код над torch-тензорами»: одна и та же формула служит и моделью, и эталоном для проверки градиента.

## 14.11 Когда символьный слой полезен

- **CAS-помощник:** `diff`/`diff-canonical`/`collect` строят формулу и сверяют её с autograd (`neuro`) без внешнего sympy.
- **Reverse-mode градиент:** `(grad term var)` даёт градиент скалярного лосса для `matmul`, свёрток, `softmax`, `relu`, `reshape` — там, где поэлементного `diff` нет.
- **Правила над данными:** `match`/`subst`/`rewrite-all`/`derive` работают с S-выражениями — факты, правила и запросы остаются обычными `:syntax`-данными.
- **Нейросимвольная маршрутизация:** `ns-if` ведёт запись в одну из ветвей по знаку level-функции; каждая ветвь — обычный тензорный подграф (гл. 10).
- **Метапрограммирование:** `:syntax` + `defmacro` + `read-from-string` + `eval` замыкают цикл «терм → текст → терм → код».

Символьный слой живёт на S-выражениях в глобальном/world-памяти (гомоиконность), нейронный компилируется через HLO (гл. 10). Qualisp сознательно разделяет эти миры: интроспекция термов не мешает нативной скорости тензорных ядер.

## 14.12 Известные ограничения

- `diff` не приводит подобные (`d(x·x)/dx = (+ X X)`); приведение — в `diff-canonical`/`collect`.
- `diff` не знает `matmul`/`transpose`/`reshape`/`softmax`/масок: отказ `diff: not elementwise; use grad`; `relu` даёт `diff: relu is not differentiable symbolically`. Для них есть `(grad term var)` (reverse-mode, §14.7).
- `grad` считает градиент скалярного лосса `(tsum term)`, а не поэлементную производную; `^` требует числового показателя (`grad: ^ needs a numeric exponent`).
- `derive`/`matches` возвращают `:syntax`, а не `(:list :syntax)`; `(:list :syntax)` неконструируем.
- Пустое окружение — `t`; `nil` означает «не совпало». `subst` принимает оба маркера.
- `ns-if` — hard-роутер: нет blending и soft-режима, нет per-cell boundary, нет обучаемого `ε`, нет counterfactual-ветвей на band, нет автовывода покрытия, нет `ns-eq` как примитивного атома (только сахар), нет `:axis`.
- Операнд атома не может быть NS-выражением (`NsIfDerivedAtom`); guard не может быть булевым (`NsIfBoolGuard`).
- Ветки обязаны быть по-строчными; reduction в позиции результата — `NsIfNotPerRow`. Захваченный per-row тензор полного батча несовместим с компактом: безопасны скалярные захваты.
- Отдельного примитива `ns-grad!` нет: backward идёт обычным `grad!` через HLO-граф (гл. 10).
- `ns-band` — вызываемая форма и возвращает eager-маску `(:tensor :u8 (B))`; узла графа/`defgraph` для неё в v1 нет, поэтому в трассируемом коде маску собирают арифметикой атомов и `t-gt`/`t-lt`.
- Нет reader-макросов, property lists, `amb-*`, `defrule`/`query`, `define-compiler-macro` — их место занимают описанные выше аналоги на `:syntax` и макросах.
